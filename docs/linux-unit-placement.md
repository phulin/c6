# Linux layered friendly-count query

`skip_turn::placement::Inputs` now supplies the actual layered Formation friendly-count dependency to the existing SkipTurn handler query. It uses the existing owned World, Map, Unit, Formation and native-order DefinitionTable. There is no aggregate friendly-count, same-type, war, cargo or rivalry boolean oracle. Complete gameplay state, action execution and turns remain unimplemented; full manager activation legality and mandatory action continuation remain open, and `Engine::apply` remains unsupported.

The source inspection also exposed a prior adapter error. Map UnitReference's eight bytes are ComponentID: signed owner short, signed component-type short, then generated unsigned ID. The existing `owner: i32` field preserves the first two halves together, but World previously treated it as a plain player. Its earlier synthetic type-zero tests missed this. New accessors preserve all raw bytes and expose the signed owner/type. World::unit now follows actual CManager::GetUnit: invalid owner `-1` or ID `UINT_MAX` returns absent; GetValidPlayer uses unsigned player range and the existing original player mapping; then Units.Find uses the low-sixteen-bit recycled slot without generation rejection. GetUnit ignores component type. Unknown mapping/collections remain errors; record presence does not replace validity authority. Layer membership separately compares **all** owner/type/full-ID bits, so wrong component type or stale generated ID cannot select a layer even when GetUnit would resolve its slot.

Layer discovery checks native coordinate validity, computes the signed wrapping `y*width+x` sparse-grid index, scans actual layer order and selects the first grid containing the actual UnitID (type 1). No layer or invalid location yields the actual empty candidate vector. This is linear sparse-grid indexing, without geometric coordinate wrapping or independent per-axis bounds checks. The genuine candidate vector retains order and duplicate references; Plot count bytes and Unit locations do not manufacture occupancy.

Formation counting resolves the actual owner's member IDs in order, skips missing or delayed-death members, and returns the unsigned **maximum**, not sum, of their counts. Each per-unit count obtains its owner, resolves each candidate through native GetUnit semantics, checks war first, and checks same-type only for the same owner. Actual IsCargo is a literal false body in this pinned Linux target; no default assumption or cross-platform rule is involved. Known trade-route/spy definitions are excluded. A null definition skips those definition filters but still undergoes rivalry. Candidate delayed death is not an extra filter: the native overload only filters delayed death on Formation members.

Same-type uses the actual Unit.Manager vtable methods, native domain/formation-class hashes and definition properties. Both wildcard-domain directions, the excluded domain constant, trade-route exclusion and null definitions are retained. The original unequal-formation-class combat/range branch ultimately rechecks the same pure class hashes; it cannot make unequal classes pass. Religious rivalry is now computed from typed religion strengths/types and actual team values: different owners, both strengths signed positive, different religions and not on the same team. Team rules resolve both actual valid Player records in native order before null checks or same-player success, then preserve `NO_TEAM=-1` branches. A valid mapping with an uncaptured Player record is an error, including same-player queries; a resolved same player does not require a Team value. A focused regression covers those distinctions and second-record resolution before Team reads.

War is queried from actual Game.DiplomaticRelations, **not** the newly decoded Player.Diplomacy record. Target validity and actual Core Player alive status precede relation lookup. For different living valid players, the complete ordered WarTypes vector and original relation player-count produce the native signed wrapping triangular index; any value except `-1` denotes war. Missing relation storage or invalid index rejects explicitly. A requested full vector must have the source-derived triangular length; no individual precomputed pair result substitutes for it.

Player now carries optional actual Configuration slot status/team and Core alive fields. Unknown fields remain `None`. The concrete handler adapter derives IsHuman from original slot status exactly equal to 3, including when external policies provide every decision. PLOT_UNIT_LIMIT is an explicit optional signed scalar from the actual configured native getter, not a permissive default. These facts and native definition properties still require actual export/import provenance; this change does not pretend the current wire import already supplies them.

Definition pointer binding no longer requires an oracle. Original Unit Read maps the serialized type hash through genuine HashToIndex. Its actual post-load vtable invokes InitializeDefinition on the remapped index, resolving through the real registry and storing both pointer and collection index, or null and `-1`. The query reproduces both lookups using the existing native registry contract, preserving missing definitions. This bounded post-load contract excludes arbitrary live pointer edits; a future exact type-changing action must maintain this binding. When a logical candidate Unit is supplied, all recycled aliases of the same resolved owner/full ID use that candidate's current fields during the Formation query. Other members remain borrowed from World; no duplicate world is built.
