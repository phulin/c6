# Linux completion dispatch internal kernel

The [Rust kernel](../crates/c6-core/src/turn_completion.rs) implements source-backed control flow for `PlayerTurnComplete::Execute` and `SetTurnComplete`. It is an **internal implementation milestone** toward the complete Linux gameplay state/action/turn objective. It does not implement an accepted EndTurn, a complete Game.Update, native pause/resume, or an external decision boundary. Public `Engine.apply` remains unchanged and Unsupported before mutation. No original code was executed or compared for this checkpoint. The initial implementation commit `d5b1f70` missed explicit singleton receiver capture/retention and is historical; this corrected contract includes the independent review findings.

The target remains supplied XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`; any future native fixture also requires Linux host SHA-256 `106d4986567cf60aad787dfac990d089e41775e04b5f40e073f59a3a8ffe74f4`, actual rules/configuration identity and complete affected-state/RNG observations. The [audit](../tools/linux/turn_completion_kernel_audit.py) reuses the independently verified original method fingerprints, branches and defined-ELF GOT resolution from [turn progression](linux-turn-progression.md), adds concrete production/accessor identities, and pins the implementation sources in [its report](../evidence/linux/turn-completion-kernel.json). Discovery attribution remains cru121, *Civ6-GameCore-reference*, revision `5af389445118bed2bdebf7a8a42b219c8fba5175`, CC BY 4.0; see [reference limitations](reference.md). Linux target bytes establish these contracts.

`execute_prefix` preserves the native order: unsigned encoded player >63 returns before resolution; after resolving the player it unconditionally captures the current Game pointer before IsHuman, including for nonhumans; a human pause test uses that retained Game receiver; human and paused logs then synchronously reports `0xa7b85261`; already complete logs only; otherwise the setter writes completion and produces a mandatory `RequiresGameUpdate`. There is no added alive, active, notification or CanEndTurn admission test. The external provider still owes actor entitlement and actual player availability. Raw reason hashes remain raw: NONE is `0xb6fa1284`, UserForced is `0x720b6468`, and TurnTimerExpired is `0x4601eac9`. Other reasons follow the original non-forced hook path. RequestAction typed-variant conversion, message admission/draining and post-message effects are outside this kernel.

`set_turn_complete` writes original global `Player::ms_abIsTurnComplete[requested.GetID()]`, identified at RVA `0x3c06210`. It does not invent a completion field in a serialized player. False returns true without hooks. True captures the current Player Manager once after the global write, then visits all 64 numeric slots and reads each slot's validity through that retained Manager, and for a valid slot rereads **the requested player's** alive state and calls **the requested player's** hook. The receiver is never replaced with the enumerated player. There is no simplification to one hook or a cached hook count. A hook may replace the globally available Manager, but later validity tests keep using the captured receiver. Game::GetInstance (`0x2660650`) and Player::Manager::GetInstance (`0x2b53260`) are pure pointer reads in this target; their lookup order and receiver identity remain explicit. Actual `EditTurnManager` (`0x299e450`) and owner `EditCities` (`0x20a8cb0`) are pointer reads, independently pinned; even NONE follows those accessors on each hook.

For forced/timer reasons the cities hook rereads its actual owner's human state. For a human it walks original recycled city-container cursor order, resolves each cursor city through ID/Find, checks typed `BuildQueue.entries`, edits only an empty queue, and assigns `production_overflow = 0`. Actual `Front` delegates to the same queue's size/front operations; `ClearOverflow` at `0x2850fc0` delegates to fixed-point integer assignment at `0x1fcdc10`, which stores integer zero shifted by eight (still zero) at queue `+0x1f4`. All other typed production fields remain unchanged. Container End is reread after every increment. Implementations must bind live handles/cursors and the actual queue, rather than sort IDs or reconstruct a queue from incomplete wire defaults. Existing complete typed `City` already owns this `BuildQueue`.

`City::EditBuildQueue` at `0x1fe4890` enters `FAutoVariable<BuildQueue,City>::edit`. Its exact archive/dirty effects are **not closed** here. The required `edit_build_queue` provider must account for them before returning a typed mutable queue; no default provider pretends a field write suffices. Logging, synchronous reporting/subscribers and live accessors likewise have explicit provider obligations. This is executable control flow plus a concrete production leaf, not proof of complete forced/timer gameplay effects. An internal provider error may follow the global completion write; callers must not expose that partial mutation as a successful or state-pure public action.

`RequiresGameUpdate::run` obtains a fresh current Game pointer before each required Update and calls a required complete `Game::Instance::Update` provider. That provider owes processor, pending diplomacy and cache profiling, and all nested rules/upkeep and external decisions. It may not return success after skipping work. After the first whole Update returns, the continuation rereads the same requested player's active flag. True produces exactly one further required whole Update; the second completion returns without an additional active test. A dispatch-body return is not public EndTurn acceptance. These values are Rust internal continuations and cannot be cloned or constructed externally; they are not tokens obtained by aborting an original native stack. The project supplies no full Game.Update provider.

Eleven branch/effect tests cover unsigned boundaries, paused-human precedence and subscriber effects, duplicate logging and nonhuman pause short circuit, repeated same-player hooks, callback-sensitive alive and city-end rereads, forced/timer empty/nonempty queues and unrelated production preservation, explicit archive failure after global mutation, false setter/dead/inactive behavior, mandatory one/two Update ordering, initial Game capture before IsHuman with retained pause receiver, retained Manager under hook replacement, and fresh Game lookup for each Update under callback replacement. Test providers are diagnostic fixtures, not original-code parity or production providers. Run `cargo test -p c6-core turn_completion` after the coordinated module export and `python3 tools/linux/turn_completion_kernel_audit.py --output target/linux/turn-completion-kernel.json` for static evidence.

Required continuations remain complete phase/player/city/unit/map upkeep, jobs, ordered message/reporting/diplomacy effects, all player decisions supplied externally (including NPC, off-turn and automation), and exact logical state/gameplay RNG. Native AI policies are not silently invoked and human flags are not changed. The full objective is not reduced to NONE or a lifecycle subset. Unknown save bytes remain unclassified and unmasked; the recorded raw 89,198-byte Save→Load failure remains unresolved.
