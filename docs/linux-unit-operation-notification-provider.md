# Concrete Linux notification predicates

`unit_operation_notification_provider::CapturedOwner` implements real notification predicates over production wire records and explicit omitted live fields. It binds actual target subtype addresspoints, retains object identity separately from ComponentID, and supplies the existing aftermath blocking reducer. It is a read-only predicate adapter: complete notification Update, SkipTurn, reporting delivery, gameplay state/RNG and turns remain unsupported.

The [audit](../tools/linux/unit_operation_notification_provider_audit.py) verifies all 39 target vtables against XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`, checks the production subtype table, inventories exact predicate/factory method dependencies, and replays the actual captured owner through the production codec/provider. [Its report](../evidence/linux/unit-operation-notification-provider.json) identifies every input and source. Original code was not executed; private observations were not modified. Attribution remains in [reference.md](reference.md).

The provider closes four concrete rules:

- The nine inherited `IsExpired` bindings use positive signed delta, actual current turn, and wrapping signed added-turn plus delta. Nonpositive delta returns false without needing a turn input. The other thirty subtype bindings reject explicitly; no base substitution is made.
- Base `IsValidForPhase` at slot `+0x30` returns true. This is the predicate called by the blocking reducer. Actual `IsNeeded` is a separate method at slot `+0x38`: its base binding returns true when flag `+0x19a` is false, otherwise calls actual subtype expiration and negates the result. Unknown overrides reject. The former lifecycle metadata mislabeled these slots; successor metadata and current APIs correct that historical error.
- All 39 `GetEndTurnBlocking` slots bind the base getter. Dismissed records return zero without invoking expiration. Other records invoke actual expiration, return zero when expired, and otherwise require the actual omitted signed enum `+0x130`. A missing field is never treated as zero; even a known zero enum does not skip expiration.
- The concrete provider drives the production unsigned-severity blocking reduction with separate phase validity and IsNeeded semantics. Captured ComponentIDs may duplicate without merging objects. Unsupported creation, callbacks, activation, dismissal and manager operations reject without mutating the captured owner.

Six tests cover base and PrideMoment subtype identity, actual phase-valid=true with IsNeeded=false, signed wrapping expiry and missing-turn short circuits, dismissed records avoiding unknown subtype expiry, missing `+0x130`, and rejection without mutation. Separate aftermath tests prove the opposite predicate values and original reduction call order.

The immutable passive capture contains twelve first-Find objects. Their five observed virtual targets uniquely identify eleven base Instances and one PrideMomentRecorded object against the exact 39-table inventory. This is a documented inference from the observed complete five-target profiles and original observer's table validation, not a newly captured addresspoint or a hash-to-subtype guess. All twelve actual live blocking values are zero. Added-turn/delta/flag `+0x19a` come from the identified Save baseline; those unread fields were not captured anew at first Find. Each delta is positive, so exact expiration additionally needs the current turn at its query boundary.

The audit preserves two distinct results. Without a live-turn input, all expiration queries reject, the three already-dismissed blocking queries return zero, and overall blocking reduction rejects. A separate conditional replay uses `CorePrefix.current_turn`, decoded by the production source-ordered codec from the actual before stream. Its saved value is 592; no fixed offset or fixture constant supplies it. With that saved turn, all twelve expirations are false and the blocking reduction is zero. The adapter itself performs no turn updates. Matching saved turns before/after the broader action does not prove absence of a transient turn change in unresolved synchronous callbacks; the conditional result is not an observed native predicate-return comparison.

Supplied base data identifies six auto-notify candidates: ChooseTech, CommandUnits, CityRangeAttack, ConsiderGovernmentChange, FillCivicSlot and ChooseCivic. Their exact exported Create/Register/expiration/phase/needed dependency identities are inventoried in the report. The XML is discovery evidence; it does not establish the active definition array, DLC/mod overlay, native order or live creator registry. Actual Manager.Create checks initialization/uninitializing, looks up the creator, and uses base Instance.Create when no nonnull creator is present **or the registered creator returns null**. Pool reuse, actual Initialize, subtype rules, true IsNeeded, duplication, Send/Add and synchronous effects remain required. A null registered result must not be mistaken for absence of all creation work.

The smallest remaining evidence packet is the actual ordered active definition/creator inventory and same-invocation predicate inputs/results: actual subtype slots, turn/added/delta/flag `+0x19a`, live blocking `+0x130`, phase-valid/expiry/blocking returns, and callback state sufficient to prove the current-turn value at each query. Existing saved current turn should be reused when intervening updates are proven; no new capture is needed solely to rediscover that saved field. This packet was passed to `reference_reuse` for a later profile; the current frozen handler run was not expanded. Factory/subtype effects and complete RNG still need original-code fixture comparison before an action can be accepted. The 89,198-byte raw Save→Load difference remains unmasked and unresolved for exact state.
