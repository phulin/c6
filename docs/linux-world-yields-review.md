# Independent Linux world and prerequisite yield review

The owned world lookup boundary and the two improvement prerequisite yield helpers are accepted as static, source-backed contracts over supplied typed inputs. No correctness defect requiring a source change was found. This review does not provide native differential acceptance or complete gameplay state, action execution or turns.

Reviewed commits are `fc1e2f7`, `4f245e8`, `d8462d1`, `6a7d4b2` and `e31a688`, at source HEAD `d8462d11b94eaab212f2eafa83ca095873d8f273`. Exact file SHA-256 and Git blob identities, including the uncommitted shared `lib.rs` integration context used for tests, are recorded in [the review evidence](../evidence/linux/world-yields-review.json). The owned implementation files had no tracked differences during review. This review owns no shared exports.

The supplied Linux XP2 module was independently SHA-gated to `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. Original symbols and instruction bodies confirm:

- Unit and Formation owner collections delegate to recycled Find (`0x2baa650` and `0x2b05830`). `UINT_MAX` is absent; other IDs use their low sixteen bits, select the block and slot, and read the stored pointer without generation equality. Explicit slots, requested/resolved IDs and complete empty collections in `world.rs` preserve this behavior. Native owner identity is retained; later changed record owners and replacement Player owners are rejected rather than silently rebinding indices.
- Manager validity (`0x2004fc0`, `0x2005000`) first checks unsigned player ID below 65, then compares the actual mapping entry at manager offset `0x1a08` with -1. Imported Player presence cannot establish validity. The world adapter correctly distinguishes unavailable mapping, invalid mapped entry, and a valid mapped player whose typed acquired mask is unavailable.
- Improvement Find (`0x1ffbea0`) takes a direct index below count, otherwise uses unsigned hash lookup. Its actual push-back (`0x22dd8b0`), lower-bound insertion and comparison (`0x22ddd90`) put new equal hashes before old entries. Find selects the first equal entry, so the last insertion wins. `OrderedImprovementDefinitions` preserves supplied order and checks property/hash alignment; the supplied `DefinitionLookup` remains responsible for implementing this semantic contract.
- The two helper bodies (`0x2a3fd30`, `0x2a3fe40`) follow reference order, skip null or nonmatching references, and use the matching resolved prerequisite collection index. HasTech/HasCivic reject -1 and unsigned indices outside the acquired vector before the global query. Global node presence/active state precedes the acquired bit read, including for an unacquired bit. The civic normalization is identity only under the documented actual resolved-definition index bound.
- Native FixedPointT<8> integer assignment (`0x1fcdc10`) shifts a 32-bit integer by eight; addition (`0x1fe5330`) adds 32 bits. Wrapping shift/add in `yields.rs` preserves low-32-bit behavior for negative and overflowing bonuses.

Constructor validation is structural. It checks dimensions, duplicate owners/layers/cells, slot bounds/duplicates and owner consistency; it does not prove the supplied records are a complete capture. Importers must gate module, actual Linux rules/configuration and provenance. `NativeDefinitionIndex::new` checks a caller-supplied actual count; supplying an invented count would violate its contract. Complete acquired vectors and observed global availability are required. Unknown input remains unavailable, while a known absent/inactive node can be false. Raw record mutation remains infrastructure: it does not perform coupled occupancy, ownership or formation action effects.

Validation passed: seven owned world tests, seven numerical yield tests and six existing movement-world tests selected by the broad `world::tests` filter; `cargo clippy -p c6-core --all-targets -- -D warnings`; and a fresh 37-method target-byte audit using `tools/linux/yield_prerequisites_audit.py`. The audit and this review execute no original game code. Rust synthetic boundary cases and byte fingerprints do not substitute for an initialized native oracle comparing outputs and all affected state.

Remaining acceptance boundaries are the actual native ordered registry/reference export, complete acquired/global provider import, configuration identity and native differential fixtures. Complete world reconstruction, exact gameplay RNG/state, actions and turns remain outstanding. External policy decision boundaries are unchanged. All unknown save bytes remain unclassified and unmasked, including the recorded raw **89,198-byte Save→Load failure**.
