# Linux improvement prerequisite bonus helpers

`c6_core::yields` implements the complete numerical bodies of `Improvement.Yields.GetPlayerBonusTechYieldFrom` (`0x2a3fd30`, 267 bytes) and its civic analogue (`0x2a3fe40`, 267 bytes), over explicitly supplied original typed inputs. These are source-backed implementations with target-byte checks and Rust boundary fixtures. Initialized native differential acceptance remains outstanding. They do not implement outer `Rules.GetYield`, improvement adjacency, actions or turns; complete gameplay state/action/turn support remains unimplemented.

The [read-only audit](../tools/linux/yield_prerequisites_audit.py) and [result](../evidence/linux/yield-prerequisites.json) pin the supplied Linux XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`, 37 method bodies, critical instructions and caller branches. This adds no native execution. Original disassembly stays in the private paths recorded by the report. It independently checks the retained [yield-effects](linux-reporting-yield-effects.md) and [query-closure](linux-reporting-yield-query-closure.md) evidence against original bytes.

Both native functions return a four-byte signed `FixedPointT<8>` through a hidden return pointer in RDI. Receiver RSI, player EDX, improvement index-or-hash ECX and requested yield R8D follow it. The template parameter is eight fractional bits, not eight-bit storage. `FixedPointT(int)` tails to assignment at `0x1fcdc10`, which shifts a 32-bit integer left eight bits and stores its low 32 bits. Addition at `0x1fe5330` reads and adds 32 bits. Rust therefore converts every accepted row with a wrapping shift and accumulates with wrapping addition, in original reference order, without floating point or a final integer conversion.

The native sequence is:

1. Initialize the result to zero and call original `Player.Manager.IsValid`. An invalid native player returns zero. Political ownership or presence in a partial imported player vector cannot replace this check.
2. Resolve the original improvement registry using `Find(unsigned int)`. Values below native definition count are direct indices; other values use the hash lookup. A genuine miss returns zero. `OrderedImprovementDefinitions::new` validates a supplied `movement_world::DefinitionLookup` against the complete, native-ordered property array once. The query then uses its indexed lookup; duplicate hashes retain that registry's original last-inserted resolution. The audit pins the actual improvement push_back/lower-bound insertion and unsigned comparison bodies, plus Find/lower-bound selection: equal hashes insert before older entries and first-equal lookup selects the latest insertion. The trait is a supplied native lookup contract; validating alignment does not certify arbitrary implementations of that trait. Missing definitions, inconsistent array lengths/hashes, or an inconsistent lookup result are errors.
3. Iterate original bonus references in order. Null row references, null yield references, nonmatching yield collection indices and null prerequisites contribute nothing. An uncaptured reference array is an error, distinct from a known empty array. A row containing both prerequisites is independently eligible in both helpers, under the corresponding check.
4. `Player.Techs.HasTech` (`0x2b8ac60`) and `Player.Culture.HasCivic` (`0x2a73e70`) reject `-1`, then compare the requested index against the acquired vector size using unsigned arithmetic. Out-of-range indices return false before consulting the global provider. For an in-range index, global node presence and `IsActive` are checked **before** the player's acquired bit, including when that acquired bit is false. Both conditions must hold before adding the integer bonus.

Civic `HasCivic` additionally invokes `Types.GetIndex` (`0x2951db0`). Its underlying `GetTypeIndexT` (`0x2955a70`) returns an input below the actual civic definition count unchanged; other inputs can involve a hash lookup. These bonus helpers pass the resolved prerequisite definition's `GetCollectionIndex`, not an arbitrary CivicTypes/hash input. `NativeDefinitionIndex::new(index, actual_definition_count)` restricts the public reference input to that original resolved-index domain. It must be assembled from actual native definition registries, never SQL rowids, an invented count or sorted SQL rows. This module does not offer a generic hash-taking implementation of `HasCivic`.

`PrerequisiteState` supplies native player validity, complete acquired bool vectors and actual global availability. Global availability means a known original node's active flag, with known node absence returning false. It does not mean research eligibility or `CanStart`. Uncaptured masks or providers return `MissingInput`, even if a guessed false value would leave the result numerically unchanged. The implementation only requests data reached by the native short circuit. The typed world's adapter owns assembling those inputs; this module neither reads opaque saves nor infers masks from completed prerequisite booleans.

The seven focused tests cover both helpers' negative and wrapping arithmetic, ordered provider queries, both availability conditions, missing-input rejection even for an unacquired in-range prerequisite, native index short circuits, nullable/mismatched references, invalid-player and missing-definition zeros, direct-index and duplicate-hash resolution, and registry shape validation. Their synthetic inputs test the source contract; they are not initialized Civ VI native fixtures or gameplay parity. A fresh captured native-order improvement/reference registry, global/player masks, configuration identity and differential oracle remain required for runtime acceptance.

```sh
cargo test -p c6-core yields::
cargo clippy -p c6-core --all-targets -- -D warnings
python3 tools/linux/yield_prerequisites_audit.py --output target/linux/yield-prerequisites.json
```

No `Engine.apply`, SkipTurn or turn admission is added. Other plot yields and all affected gameplay state/RNG still require their exact implementations and original-code comparisons. Unknown save bytes remain unclassified and unmasked, including the separate raw 89,198-byte Save-to-Load failure.
