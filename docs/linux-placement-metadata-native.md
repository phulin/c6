# Separate Linux placement metadata preparation

`native/linux/placement_metadata.[ch]` prepares a separate read-only count oracle for the pinned Linux XP2 module. No original game code has executed for this profile. Complete gameplay state, actions and turns remain unimplemented. The existing all-plot domain fixture and its accepted artifacts remain unchanged.

The exporter uses two exclusive-create NDJSON outputs. `C6_PLACEMENT_METADATA_OUTPUT` contains genuine inputs: the complete 65-entry manager mapping and actual player-table presence, requested validity/resolution/owner, actual Configuration slot status/team and Core alive flag; native ordered Unit definitions and their actual collection indices, type hashes, Find(hash)/Find(ordinal) results and placement properties; complete Game.DiplomaticRelations WarTypes values and actual player count; and signed configured PLOT_UNIT_LIMIT. It obtains GlobalParameters from its genuine configured getter. Definitions come from the real collection, never SQL row ordinals; an in-range null At is an explicit unsupported failure.

The actual manager mapping and player pointer-table extents must both be 65 before slot reads. GetValidPlayer's result must equal the queried table pointer when valid and null otherwise; mapping values never redirect pointer lookup. A resolved player's actual owner must match its query. `stored_nonnull` remains separate from validity and resolution. Valid slots with null stored pointers remain explicit rows. Each resolved player's Unit and Formation collection is traversed in native order, checked against its original active count, with unique low16 slots, exact owner and Find(full generated ID) pointer equality. No owner limit, sampled formation cap or silent truncation is used. Formations are enumerated independently, including unitless and unplaced formations. The exported membership is a complete logical lookup inventory; it does not invent allocator capacity, free links, generation state or serialization metadata. A matching original Core stream and owner trace must supply the actual Map/Unit/Formation wire records and recycled metadata required by a consumer. A consumer that only implements lookup must explicitly avoid claiming allocator state.

`C6_PLACEMENT_METADATA_EXPECTED_OUTPUT` contains original answers only. Each actual Unit and each actual Formation has its own anchor and seven ordered query positions: current (`direction=-1`) then directions zero through five from original Map.GetAdjacentPlot. Invalid anchors, absent current plots and null neighbors retain explicit rows. The original member's location-layer getter is used, including layer `-1`; no layer is manufactured from a coordinate or occupancy counter. Actual UnitContainer.GetUnits(x,y,layer) returns a borrowed cell vector or the container-owned empty vector. The exporter passes that exact reference to the original free Unit/Formation count overload with bool false. There is no vector construction, synthetic C++ layout, hidden return object, copied occupancy or destructor. The retained original Map owns that vector until the synchronous call ends.

Unit runtime definition bindings and formation pointers are also expected invariants, separate from input definitions and wire state. These observations cannot substitute for typed hash-to-index/post-load binding reconstruction. No original SkipTurn handler result is provided: the actual registered handler receiver lifecycle remains unproven. Count parity is a bounded prerequisite for that handler and full manager admission, not accepted action or turn parity.

The original const Unit Begin/End return a one-word iterator. Formation Begin/End omit a const qualifier but their verified bodies only add the container offset and construct a local one-word iterator from the live-list head or null. Dereference only reads a borrowed member; increment changes only the exporter-owned iterator. The actual Formation RecycledIDContainer lives at wrapper `+8`; its original Size reads active entries. WarTypes lives at Game.DiplomaticRelations `+0x1a0`; its original vector size and const subscript provide the complete ordered eight-byte entries, of which the first signed i32 is WarTypes. The actual relation player count is the original signed i32 at `+0xc0`. A length unequal to `n*(n-1)/2` rejects instead of truncating or substituting pair answers.

The runner owns a separate `c6_linux_placement_metadata_admission_begin/quiescent/admission_end` scope, module reference and loaded Context/Game lifetime. It must gate the pinned module SHA-256, Linux host, dependencies, complete rules/DLC/mod/configuration/input and all source identities. Unknown/active work must terminate the isolated process immediately before further state reads, saves, facade release or teardown. The exporter repeats the quiescence gate around saves and every original count. Paths `C6_PLACEMENT_METADATA_SNAPSHOT_BEFORE`, `_CONTROL`, `_AFTER`, `_REPEAT` must be distinct private exclusive-create saves, also distinct from both outputs. The runner must separately observe cleanup. A nonzero return, partial file, missing successful summary or missing completeness predicate makes the capture unusable.

Four internal raw saves and two known RNG streams are bounded purity controls. They do not cover all logical state, gameplay RNG or transitively mutable receiver state. Source names and const qualifiers do not prove runtime purity. All four raw saves, outer controls, expected outputs and policy observations must be retained and compared after any future reviewed native capture. Unknown Save→Load differences remain unclassified and unmasked, including the historical **89,198-byte inequality**.

Reproduce preparation without loading or executing original code:

```sh
python3 tools/linux/placement_metadata_audit.py --output target/linux/placement-metadata-preparation.json
cc -std=gnu11 -Wall -Wextra -Werror -fanalyzer -fsyntax-only native/linux/placement_metadata.c
```
