# Passive current-handler metadata helper preparation

The standalone helper in [current_handler_interruption.c](../native/linux/current_handler_interruption.c) prepares a later, separate metadata capture of the runtime bindings missing from source report `1dae236`. It has **not been integrated into a runner or executed against original game code**. The [preparation report](../evidence/linux/current-handler-interruption-metadata-preparation.json) checks pinned original methods/layouts, strict C compilation/analyzer results and synthetic refusal cases. It does not admit any live bindings or native Manager predicate result.

The helper calls no original getter, handler method, predicate, script, action or turn function. Its only caller service is a mandatory, separately admitted quiescence callback. It reads the genuine current Game global, its component container, Manager, mapped Player slots and active Unit containers through exact bounded target layouts. All memory copies use safe kernel self reads; inaccessible or overflowing extents reject. This avoids speculative calls through interposed getters while capturing actual live Manager and handler method slots.

The exact Linux GameCore SHA-256 is `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`; host SHA-256 is `106d4986567cf60aad787dfac990d089e41775e04b5f40e073f59a3a8ffe74f4`. The helper hashes the actual module file and `/proc/self/exe` before observing original objects and rehashes the retained module descriptor before completion. It compares loaded ELF program headers with that file, bounds code/table reads to the module's PT_LOAD ranges, verifies actual `/proc/self/maps` read/execute permissions plus file device/inode/offset, requires vtable slot mappings to belong to the same hashed file, checks actual target module ownership, and compares complete live method bytes with the hashed original file. A symlink-only module pathname, unreadable mapping, altered slot/code, foreign target or unsupported handler rejects; there is no original-image prediction fallback. Host ELF addresses are never base-added: the helper performs no host-address access.

## Actual runtime facts

The capture records the real Game component index and 24-byte component vector, actual 104-byte Manager object, live Manager vptr, and method pointers at `+0x88`, `+0x98`, `+0xa0`, `+0xd8`, with all 82/40/86/116 live code bytes and module ownership. It bounds the actual ordered handler vector by its native begin/end/capacity. Every slot is explicit, including actual nulls. Each nonnull handler contributes its complete 16-byte base header, native ID/hash/vptr, actual `+0x20` pointer, owning module and complete three-byte live leaf. Supported leaves are BaseHandler and MakeTradeRoute; neither is invoked. A handler's native hash field is not presented as an independently observed reverse-map answer.

All 65 Player query slots retain stored pointer, mapping value and resolved pointer using the original `IsValid`/`GetValidPlayer` field semantics. Each resolved Player must have the matching native ID. The Units parent pointer must lead back to that retained Player. The helper traverses the actual allocated list, including unplaced Units, with its original count, head/tail and previous/next links. It checks each Unit's full stored ID, owner, concrete vptr, unique low16 slot, exact 8-entry block membership and actual entry/object pointer. The original `Find` uses low16 block lookup; this helper additionally preserves the full native ID and refuses the sentinel. Count mismatch, cycle, stale parent, bad block or invalid native identity rejects. It does not synthesize an actor roster from wire data.

Each original Unit contributes its actual 200-byte queue object, native block pointer, logical block capacity/count, inline-storage relation and **all capacity bytes**, including unknown/padding/stale bytes without masking. The admitted storage shapes are original constructor null/zero, the exact `(queue_address+15)&~15` inline pointer with capacity 4, or a nonoverlapping 16-byte-aligned external block with capacity above 4. Arbitrary in-object offsets, mismatched capacities and unsupported shapes reject. Node size is 40 bytes; the helper does not dereference shared parameter pointers or invoke serializers. The queue header is reread for equality around the block copy, and an inline copy must equal the bytes in its owning queue object. Allocation extent here means the original queue block header's logical capacity; allocator implementation metadata and independent heap-allocation ownership remain outside this capture. The caller must retain the actual Unit/container/queue allocation and exclude mutation or destruction throughout the call.

For a nonempty queue, the first node's actual first 32 bits are recorded directly as `native_front_bits`. These are native operation bits, not a saved operation hash. This first helper admits only index-form current identities (`bits < 0x800`) within the actual handler vector; other native representations explicitly reject. An in-bounds actually null slot is recorded as null in `observed_numeric_slot_pointer`. This is source-derived numeric vector selection, not an observed original GetHandler return; each nonempty row states that distinction explicitly. The actual Manager vector and selected live slot are reread for each nonempty queue and must match the initially captured slot ownership. A nonnull current handler must still match the initially captured base header and actual target. No missing evidence or out-of-range numeric key becomes a null/default success case. Matching the Manager method bodies does not validate live transitive PLT/GOT destinations such as HashID construction/IsIndex, vector access, Unit queue access and rbtree helpers. Their original native getter equivalence remains an open pre-answer/native acceptance obligation; the helper neither calls nor observes their returns. Same-ID bypass and predicate return values are not calculated by this metadata helper.

## Caller and future profile obligations

`c6_linux_current_handler_interruption_capture` accepts the admission structure from [the header](../native/linux/current_handler_interruption.h): retained original module/Context/Game, a frozen full-profile SHA, an exclusive output path and a strict three-argument idle callback. The callback must authenticate the exact Context/Game/session association, main-thread lock, initialized native state, idle work/queues and all owning lifetimes. A missing callback refuses entry. A nonzero callback exits immediately with 240, without permitting post-state capture or cleanup under unknown work. The helper cannot prove those ownership/locking facts from a public pointer or profile digest; the caller's complete source and actual setup must be reviewed before any original execution.

Proposed integration is a **new** `current_handler_interruption_metadata_observer` profile after the existing Military preparation work. Existing Manager metadata, Military, registry and source-prediction profiles must remain unchanged. The sole runner owner would add a separately audited wrapper, retain the initialized original session and Game facade correctly, adapt an approved idle guard without an incompatible function-pointer cast, and load only this helper's frozen source/build. No runner changes or original capture are part of this checkpoint.

Before that integration can be admitted, freeze the wrapper/profile/compiled-helper sources, exact module/host/dependencies, rules database and rules-input identity, DLC/mods, configuration, input Save/Core and all output destinations. Output belongs under private `../c6-ghidra`; do not publish native memory/code bytes. Obtain two complete same-context fact passes, four internal plus two outer full unmasked Saves, known Game/Map RNG endpoint controls and terminal controller/framework/client cleanup. Compare the full facts and all six Saves byte for byte; unknown bytes remain unclassified. Equal Saves do not establish complete transient-state purity or complete RNG coverage.

A later pre-answer checker must bind these actual native fronts to same-context original serializer ownership/wire evidence and independently observed reverse-map answers, preserving every Unit and nullable slot. The helper supplies no reverse-map traversal or lookup answers and cannot replace that missing evidence with definition order or handler hash fields. Any future predicate comparison requires its own admitted boundary fixtures and affected-state checks. Existing saved queue corpus counts and image-predicted leaf targets remain source-only evidence.

Reproduce preparation without executing original code:

```sh
python3 tools/linux/current_handler_interruption_metadata_audit.py \
  --output target/linux/current-handler-interruption-metadata-preparation.json
```

The audit hashes original files as data, inspects complete method bytes/symbols/DWARF, compiles the helper with strict warnings and GCC analyzer, and executes only local synthetic memory fixtures under UBSan. Tests cover hash standard/block/stream boundaries and wrong identities; unreadable/overflowing spans; inline/empty/native-ID queue boundaries; a complete synthetic 65-slot roster with parent/block/list rejection; live-code mismatch and missing executable permission; null entry admission refusal; and fatal unknown quiescence. Synthetic pointers/code are never original receivers or admitted runtime observations.

Complete live gameplay state, all RNG, full Manager legality, scripts, action execution, turns and every-player external decision boundaries remain unimplemented. The historical **89,198-byte** raw Save→Load failure remains unclassified and unmasked.
