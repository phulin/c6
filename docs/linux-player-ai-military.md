# Linux AI.Military saved wire

This bounded codec targets Linux XP2 module SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. It preserves typed saved fields and raw bool bytes, signed fixed-point storage, hashes, container order and recycled-ID metadata. Native Player lookups, initialization, signals, archives, definition resolution, Operation execution and policy are separate. Full Player/world import, actions and turns remain unsupported; the 89,198-byte raw Save→Load difference remains unmasked.

The current Military writer (`0x21453f0`) emits version 14, signed Player identity, three regional strengths, war-footing bool, cities-taken turn vector, four explorer counts, construction bool, desired Technology hash, preparation/rival byte vectors, conditional operation-type hash arrays, recycled Operations, 64-entry regional strength WriteArray, UnitPromotionClass and PseudoYield hash arrays, MilitaryDefense vector and two signed Q8 levy vectors. MilitaryDefense (`0x21452f0`) is version 1, Player identity, defense enum, subject ID, desired/current unit counts and counted Assignments. Assignment (`0x2145270`) is version 1, assigned Unit ID and signed x/y PlotCoord.

The three operation-type arrays have **no saved presence discriminator**. Native Read (`0x2145620`) initializes lists before testing the allowed-type vector size. `InitializeLists` (`0x2145be0`, 1,919 bytes) calls `GlobalAi::HasAiPersonality` at `0x2145c02`; false skips list initialization. A known leader invokes the operations handler's leader/civilization/handicap query at `0x2145c96`. The no-leader branch sizes its list from the AiOperationType definition count at `0x2145dc5`–`0x2145de1`. Thus global definition presence alone cannot establish this per-player branch. Decoding requires explicit `Context { operation_type_arrays_present }`; context-free entry points return `MissingContext`. Encoding preserves the selected branch as `Option<OperationTypes>`. The existing two original Save corpora structurally contain all three arrays for every Military record; that finding does not provide a general context inference rule.

Recycled Operations retain version `0x10001`, block size 16, capacity, counted indexed entries, current ID bits, free count, first/last free indices and the ordered free chain. No allocation uses native advertised capacity: actual entry counts consume aggregate byte/item budgets and allocations are fallible. All output bytes/items are measured before output allocation.

Discovery names are attributed to [cru121's pinned reference](reference.md), revision `5af389445118bed2bdebf7a8a42b219c8fba5175`; supplied ELF bytes, symbols and DWARF are authoritative. Audit metadata and validation results are recorded in `evidence/linux/player-ai-military.json` by `tools/linux/player_ai_military_audit.py`; no original game code runs.

Context is an attributed low-level wire input, not reconstructed initialization. Complete Core import still needs faithful HasAiPersonality/list initialization from real Player, configuration and rules inputs, or an attributed complete initialization snapshot. `Some(OperationTypes)` with empty saved arrays is accepted as a structural transport carrier; no native-save validity is asserted. The live vector guard and saved definition-array count are distinct values, and validating their relationship requires that initialization context.

The offline typed parser currently checks all 86 original Military records, including nested Operation/OperationDef/OperationTeam extents against their actual trace hooks. Research has no owner hook in these particular traces; version 4 at the exact consumed Military end is a bounded next-schema dependency, not a fabricated Research hook. Its complete typed parser is separate.
