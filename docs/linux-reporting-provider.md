# Conditional Linux reporting-provider boundary

The corrected conditional SkipTurn profile records eleven balanced original reporting calls, but those entry/return observations do not establish callback effects. The first Rust Unit/Formation kernel must reject an unsupported reporting environment before mutation. Complete gameplay state, action execution and turns remain unimplemented; this audit does not change that scope.

The [static contract](../evidence/linux/reporting-provider-static.json) pins the supplied Linux XP2 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa` and host `106d4986567cf60aad787dfac990d089e41775e04b5f40e073f59a3a8ffe74f4`, method fingerprints and a four-hardware-breakpoint passive replay plan. Its parent is corrected configuration `b6ca58d53073abc2afa9176a4ceba350fafe3f91ba12dbf84fd08e25a3be9a5b`. Static checks execute no game code and do not count as an observed callback inventory.

The map sender `0x2d4a4b0` first reads enabled and suspended predicates. Its cache dispatcher synchronously calls each matching nonempty delegate; the original EngineUtility provider then updates dirty-component bookkeeping and dispatches a registered translator. Relevant host Publish methods query an optional synchronous pre-publish subscriber before creating a queued host event. A zero Send return or unchanged serialized bytes cannot establish that any of these surfaces are pure output. The [aftermath audit](linux-skip-turn-state-success.md#reporting-dispatch-boundary) retains the direct-call evidence.

The capture plan uses these checkpoints, with host addresses and game module RVAs retained separately:

| Checkpoint | Observation |
|---|---|
| Game `0x2d4a4c6` | Actual suspended result in AL, event/map, enabled byte `0x3c00649`, cache-update byte `0x3bffce8` |
| Game `0x2724777` | Resolved cache callback RAX and adjusted receiver RDI immediately before its tail jump; event/data/map and caller |
| Host `0x3214cb0` | Actual translator pointer after lookup/load, including null; event/data/map |
| Host `0x2fd7db0` | Actual DispatchData pre-publish pointer at `+0x10`, caller and raw delegate words |

Reporting suspension is not a guessed global bool: original IsSuspended tail-calls Globals::IsUnserializing, which combines WorldBuilder unserializing with the actual context's loading state. Capturing its return avoids fabricating those objects or calling original methods from the debugger. Reaching that checkpoint proves the earlier enabled predicate returned true; disabled sends miss it. The translator checkpoint only covers found registrations. A missing checkpoint must remain a coverage limitation until the full selected call sequence and relevant branches are reconciled.

The cache delegate checkpoint captures the target after original member-pointer adjustment and virtual resolution. For pre-publish registration inspection, the inspected original Linux member-delegate helpers read closure-this at `+0`, member pointer at `+8` and signed this-adjustment at `+16`; a low-bit-set member pointer resolves through the adjusted receiver's virtual table. Raw words, process addresses, mapped module identities and derived RVAs must all be retained. A nonnull registered pointer alone does not prove actual invocation or classify the target's effects. Any exercised target needs its own exact-target instruction/call evidence; namespace names do not establish cache-only or planning-only ownership.

The native lease owner runs the single same-source replay, using the archived preload and initialization profile with fresh output/userdata paths. No inferior calls, field writes, software game-code breakpoints or permanent hooks are part of this plan. Loader debugger instrumentation is reported separately. Hardware traps affect scheduling, so command bytes, original balanced execution, all Core stream identities, bounded typed state, worker quiescence and complete cleanup must be compared with the parent. Raw ASLR/live-object differences remain unmasked. Failed or incomplete replay results do not establish callback absence.

The [closed passive replay and classification](../evidence/linux/reporting-provider-passive-1.json) now record native/GDB exit zero, no checkpoint mismatches or read errors, the identical command and all five full Save identities. Its original component checker also passes against the corrected construction control and execution. All **3,140** raw hits are retained; the armed worker phase has eight cache delegate tail jumps, ten registered translator pointers and seventeen pre-publish getters. These observations are a single same-source replay, not a second independent fixture or a universal callback census.

The selected cache calls have this concrete classification:

| Calls | Original target and observed effect boundary |
|---:|---|
| 7 | Resolved target `0x2708590` is the static-function delegate thunk. Its adjusted receiver is executable address `0x27ff430`, Unit EventStream OnUnitUpdateEvent. The original static getter/cast returns that address as the function pointer. OnUnitUpdateEvent tail-calls PublishUpdate, which snapshots the real Unit into a cache entry, allocates in `ms_aEventInstances` at `0x3c03858` and invokes EngineUtility `+0xb8`. Seven host CacheUpdated event **275** Publish getters are observed. This establishes cache/output work; transitive snapshot Fill effects and complete cache state were not captured. |
| 1 | Queue-complete event `0x9ea4c222` resolves directly to YieldMonitor::OnMessagesProcessed at `0x2c66430` with a real live receiver. It conditionally runs plot/trade yield checks when the actual active human count is nonzero. The plot check compares real yields, writes changed values into its receiver-owned cache and can recursively report plot and aggregate yield changes. Its actual predicate result, cache contents, trade-route callback and complete transitive effects remain unobserved. It cannot be accepted as a no-op or excluded as planning-only. |

The ten translator pointers are UnitActivityChanged `0x320b670` (three), UnitOperationDeactivated `0x320ccb0` (two), UnitOperationsCleared `0x320cd30` (two), UnitOperationAdded `0x320cb30` (one), UnitOperationStarted `0x320cbb0` (one), and NotificationActivated `0x3212d00` (one). Each corresponding Publish getter is also observed. Operation translators construct stack payloads/headers, copy identities and enums, then Publish. Notification translation reads typed values and preserves event order before Publish257. Activity translation also acquires a real Unit facade and invokes its virtual `+0xb0` and `+0xb8` before Publish35; complete transitive facade effects require further evidence. No authoritative Core mutation is proven by this capture, and no universal absence of such mutation is claimed.

All seventeen selected pre-publish pointers are **null**: event275 seven times, event35 three, event70 two, event71 two, and events67/68/257 once each. Therefore these observed Publish calls bypass their optional pre-publish callbacks. This is scoped absence for the actual getter hits. It establishes neither absence of later queued-event consumers nor absence of subscribers in another profile. Host EngineUtility additionally performs parameter-based dirty-component bookkeeping; its inspected Add helper deduplicates ComponentIDs and appends to receiver-owned vectors. Actual dirty registrations and vector changes were not captured.

Both selected generic-sender flag checkpoints had **zero hits**: map `0x2d4a4c6` in replay1 and vector-map `0x2d4a521` in replay2. Inspection of the actual typed overloads resolves the mistake: Type-only, identity, identity/int, identity/int/int and Value/Value methods each implement their own enabled/suspended checks, map construction, cache dispatch and EngineUtility call. They bypass both generic methods. The first report's vector-route attribution was unsupported and is corrected here and in its derived public summary; frozen raw observations remain unchanged. The verified actual typed-send paths reaching cache/provider require successful enabled and false suspended branches; invoked delegates require enabled cache updates. These are branch facts, not direct flag values or a flag history. No additional run is required solely to repair this unused observation.

Raw callback/receiver pointers and process addresses are preserved. The observer's mapping-derived module offsets are retained as reported; for the ET_EXEC host its mapping starts at `0x400000`, so that mapping offset must not be mistaken for the ELF virtual address used by the static audit. Host translator pointers themselves supply the pinned ELF addresses in this replay. Raw ASLR/live-object differences are never masked. Cache target addresses are normalized against the separately captured XP2 load bias.

The [focused second replay](../evidence/linux/reporting-provider-focused-2.json) uses the same archived source/preload/configuration with four hardware points, no inferior calls or game writes, and fresh process/output paths. Native/GDB exit zero, command identity and all five Save identities agree again. Its observation is decisive: **active human count is 1**, and the actual YieldMonitor receiver has **6,996 plot-cache entries and 182 trade-cache entries**. The raw spans are 223,872 and 14,560 bytes. Original plot iteration shifts each index by five, proving 32-byte entries; the original trade destruction loop decrements by `0x50`, proving 80-byte entries. The observer's original unclassified-width annotation remains in raw evidence; these widths are a separately evidenced static refinement. Both collections are nonempty. An inactive or empty-monitor shortcut does not apply to this profile.

The exact active-human predicate iterates Player::Manager's actual alive list, counting IsTurnActive only for players whose actual IsHuman is true. IsHuman reads that player's real configuration; IsTurnActive reads live byte `+0x290`. The count-return checkpoint at `0x2c66439` captures EAX before the original zero branch. Nonzero executes CheckForPlotYieldChanges followed by CheckForTradeYieldChanges. Plot checks compare the current local-observer yields against the receiver-owned per-plot IndexLists, assign changed cached values and report plot changes `0x1f943311` and aggregate changes `0x8fef0d8e`. Trade checks scan actual Trade routes, locate receiver-owned origin/destination cache records, compare/update FixedPoint yields and report changed routes `0x14deda5a`. These are exact instruction-derived rules, not invented fixture IDs. Neither before/after cache contents nor the individual comparison outcomes were captured.

The activity translator's Unit facade calls occur only when the **new** activity is OPERATION `0x490cc8e1` (original host compare `0x320b6c8`). That explains one observed `+0xb0` and one `+0xb8` call across the three activity translations. Both actual targets and the real facade table match XP2 Exports::Unit: GetOperationType `0x2c93be0` and GetOperationParams `0x2c93c40`. Both bodies read the real Unit's current queue rather than restoring the old node. Type reads the front handler and resolves its registered type. Params invokes the front parameter object's Write(caller map) only when nonnull. The inherited SharedParameters::Instance map Write (`0x28199e0`) is empty, including SingleLocation's binding; SkipTurn inherits parameter-free BaseHandler::MakeParameters. No direct authoritative Core store or lazy Core field initialization occurs in these two inspected Exports bodies. Arbitrary replacement handlers or parameter overrides require their own exact binding/support.

Unit snapshot FillConstants (`0x28050e0`) copies three raw source fields to its output. FillVariants (`0x2805100`) directs every explicit non-stack store to the destination snapshot, copies source fields and calls movement, combat, upgrade, readiness, formation and name getters. Its bool parameter is unused by this target body, so passing false does not skip those dependencies. The inspected Unit name getter selects existing definition/veteran/GreatPerson name pointers without a direct Unit store. The identified Unit virtual name slot matches `GetName` (`0x2c28d20`). This narrows the observed callback's direct writes to cache/output construction; it does not establish a complete transitive getter purity proof.

The remaining exact dependency is concrete. Active plot-yield reads delegate to Rules::Yields::GetYield (`0x2bf5ad0`, 3,498 bytes), whose city/player/climate/improvement queries and actual virtual bindings are not fully closed. Trade reads delegate to CalculateTradeRouteOriginYield (`0x2be3b70`) and CalculateTradeRouteDestinationYield (`0x2be4120`). Origin path-yield calculation (`0x2c08a80`) reads an existing path and can fall back to FindNewPath. Snapshot upgrade/readiness getters similarly invoke further original rules. The inspected monitor routines directly write monitor cache values and emit reports, but all transitive authoritative/lazy writes, temporary pathfinder state and possible recursive callback effects require evidence. No namespace-based exclusion or universal no-op claim follows from their names or from unchanged Core stream regions.

The kernel now has a concrete reporting environment dependency: it must model or reject the seven Unit snapshot cache/output calls and the queue-complete YieldMonitor continuation, plus real translator/facade/dirty-component effects. Exact rejection before mutation remains required for unsupported environments. This evidence does not admit a complete Rust live action. Matching the known `be08f44a...` post-Core stream does not cover omitted live state, complete gameplay RNG, subscribers in other profiles or complete turns. Full-host admission and gameplay parity remain false. The separate raw Save→Load **89,198-byte failure** remains unclassified and unmasked.
