# Linux Game.Techs owner

`game_techs` decodes the current version 3 Game.Techs owner and projects its bounded Read/Validate semantics with an explicit native-order technology registry. Complete gameplay state, action execution, upkeep and turns remain unimplemented. This is source validation and a saved-owner diagnostic, not native differential acceptance or a complete Core parser.

The pinned Linux module is SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. The static audit checks the original function bodies and selected call sites without executing game code. Proprietary disassembly stays in `../c6-ghidra/evidence/linux-game-techs`; the public [report](../evidence/linux/game-techs-source.json) records addresses and hashes.

The source wire grammar is:

| Owner field | Current wire representation |
| --- | --- |
| Owner header | u32 version 3 |
| Nodes at raw owner +0xc0 | u32 count, then ordered TechNode records |
| TechNode | u32 version 3; u32 technology hash; canonical byte bool active; i32 FixedPointT8 raw cost; u32 prerequisite count; ordered u32 technology hashes |
| Iteration at raw owner +0xf0 | u32 count, then ordered u32 technology hashes |

The raw node stride is 0x30; its signed native type is at +0, active byte at +4, raw cost at +8 and prerequisite vector at +0x10. The iteration vector is independent of the nodes. SQL edges and SQL row order cannot replace either vector. CurrentVersion at `0x2f549d0` is 3; the decoder refuses other versions. Native TechNode Read supports historical defaults before active's version 2 and cost's version 3; those historical formats are outside this decoder's support boundary. Noncanonical bool bytes are explicitly refused.

Owner Read `0x2a2c200` calls ClearTechs, reads both vectors and calls ValidateTechs `0x2a2c290`. Each serialized TechTypes value goes through `0x2d4ef20` to HashToIndex `0x2016480`: actual definition Find(hash), GetCollectionIndex on success, otherwise signed -1. `DefinitionLookup` therefore means the admitted native collection's Find behavior, including direct small-index handling and duplicate-hash behavior. It does not mean a SQL row-ID lookup.

ValidateTechs stably removes nodes whose remapped type fails definition Find, then removes failing iteration entries, then failing prerequisites from each surviving node. Predicates at `0x2a2e040`, `0x2a2e100` and `0x2a2e1c0` call Find with the signed native type converted to unsigned. They do not add a separate -1/0xffffffff sentinel test. No active filtering, sorting, deduplication, missing-definition insertion or prerequisite rebuilding occurs in this function. `Techs::project_read` retains duplicate occurrences, exact order and raw cost bits. It returns a distinct `ReadProjection`, so raw serialized hashes cannot masquerade as validated native indexes.

InitializePostLoad `0x2a2d120` calls BuildTechs `0x2a2c8e0` if **either** nodes or iteration is empty after filtering. Otherwise it returns without graph mutation. `ReadProjection::post_load_without_rebuild` implements this exact branch and returns `BuildTechsRequired` for either empty vector. BuildTechs uses runtime/rules initialization inputs and ordering logic that this module does not implement. InitializeNewGame also enters BuildTechs; Reset clears both vectors. These paths cannot use a fabricated empty graph or SQL-derived substitute.

The resulting `Graph` supplies GetTechNode's positional fast path followed by first matching type in native node order (`0x2a2d180`), HasTech's node-active projection (`0x2a2d160`) and ordered prerequisites (`0x2a2d3e0`). GetTechNode returns absent for -1. An absent node yields false active availability and the empty fallback prerequisites. The owner constructor `0x2a2c6c0` constructs its +0x110 vector at call `0x2a2c789`; vector/base constructors `0x21e39d0` / `0x21e4110` initialize empty begin/end/capacity pointers. Clear/Read/Validate and the no-rebuild post-load branch never modify this fallback field. This empty result applies to the projected constructed-owner lifecycle, not an arbitrary mutated live capture. Graph construction here is owner-local source projection; module/rules/DLC/mod/configuration binding and snapshot provenance must still be enforced by the admitting caller. It is not a claim that native callbacks or the complete post-load lifecycle executed.

The existing immutable ff31 original Core and its independently attributed owner trace select exactly one save-1 Game.Techs owner: `[73312277, 73314260)`, **1,983 bytes**. Those offsets select a diagnostic input; they are not parser constants. The typed decoder consumes the complete slice: **75 nodes, 75 iteration entries and 249 aggregate items**. This report does not remap that slice with a genuine admitted registry, assert post-filter nonemptiness, or compare it to an initialized native graph. Core transport currently retains this later owner inside its untouched tail; witness-bound component export and rules-bound admission are separate composition work.

Reproduce the static audit and source checks with:

```sh
python3 tools/linux/game_techs_audit.py --output /tmp/game-techs-source.json
```

The checker compiles the exact owned Rust source with std-only API-shaped Limits and DefinitionLookup test shims. It checks duplicate positional selection, stable filtering, prerequisite/iteration order, raw cost bits, every truncation, exact and one-short byte/item budgets, invalid version/bool/trailing bytes, empty-after-filter rebuild refusal, and the existing original owner grammar. These synthetic registries are explicitly test data. The v2 audit extracts its complete immutable source-preimage tar into an archive-hash directory and compiles only that retained tree. It verifies every extracted preimage before and after compilation, including the checker shims and audit helper. Executables are retained under archive/build/executable hash paths; reruns do not overwrite prior candidates. The report records the base Git commit, complete actual source differences, compiler and standard-library identities. Earlier v1 mutable-path candidates and reports remain historical artifacts with their original limited provenance. This avoids attributing a build to unrelated concurrent checkout changes. No original game code runs.

For live admission, export all node records, their complete ordered prerequisites and the independent iteration vector after native Read/Validate/PostLoad, together with exact module, native-registry, enabled DLC/mods, configuration, source snapshot and capture identities. Capture node counts and whole vector contents in one paused observation, preserve duplicate occurrences, and retain the empty-fallback-vector observation. For the nonempty source-projected path, bind the same owner slice to its attributed snapshot/trace and actual technology registry, then compare its complete projected graph to this passive capture before treating it as differential acceptance. Action acceptance additionally requires all affected gameplay state, RNG, ordering and logical identity; native save production is not a gate. The recorded **89,198-byte** Save→Load difference remains retained and unmasked.
