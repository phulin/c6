# Linux Unit event output boundary

The Unit EventStream entries, delivery keys and allocator statistics are rebuildable output state for the no-UI simulator. They need not match the native heap or node IDs when that delivery interface is omitted. This conclusion follows the concrete consumers and storage bindings below; it does not exclude the authoritative Unit, its properties, snapshot query effects, other reporting subscribers or unknown save bytes.

The [focused audit](../tools/linux/unit_event_consumers_audit.py) gates the original XP2 and host SHA-256 identities, checks consumer callsites/vtable bindings, scans original `.text` references to the queue global, and fully decodes/re-encodes the selected before/after Unit with the production Rust codec. Run `python3 tools/linux/unit_event_consumers_audit.py --output evidence/linux/unit-event-consumers.json`. The [report](../evidence/linux/unit-event-consumers.json) records those results and method fingerprints. This runs no original game code.

`ms_aEventInstances` is the 80-byte local ELF object at `3c03858`. Its complete direct-reference set is global initialization `1fc2e40`, Uninitialize `27ff200`, GetStatus `27ff230`, Add `27ff2d0`, Process `27ff3b0`, Destroy `27ff410` and Clear `27ff420`. Initialization registers a destructor, not a serializer. No serializer directly references the queue. Process and the inspected downstream consumers do not return or retain the entry pointer. This is a bounded lifetime/consumer proof, not a claim that arbitrary aliases or external interface calls are impossible.

Delivery enters through Exports.Context.UpdateCache `2c7d3d0`, Dispatcher.Receive `2723e40` and the registered Unit.OnUnitCacheUpdate delegate `27ff440`. The delegate requires stream type `15d11e18` and passes the key to Process. Process validates the key, selects the reflected player using the copied owner, updates its Unit collection, then destroys the queued key. The node key does not become a gameplay Unit ID; reflected identity comes from the copied constants.

Cache.Unit.Update `28056c0` copies constants, variants and properties into the reflected Unit. Cache.Player.Units.Update `27f3500` handles update command 2 by finding that reflected Unit, copying it and updating cached map membership only if location changed. Create/destroy commands also act on reflected containers. The concrete context and map virtuals lead to separately owned storage: Cache.Game.CreateMap allocates a new `0x1e0` object, Cache.Map constructs its own UnitContainer at `+b0`, and virtual `+c8` returns that container. Shared Map container method names therefore do not establish a write to the native gameplay map. These inspected consumer bodies invoke no gameplay reporting callback.

Other queue readers expose scalar type/count/capacity/entry-size/peak statistics to logging and playback diagnostics. The concrete manager slots resolve GetStatus, LogStatus and CachingEventPlaybackComplete; none exposes an entry pointer to rules. The direct-call review found no native gameplay reader of this Unit output state. Exported Unit accessors explicitly distinguish native and reflected pointers; reading reflected output to choose a later action belongs to the external player policy in the intended boundary. This supports omitting this specific output delivery path, without declaring all cache objects nonauthoritative.

The dynamic-property source is the actual Unit's embedded ordinary Data::TypedVariantMap at `+1f8`, returned directly by `2421a00`; no provider or alternate property object is selected. Its wrapper and the fresh Entry destination invoke the same pinned host map constructor. Add copies to Entry `+200` with null exclusion map and append=false. The full production Unit codec consumes all 73 fields and roundtrips both closed records; their property entry counts are zero and their entire property wire records are four zero bytes. The map writer records the actual entry count without filtering entries, so an empty wire map does not hide inline or nested values.

For this supported empty-property shape, Copy clears an empty destination, sees source begin==end, skips every per-entry/custom-array/CreateVariant branch, then assigns the source/default manager pointer. SetManager on the empty destination reaches SetManager_Base `3968b60`, which only stores destination `+20`; it does not call the manager, acquire a reference, change the source, draw RNG or emit reporting. Thus ordinary empty property ownership copying adds no gameplay callback dependency. Per-callback live property pointers/counts were not newly observed; the exact initial/final source records and supported empty-source branch remain the stated profile. Arbitrary nonempty/custom variant copying is not accepted by this proof.

For implementation, retain exact authoritative source properties and any gameplay effects of producer queries. The [Unit event effects audit](linux-unit-event-effects.md) closes the reviewed Placement/upgrade reads and pins one actual old-empty AWAKE HasAdjacentMove=true call; HoldCycling remains unresolved for other reachable branches. Do not require exact computed UI snapshots, queue keys, reflected output maps, peak allocations or output heap layout to admit a no-UI transition once its authoritative effects and applicable query branches are handled. No new native capture is required merely to reproduce those output values.

Raw evidence remains local under `../c6-ghidra/evidence/linux-unit-event-consumers/consumers/`. No private upload or Ghidra mutation occurred. Complete state/action/turn support, complete gameplay RNG coverage and full action admission remain unimplemented; the historical 89,198-byte Save→Load failure and unknown bytes remain unmasked.
