# Linux City/District production review

The movement-relevant registry and initialization rebuild are accepted at `eee78a3` plus correction `da41b51`. This review covers `city_district.rs`, its `RuntimePlotInputs` integration, and the source contract in [linux-city-district-state.md](linux-city-district-state.md). It does not establish complete City/District state, native mask parity or movement parity. Machine-readable identities and results are in [city-district-review.json](../evidence/linux/city-district-review.json).

One concrete defect was found and fixed. After the saved Wonder hash resolves to a native index, original Read narrows it to signed i16. Both augmentation branches subsequently call **BuildingDefinitions.Find**, converting that packed value to u32, rather than indexing with At. The initial implementation used At. An independent source-only reproducer resolves index 32768, narrows it to -32768, then resolves `Find(0xffff8000)` to a different CanalWonder definition. The earlier checkpoint returned DefinitionMapping; the corrected checkpoint returns the source-expected mask 23. Original calls at `0x2d7b13d` and `0x2d7b1eb` and the Canal-only packed -1 guard at `0x2d7b12a` are now pinned by the audit. The independent Bridge path retains its lack of that guard and performs Find after actual Wonder completion. These large-registry cases are synthetic contract tests, not observed native gameplay branches.

The remaining inspected behavior matches the original query contracts. Lookup retains requested IDs separately from actual record owner/full ID; ignores generation bits and component tags where the native manager does; rejects the sentinel ID; and uses the actual District plot owner for its parent City lookup. A missing player mapping or table remains unavailable, while a proven invalid player or complete empty table proves absence. IsCity compares the resolved District definition hash with City Center and does not require completion. District instance IDs never substitute for definition indexes.

The adapter preserves an absent District separately from unavailable lookup and a zero mask separately from an unavailable mask. The rebuild performs the complete base pass before XP2 augmentation, in plot order. Canal and InternalOnly branches remain independent; CanalWonder does not require Wonder completion, while Bridge does. Adjacent City checks use the original IsCity semantics, including incomplete City Centers. Water retains the native Terrain index 15/16 fast path. Coastal, Wonder-completion and directional adjacency inputs must be supplied explicitly; none are inferred from incomplete Map or registry data.

Slot tables borrow validated records, cap each container at 65,536 slots and perform lookup without allocation. Player availability occupies a fixed 65-entry array. Rebuild checks its plot bound before reserving one fallible mask vector, borrows the Map and registry, and returns no partial result after a missing dependency. It does not mutate the input or implement subsequent construction, pillage, destruction or transfer updates.

Review validation reran the 76-method static audit and both original serialized-prefix fixtures, all six focused Rust tests, and a separate harness. The harness checked requested/resolved owner and ID differences, low-16 aliasing, ignored tags, player 64, actual-owner parent lookup, missing versus empty tables, sentinel/out-of-range absence, duplicate-slot rejection and unavailable versus zero masks. It also checked all 65,536 raw mask words against eight domain values (524,288 cases), and reran the independent corrected Wonder regression. All passed. The original prefix fixtures contain 245 Cities and 1,284 Districts each; they do not export live masks or prove runtime definition indexes. No original-code execution was performed for this review. Native mask/movement comparisons and real rules/runtime providers remain pending.
