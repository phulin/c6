# Linux Unit event snapshot effects

This is a bounded static follow-up to the active reporting callbacks in [the provider audit](linux-reporting-provider.md). It does not establish complete gameplay, callback purity, RNG coverage or full host action support. The reproducible report is [unit-event-effects.json](../evidence/linux/unit-event-effects.json); generate it with `python3 tools/linux/unit_event_effects_audit.py --output evidence/linux/unit-event-effects.json`. The tool reads pinned originals and closed evidence and does not execute game code.

The seven observed armed phase-5 Unit callbacks resolve through thunk `2708590` to `OnUnitUpdateEvent 27ff430`. Their event hashes are, in order, `e23b112d,383669f1,15c35863,e23b112d,3d4006f2,e23b112d,383669f1`. These are actual callback observations; source Unit pointers and computed snapshots were not captured at FillVariants. The before/after typed Unit evidence identifies the fixture actor separately and must not substitute for per-callback pointer provenance.

`OnUnitUpdateEvent` takes the component identity at event-data+8 and invokes `PublishUpdate 27ff860`. A valid resolved Unit reaches `Add 27ff2d0` with update command 2, map layer 0 and false boolean. Add constructs a snapshot, fills constants and variants, copies dynamic properties, and allocates an event-stream entry. `FillVariants 2805100` does not use that boolean to suppress queries. Its explicit non-stack stores target the destination snapshot; this observation alone says nothing about transitive callees.

The native entry is 296 bytes: command at 0, 12-byte constants at 4, 184-byte variants at 16, property map at 200 and map layer at 288. Exact variant offsets and eleven low flag bits are in the report. The native String type's extent is incomplete in the available type information; bytes between its offset 16 and the next field at 24, upper flag bits and padding are not classified as independent state. String assignment may allocate destination storage.

`KeyedAlloc 27ffb20` allocates a node, inserts it under the old u32 next key, increments that key with wrapping arithmetic and updates peak allocation. Allocation failure returns UINT_MAX. Publish sends CacheUpdated only when the returned key differs from UINT_MAX; an old key of UINT_MAX can therefore mutate the container without publishing. The seven observed CacheUpdated calls prove seven accepted returned keys, but their values, complete entries and allocator/peak state were not captured. These are real cache writes. The later [consumer audit](linux-unit-event-consumers.md) proves their bounded reflected-output role and permits omitting these queue/allocator values in a no-UI implementation, while retaining authoritative producer-query effects.

The upgrade snapshot queries follow ordered definition upgrades, player build-unit mapping, tech/civic prerequisites and a cycle-checked recursive selection. Gold and resource cost queries read existing player cost vectors, formation and discount parameters; they do not deduct currency/resources in the inspected bodies. Their fixedpoint temporaries are on the stack. MaxDamage's property-map dispatch resolves to the host const tree lookup, not insertion. Before and after serialized properties are empty; intermediate callback property maps are unobserved. Nonempty imported map copy can invoke child variant/copy machinery and is not universally classified as pure.

Readiness has a meaningful transitive dependency. ReadyToAutomate requires CanMove and no pending operation. ReadyToSelect requires ReadyToMove, no automation, and !CanCyclePast. Member readiness requires no delayed death, positive native fixedpoint moves, no pending operation, AWAKE, automation -1 and no busy state; multi-member formations check existing members in native order. CanCyclePast returns false for NeedsAttention or HasAdjacentMove, otherwise queries both command and operation HoldCycling managers. Those managers can invoke full registered CanStart logic with testVisible=false and a result map; subtype/scripts and their effects cannot be omitted without proving that branch is skipped.

HasAdjacentMove tests six neighbors with Placement flags 1, null output plot, INT_MAX distance and an empty callback. This excludes Placement's alternate-location search because flags & 0x30 is zero; it does not exclude terrain, embarkation, diplomacy, visibility and defender queries. GetBestDefender receives flags 0x108. Its concrete Unit comparator `2bdfdb0`, called via PLT `1e932d0` at `28ca077`, accepts a candidate if the current best is null, rejects a null candidate otherwise, and compares signed GetCombat(false) strictly. Ties retain the earlier candidate. The attacker argument is unused. The comparator and reviewed strength/max-movement query bodies have no source writes, reporting or RNG. The surrounding native Unit/XP2 Map query closure is now reviewed: existing layer/cell vectors supply candidate IDs, missing cells return an existing fallback vector, and EditUnit resolves an existing player/container slot without allocating or changing it. Actual flags 0x100 skip ordinary visibility, hidden visibility and visibility-layer queries; only coordinate/definition validation and TeamVisibility owner matching remain. Religious-strength early return and strict strength comparison preserve native candidate order. No source writes, reporting, RNG, allocation or lazy insertion were found in these reachable query bodies. Actual candidate identities and intermediate computed results are not captured.

A narrowly scoped passive readiness checkpoint is RVA `2c28137`, bytes `84c07518`, immediately after HasAdjacentMove and before testing AL. AL is the result and RBX retains the actual Unit. Identity is u32[RBX+b8], owner i32[RBX+130], location i32[RBX+100/+104], activity u32[RBX+290] and NeedsAttention u8[RBX+738]. Require the armed callback phase and FillVariants → ReadyToSelect → CanCyclePast provenance. True skips both HoldCycling fallbacks. A preserved failed replay prefix now captures this exact call: selected owner 0/unit 15794187, location (81,58), AWAKE, queue count 0, NeedsAttention 0 and AL=1, with the required Fill → ReadyToSelect → CanCyclePast frames. The next original conditional therefore skips both HoldCycling managers for this call. This is an instruction-derived next branch, with no separate post-jump checkpoint. The replay then failed at the monitor-entry vector decoder and terminated without proven cleanup, completed effects interval or coherent poststate. Its 32-hit readiness cap prevents a complete census claim. The report binds configuration dff58116edc7f77ccfa668279bf70864083ccafb9f96dede2715fc9164fc2c44 and exact failure/observation hashes; it does not promote this failure into action acceptance.

The concrete Placement diplomacy checks read blocked-entry bool vector +2c20, open-border counters +498 and symmetric alliance/permanent/war vectors. CanEnforceBorders is a direct +480 read. Embarkation scans existing pass vectors and tech/civic definitions/prerequisite flags; it does not unlock embarkation. Native plot city-attribute lookup indexes an existing sparse vector, falling back to entry 0; its nonconst indexing signature does not allocate. District checks read definition hitpoints, existing completion/pillage flags and player strength statistics, producing caller-stack fixedpoint results. Original actor fields pin originalOwner 0 and barbarian tribe -1; these are initial fields, not a new per-callback read. Exact method fingerprints and concrete Unit/XP2 Map/Plot virtual bindings are in the report.
