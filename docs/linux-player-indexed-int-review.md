# Linux Player component review

Checkpoint `c01b8aa` is accepted for its stated bounded scope: Goody_Hut v1, Bonuses v4, complete current Congress v12 and nested Refund v12 wire values, explicit registry overlays, and structural first-player indexing through Congress to Cities. No concrete implementation defect remains. This does not establish a complete Player codec or native Player.Read lifecycle equivalence. Source identities and review results are recorded in [player-indexed-int-review.json](../evidence/linux/player-indexed-int-review.json).

The reviewed grammar matches the original current serializers and readers. Indexed arrays contain ordered hash/i32 pairs; Congress's GovernmentSlot vector is positional. Congress includes all six favor scalars, four indexed arrays, four modifier scalars, the counted Refund vector, bool and final victory-point scalar. Each Refund carries the Congress version constant 12, its Resolution hash and two signed values. Current-version refusal, canonical bool checks, truncation and trailing-byte errors are explicit support boundaries.

Read application preserves the important native differences. Goody_Hut overlays existing values and retains the omitted applying flag; Bonuses invokes its concrete Reset, which explicitly clears and zero-resizes before the overlay. Congress resizes to the active MinorCivBonus count before each overlay, preserving the old prefix. The original `Types::Vector<int>::resize` growth loop has no initialization stores, so newly exposed values remain unavailable unless supplied by known prior state or mapped wire pairs. `MissingResizeValue` correctly refuses to invent them. Later duplicate mapped pairs win; unknown hashes are consumed without writing. These helpers use the supplied actual Find/GetCollectionIndex mapping rather than pair position or SQL order. Omitted Congress runtime fields remain required owner state and are not classified as planning-only.

Independent field comparison checked **6,182 typed scalar/count leaves** across all 86 existing original Congress records and both first Goody_Hut and Bonuses records. The first Congress range and following Cities boundary matched the original ownership observations after structural parsing; no fixture offsets select those boundaries. The two normalization streams share the same context and do not represent independent gameplay branch diversity. All original Refund vectors are empty. A separate source-only carrier with distinct signed values and two nonempty Refunds checked another 41 leaves, including each nested version and full-width hash. No native nonempty Refund observation is claimed.

The independent application harness checked 820 ordered sequences containing duplicate, unknown and direct-index/hash keys, and 4,920 Congress resize cases over shrinking, unchanged and growing prefixes. It checked zero Reset values, preserved Goody flag/prior state, last-write ordering, missing-growth refusal and resource/destination-size errors. The 37-method target/DWARF/vtable audit and all four focused Rust tests were rerun successfully. Original bytes independently inspected included Congress Read, Refund read/write, indexed-int overlay, Bonuses Reset and uninitialized int resize. No original game code executed.

The codec checks cumulative wire item counts and consumed/output bytes, uses checked arithmetic and fallible vector reservations, and returns no partial result on error. Application copies only bounded component vectors and borrows prior inputs and definition mappings. Its byte/item limits bound individual allocations and wire work; they are not a measurement or cap of aggregate allocator overhead or all simultaneously live vectors. Real active rules mappings, omitted runtime state, archive/dirty effects, complete City/Player state and the downstream Unit roster remain separate dependencies. Wire equality does not establish state/action/turn parity, and the recorded 89,198-byte raw Save→Load difference remains unmasked.
