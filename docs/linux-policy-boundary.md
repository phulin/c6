# Linux external-policy boundary: activation and research

The library implements isolated primitives, not complete Civ VI actions or turns. This bounded **static** result identifies a concrete native technology decision before the previously documented active-player `TurnManager::DoTurn` human guard. It proves neither runtime suspension safety nor complete decision coverage. No native fixture, action, message drain or turn ran for this work. The [private-source manifest](../evidence/linux/policy-boundary-sources.json) pins the disassembly and DWARF behind the typed claims; regenerate it with `tools/linux/policy_boundary_sources.py`.

The user requires external policies for **all player decisions**, while original rules, gameplay state and gameplay RNG stay exact. Off-turn analysis and objects bearing AI names cannot be discarded by name. The exact supplied XP2 SHA-256 is `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. The [reproducible audit](../tools/linux/policy_boundary_audit.py) gates that hash and verifies original direct calls, branches and defined-symbol GOT relocations. [Its report](../evidence/linux/policy-boundary-contracts.json) includes the entire mixed `QueueNextTech` body identity. All addresses are ELF virtual addresses before rebasing. Original symbol listings, targeted disassembly and DWARF remain private in `../c6-ghidra/evidence/linux-policy-boundary/`.

Discovery consulted cru121, *Civ6-GameCore-reference*, revision `5af389445118bed2bdebf7a8a42b219c8fba5175`, CC BY 4.0, especially `findings/topics/ai-contracts-and-operations.md`; see [reference attribution and limitations](reference.md). Its contracts/planning descriptions were leads. The following conclusions use supplied Linux symbols and bytes, not reference Windows RVAs.

## Ordered graph and mixed responsibilities

[The prior action boundary](linux-actions.md) establishes `PlayerTurnComplete::Execute` → `SetTurnComplete` → `Game::Instance::Update` → `Game::Processor::Update` → player processor, followed by `Diplomacy::Manager::ProcessPending`. The active-player processor eventually calls `TurnManager::DoTurn`, which returns for human configuration; inactive players enter AI Control directly. That guard alone is insufficient to establish an external-policy loop.

`Player::TurnManager::DoTurnActivate(bool)` (`0x2ba0b60`) performs original conditional upkeep before calling AI Control activation at `0x2ba1077`. Its ordered calls include deals, culture, religion, great-person points, influence, quests, diplomacy, city activation, heroes, congress, espionage, climate resource reset, resources, units, governors, trade, statistics and eras. Later it runs actual city turn activation and cultural-identity transfers, resource maintenance, unit manager/operation virtual callbacks, formation movement restoration and game signals. These are required progression candidates whose complete nested rules and decisions remain unclassified; a subsystem name is not proof every nested call is passive upkeep. In particular, the unit-operation virtual call at `0x2ba0f73` needs its concrete loaded implementation traced before calling this phase decision-free.

`AI::Control::Manager::DoTurnActivate(bool)` (`0x201e880`) is mixed:

1. It records turn time, increments the real game-state lock, records human state and conditionally calls `GlobalAi::ProcessAi` for a nonhuman branch.
2. It waits for jobs, dispatches off-turn subscribers at `0x201e941`, repeats dispatch/wait according to the returned status and its bounded retry counter, clears an archived flag and decrements the game-state lock.
3. It reconciles actual unit controller IDs, sets priority 4 and invokes registered activation callbacks at `0x201eacc`, decrementing priorities through 0, then restores priority 4 and emits reporting event `0xa235ddf7`.

There is no enclosing human early return around steps 2–3. `InitializePostLoad` (`0x201dde0`) populates the activation vector with CityManager, the barbarian/free-city branch, behavior trees, planning, diplomacy, religion, targets, grand strategy, governors, research, economic, espionage, homeland, culture, military and tactical callbacks. A callback's own guards determine whether it analyzes, maintains gameplay or chooses. The exact registered vector and original iteration order must be observed in a loaded profile; this is not a declaration that every callback is prohibited policy.

`TurnManager::DoBeginTurn` (`0x2ba1750`) separately enters AI Control `BeginTurn` (`0x201e660`), which calls `GlobalAi::ProcessAi`, dispatches a priority signal and maintains actual controllers/contracts. `DoEndTurn` (`0x2ba1770`) calls units, cities and culture end-turn methods. Replacing the whole AI Control manager or omitting begin/activation/end would therefore omit proven state and callback transitions.

## A concrete decision with original RNG and gameplay mutation

`AI::Research::DoTurnActivate(ControlPriority, bool)` (`0x2185a70`) has mixed analysis/contracts/reporting behavior. At `0x2185e9f` it tests actual `Player::IsHuman`; humans branch over `QueueNextTech` at `0x2185eb0`. `QueueNextTech(TechTypes)` (`0x2186110`, size `0x2fc`) independently rejects humans, then selects and **synchronously commits** research. This is a concrete policy boundary rather than an inference from an AI class name.

The first branch iterates actual `TechTreeAnalysis` objects, selects using its comparator and goal/next-tech information, checks original `Player::Techs::CanResearch`, assigns its goal field, and calls `Player::Techs::SetResearchingTech` at `0x2186224`. It then reads `GetTurnsLeft` and updates its archived bookkeeping. Matching DWARF names its `TechTypes` argument `completedTech` (DIE `0x015936d4`, with original method at `0x0159367b`/specification `0x015158a7`); the activation caller supplies sentinel -1 in ESI at `0x2185ea8`. It participates in the analysis comparator; this method is not a public request accepting an already chosen technology.

The fallback branch enumerates the native technology-definition count in index order. It excludes owned technology with `HasTech`, tests `CanResearch`, and appends actual `TechTypes` with weight 1. For nonempty candidates it calls `WeightedVector<TechTypes,10>::ChooseAtRandom` (`0x2189f00`) at `0x2186360`. The resulting technology is assigned to the archived goal field, committed through original `SetResearchingTech(tech, insert_mode=0)` at `0x218638d`, followed by original `GetTurnsLeft`, archived turns update and goal reset to -1. Empty and retained-goal branches have distinct continuations. The analyzed path writes the `FAutoVariable<TechTypes>` wrapper at research+`0x248` through `0x218620b`, commits with InsertMode 0, obtains turns at `0x218622c`, and writes the `FAutoVariable<int>` wrapper at research+`0x290` through `0x2186244`. The fallback writes the tech wrapper at `0x2186371`, obtains turns at `0x21863a1`, updates the int wrapper at `0x21863b9`, resets the tech wrapper to -1 at `0x21863ce`, destroys the temporary vector at `0x21863d8`, and joins the epilogue `0x21863dd`. Wrapper addresses are not asserted to be inner-value offsets. These archived values remain in exact state scope until their role is proven. Legal candidates must use these exact native types and predicates, not operation hashes or invented IDs.

The random delegate is resolved from original GOT relocation `0x3b1c648` to `Game::Instance::GetRandNum(unsigned short,char const*)` (`0x1fe5240`). `ChooseAtRandom` supplies the candidate count narrowed to unsigned short, obtains an unsigned-short result and indexes the original candidate vector. `GetRandNum` edits the game's actual `FAutoVariable<Random>` at game offset `0xe8`, then tail-calls `Random::Get`. Thus this **policy choice touches the gameplay RNG object**. Planning ownership does not establish that these draws can be masked, replayed unconditionally or omitted from later comparisons.

`Player::Techs::SetResearchingTech` (`0x2b8ba90`) is the concrete gameplay commit boundary: it validates definition/ownership conditions, branches on InsertMode, changes the real research queue using Clear/PushBack/PushFront/RemoveByValue as appropriate, and emits original reporting events. It returns through the research callback's remaining reporting/analysis and the manager's priority loop. Hooking only this setter is too late for the fallback RNG draw and prior goal mutation.

The smallest **proven selection region** is inside `QueueNextTech`: the analysis comparator loop begins at `0x2186190`; the fallback candidate selection call is `0x2186360`, after native candidate enumeration. At that fallback call boundary the vector in RDI, original delegate in RSI and log string in RDX are live; return EAX is the selected native technology and original code immediately performs bookkeeping/commit. The analysis branch has no analogous scalar selection callback; its outputs are chosen technology, goal state and subsequent native queue/bookkeeping continuation. No existing scalar selection callback accepting an external technology was identified in that region. A prospective entry interception at `0x2186110` is broader than those selection sites and must account for the entire mixed method. An eventual adapter could suspend with the original native frame alive before a proven selection site, expose the genuine candidate IDs/predicates, receive an external choice and execute the original gameplay setter and required continuation. A synchronous external-policy callback could also supply that choice without unwinding the frame. These are prospective adapter designs, not implemented hooks. They must preserve the caller's stack/container ownership, goal/turn bookkeeping or prove which bookkeeping is planning-only, and maintain the original activation priority/event continuation exactly. Returning early from `QueueNextTech`, returning from its caller or calling the setter alone does not establish that contract.

## Off-turn subscribers, jobs and diplomacy queues

Two concrete subscriptions were verified beyond the prior off-turn dispatch:

| Subscriber registration | Actual callback | Observed effects; unresolved role |
|---|---|---|
| CityManager initialize `0x1fcf8f3`, GOT `0x3b1de78` | `CityManager::DoOffTurn` `0x1fcfc60` | Checks city analysis readiness, calculates yields, iterates actual city builders and calls their off-turn methods. Complete gameplay/planning classification unknown. |
| GrandStrategic InitializeSignals `0x2120fb5`, GOT `0x3b20990` | `GrandStrategic::DoOffTurn` `0x2122f70` | Submits victory/region jobs at `0x2122fd0`/`0x2123019`, runs jobs, calculates best units and invokes continuation. Job outputs, RNG use and whether any choice commits are unknown. |

`CityBuild::DoOffTurn` (`0x1fd8cb0`) checks research/culture/diplomatic analysis readiness, writes archived flags/vectors, updates AI trade-city state, submits a job at `0x1fd8dc4`, runs jobs and invokes continuation. These writes are evidence of effects, not proof of planning-only exclusions. Other `DoOffTurn` symbols exist; a complete subscription census and collector behavior are still required.

Actual DWARF defines four-byte enum `OffTurnProcessingStatus`: `NOT_PROCESSED=0`, `PROCESSED_CONTINUE=1`, `PROCESSED_STOP=2`. The subscriber type is `OffTurnProcessingStatus(std::__1::function<OffTurnProcessingStatus()>)`. It receives an actual native function/container, not a raw C callback pointer. This is an internal cooperative work continuation; its name/value 2 does not establish a host-visible external-decision suspension API. The manager consumes status internally and may call again before returning.

`GlobalAi::SubmitJob` (`0x20fb020`) calls `JobManager::PushJobOntoList` with the real job set. `RunJobs` (`0x20fb070`) uses original EngineUtility virtuals and `SpawnList`; `WaitForJobs` (`0x20faa30`) blocks through original `JobSet::Wait`, then clears original processing flags and conditionally calls another EngineUtility virtual. Waiting is synchronization, not a yield before decisions. Job completion can mutate state outside the core message queue, so queue-empty is insufficient. No job was classified as dispensable merely because it is AI-owned.

`Diplomacy::Manager::ProcessPending` (`0x2913510`) copies the original ever-alive player vector and, for each original IsAI player, repeatedly calls `ProcessPendingSessionStatement(player,-1,direction=1)` until false. The latter (`0x2911900`) removes an actual pending statement, then calls `ProcessStatement` at `0x291199d`. Session `ProcessQueue` (`0x2917ac0`) pops its front statement **before** calling `Session::Process`; manager `ProcessStatement` can add a statement to a real session queue or process directly. These are separate queues from Messages::Manager. Statement subclass virtual processing/response callbacks and full ownership/serialization/decision effects remain unresolved. They cannot be replaced by “no diplomacy pending” flags.

## Candidate status and pause APIs

Actual DWARF declares `Game::Instance::SetPaused(bool) -> void` (`0x2661df0`) and `IsTurnProcessing() const -> bool` (`0x2661cb0`). SysV uses the real receiver in RDI and bool argument in SIL; bool results use AL. SetPaused assigns the original archived paused flag and emits event `0x562fd140`. It has no frame/continuation token. The inspected activation callback loops and `QueueNextTech` do not test the pause flag; toggling it after entry is not a proven way to stop a running choice. It may gate enclosing update paths; that does not retroactively unwind them. IsTurnProcessing tail-calls the original processor predicate and supplies observation, not suspension. Existing HasPendingMessages/NeedsUpdate/IsAiProcessing are also observations, not universal decision readiness.

The absence of a proven pause API does not rule out an adapter preserving an original frame or a narrow external-selection callback. It means that suspension and continuation need their own evidence and native fixtures.

## Concrete next experiments and remaining acceptance gaps

1. In a complete identified Linux session, use observation-only breakpoints at player activation entry/exit, `0x201e941`, `0x201eacc`, `0x2186110`, `0x2186360`, `0x2186224` and `0x218638d`. Record actual player/control, priority, call stack, candidate IDs/order, native predicates, selected technology, research queue, archived goal/turn fields, all RNG object state/counts and message/diplomacy/job state. Breakpoints must initially preserve execution. This tests which branches actually occur before human readiness, including barbarian/minor/free-city and automated units.
2. For the lowest technology region, independently characterize analyzed-choice, retained-goal, empty-candidate and random-fallback continuations. Record the exact original goal/turn fields and events on both sides. Use full native containers and original definition IDs. Prove native pause/resume or synchronous callback lifetime/locking with no dropped jobs/events; a debugger stop alone is not that proof.
3. Compare branch-restored runs with **the same external technology choice**, preserving native rules calls and explicitly identifying which RNG calls belong to replacement selection versus mandatory rules. Define expected stream progression under external control before testing. Do not arbitrarily consume a native random-policy draw to “keep counts aligned,” or discard its downstream gameplay-RNG consequences. Selection-policy replacement and original-AI replay are different oracle profiles.
4. Trace concrete session statement subclasses and all remaining activation/off-turn/automation subscribers to choice commits and mandatory continuation. Observe pending decisions after each original synchronized host pass, including choices arising off turn. A per-player turn loop alone cannot enumerate these boundaries.

Reproduce this static checkpoint with `python3 tools/linux/policy_boundary_audit.py --output target/linux/policy-boundary-contracts.json`. No native safety, action acceptance, RNG parity, full affected-state equality or complete state/action/turn equivalence follows from a passing audit.
