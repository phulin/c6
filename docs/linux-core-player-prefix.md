# Linux post-Map Player prefix

[`core_player::Prefix`](../crates/c6-core/src/core_player.rs) reads the current Linux raw Core wire stream beginning immediately after Map. It decodes Game.Religion7 and every ReligionData7, Player.Manager1's framing, the first Player.Instance47 header, the complete first Formation collection, Goody_Hut1, Bonuses4, Congress12 and **the complete Player.Cities15 collection and its trailing fields**, followed by complete Player.Diplomacy50, Player.Districts8, Player.NameManager2, Player.Culture45, Player.Espionage17, Player.Religion20, Player.Resources16, Player.Stats27, Player.Techs6, Player.Treasury10, the complete Player.Units22 envelope, Player.Eras2, Player.Trade35, Player.GreatPeoplePoints13, Player.Influence22, Player.Quests1, Player.WMDs1, Player.Improvements1, Player.Governors6, Player.CulturalIdentity10 and Player.Heroes6. It then follows the saved WasEverAlive branch through its three bool-hash tables and complete current AI.Control/InfluenceMap/Planning wire records when present, stopping before AI.CityManager on the true branch and completing the common inline suffix on the false branch. The original true-branch fixtures still leave the first Player partial. Source-proven false-branch completion covers one wire Player only; this does not read later Players, establish a full global roster, load a live game or execute actions/turns.

`Prefix::decode_prefix_with_items(bytes, unit::Limits)` returns `(typed_prefix, consumed_bytes, dynamic_items)`; `decode_prefix` omits the item charge. The consumed position identifies the supported prefix boundary. `Boundary::AICityManager` leaves the true first entry partial; false-branch `NextPlayerEntry`/`AfterPlayerManager` follow one complete wire Player. `unfinished_player_entries` subtracts that entry only after its real tail closes. Empty Managers return `AfterEmptyPlayerManager` without consuming later Game components. Trailing input is untouched. `encode_prefix_with_items` returns the encoded supported prefix plus its exact item charge; `encode_prefix` omits that charge. Encoding refuses inconsistent boundary/count/first-entry combinations and writes no unsupported tail. There is intentionally no strict full-Player decoder or opaque unframed skip.

Manager's requested owner and the record's embedded owner remain separate fields. The original Manager writer obtains the ID from the same Player it then serializes; this supported writer-wire grammar requires equality and rejects a mismatch. It does not infer a roster-index/player-ID mapping or reproduce Manager.Read initialization and fixups. The header retains its fifteen ordered i32/enum scalars and six bools without speculative scalar names; hashes remain full u32 words, and religion names are counted byte strings without UTF-8 normalization. Formation and City owners are preserved as written without rewriting them to the Manager ID.

After this container, Player.Cities15 writes:

1. Fresh-water-housing bool and urban-defenses i32.
2. Home Continent hash and counted settled Continent hashes.

The unused `m_buildingBuildMap` is not invented as another wire vector. `m_Initialized` is likewise not serialized by this writer. Native names are taken from matching Linux layout leads and direct member-address/call observations; omitted live values are not classified as planning-only.
