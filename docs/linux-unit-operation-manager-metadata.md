# Linux Unit Operations Manager metadata preparation

The new [native observer](../native/linux/unit_operation_manager_metadata.c) prepares raw live inputs for the [typed Manager providers](linux-unit-operation-manager-world.md). It has **not been executed against the engine**. Its [static audit](../evidence/linux/unit-operation-manager-metadata-preparation.json) passes; a separately admitted runner profile, native capture and native/typed comparison remain required. Complete gameplay state, gameplay RNG, action execution and turns remain unimplemented. Neither existing handler captures nor this preparation establish full Manager parity.

The observer targets only Linux XP2 module SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa` and matching host `106d4986567cf60aad787dfac990d089e41775e04b5f40e073f59a3a8ffe74f4`. Original symbols/DWARF and full target bytes support these contracts. Existing raw disassembly remains private under `../c6-ghidra/evidence/linux-unit-operation-manager-world/source/` and `../c6-ghidra/evidence/linux-unit-operation-manager/`; the public artifact contains fingerprints and conclusions. Historical reference material remains discovery-only under [existing attribution](reference.md).

The initial unexecuted preparation at commit `fca6e3e` had an address-handling defect: it added the host's `dladdr.dli_fbase` to host constants that were already absolute ELF virtual addresses. That source/evidence pin remains historical and must not be admitted. The current v2 preparation corrects it and adds an offline regression that rejects that exact displaced symbol address.

The pinned host is **ET_EXEC**, with first PT_LOAD and required `dladdr.dli_fbase` at `0x400000`. Its symbol/table constants are ELF virtual addresses; runtime addresses add only the load bias, `dli_fbase - 0x400000`, which is zero for this target. Thus the original host lookup is at absolute `0x395f480`, its const-map conversion at `0x321c700`, and the map vptr at `0x53b3690`. GameCore is **ET_DYN** with zero-based ELF VAs/RVAs; its actual load base is added to those constants. The helper verifies the host base and lookup address plus mapped ELF64 little-endian x86-64 headers with the respective ET_EXEC/ET_DYN types before native calls. The audit independently verifies both pinned ELF types and first PT_LOAD VAs. Whole-file SHA identity remains a required caller gate.

The configured phase provider chain is closed for a concrete standard map binding. `Configuration::Game::Instance::InitializeGameVariants` (`0x28e54d0`) stores the game-values map at receiver `+0x88`. It either obtains the existing root `Key_Game` TypedVariant and converts it to a map, or constructs a real TypedVariantMap and inserts it into the root at `+0x80`. The observer requires both actual maps to have the original host map vptr at absolute host VA `0x53b3690`, with const virtual slot `+0x70` bound to host VA `0x395f480`. It verifies the actual root `Key_Game` const conversion equals the actual `+0x88` map, and verifies the original const conversion's address (host VA `0x321c700`). Unknown providers return unsupported before lookup; no provider or native object is constructed.

`GetTurnPhaseType` (`0x28e4870`) first calls `IsNetworkMultiplayer` (`0x28e48b0`). That getter uses the actual map's const `+0x70` lookup for `Key_GameMode`, converts the returned borrowed TypedVariant to unsigned int, and compares four original game-mode enums. A nonnetwork game returns the original `0x2a45183d` phase hash. A network game uses the same map lookup for `Key_TurnPhaseType`, then the original signed-int conversion. Actual keys come through the target's GOT globals. The const lookup performs a tree search and returns an existing entry or the original static default variant; its complete direct host leaf closure and both conversion closures are fingerprinted. The observer exports both raw 24-byte variants as well as the original configured result. Raw variant bytes retain noncanonical/unknown content; they are not an opaque-state simulation substitute.

All pointers are borrowed. The caller must retain the genuine configuration, its actual root owner, nested map and real variant manager until the observer returns. The original configuration destructor (`0x28e46d0`) destroys its root only when the actual ownership flag permits it, and destroys its own manager afterward. The observer never releases these objects, retains variant references beyond the call, mutates configuration, initializes a map or repairs a missing key. Existing [saved-configuration lifetime evidence](linux-saved-configuration.md) remains relevant to retaining host-owned roots; it does not replace this live identity check.

`c6_linux_unit_operation_manager_metadata_probe(module, borrowed_context)` writes exclusive JSONL to `C6_UNIT_OPERATION_MANAGER_METADATA_OUTPUT`. Its input rows contain facts, without supplied admission answers:

- `configuration`: actual receivers/map/vptr/lookup identities, actual key words, raw GameMode/TurnPhaseType variants and original configured phase hash.
- `operation_definitions`: actual ordered definition slots, count, collection index and hash; signed original FindIndex and HashToIndex results for numeric and hash keys; actual registry runtime IDs and present handler identities. GetCount and size are **u32**, despite the size body computing in RAX; FindIndex and HashToIndex are **i32**, as declared by target DWARF.
- `phases`: signed raw current-phase enum, complete original 32-byte vector header, allocator slot, validated begin/end/capacity and ordered nullable definition pointers. Present definitions supply rowid, type hash, signed PhaseOrder and nullable ActiveSegment; present segments supply rowid and the full raw flags byte at `+0x50`.
- `player_slot`: an explicit row for each of all 65 queries, with the actual mapped index, original mapping-validity result, stored pointer and resolved Player pointer. Original GetPlayer must agree with the original validity/stored-identity relationship. NULL resolutions are retained.
- `player`: every resolved actual Player ID, raw turn-active byte at `+0x290` and actual slot-status enum. The separately saved PlayerHeader flag `[2]` must be compared independently; this helper never supplies that expected answer.
- `unit_disabled`: every actual Unit from each actual Player's native container, including unplaced Units; actual owner, ID and ordinal; full 32-byte IndexList header, actual u32 size and allocation capacity, default byte at `+0x18`, and ordered unmodified value bytes. Bounds, capacity and pointer overflow are checked before reading values. Each roster entry must agree with original Find(fullID), and duplicate low-16-bit slots are rejected; traversal count must equal the native count. This is input to independent saved hash-list remapping, not an IsOperationDisabled answer.
- `globals`: actual Game pause byte at `+0x228`, signed automation-player global at module `+0x3c06598`, actual ScriptSystem pointer and, when present, actual vptr. The pure 11-byte script getter (`0x2171660`) only performs a GOT/global load. Script slots, callback registration and callback effects remain uninspected; availability never implies callbacks are absent.

The first `profile` row declares schema `c6-linux-unit-operation-manager-metadata-v2` and records actual module/host base and host load bias. `roster_summary` records all 65 slots, actual resolved-player count and actual Unit count. A final `complete` row appears only after all observations and the final quiescent check succeed. Acceptance requires status zero, framing rows, exactly 65 unique `player_slot` queries and consistent actual roster counts; a marker does not override an I/O failure.

The new `c6_linux_unit_operation_manager_metadata_quiescent` guard must be supplied by an independently reviewed admission profile. Missing guard/receiver/binding/bounds is unsupported, with a nonzero status. Unknown work from the guard immediately exits `240`, before subsequent observation or cleanup. Partial output from any failure is not an accepted capture. Existing `2aaaa`, `902` and frozen `58171` captures/candidates are unchanged. This helper does not call full Manager CanStart, handler CanStart, script callbacks, action requests or end-turn logic.

The packet also pins the wrapper's original const GetSyncRandom (`0x2d7b4d0`, returning actual Game `+0xf8`), the Map.Random global (`0x3c072f0`, 32-byte symbol), and GameCore::Random DWARF layout: seed/call/reset/lock words at `+8/+12/+16/+20`, synchronous byte at `+24`, total 32 bytes. This covers only those two known objects; the preparation takes no RNG snapshot.

The runner still needs to gate module/host/dependencies/rules/DLC/mod/configuration/source identity, retain the genuine loaded context and owners, and provide four internal plus two outer raw Saves, checks of the two known Game/Map RNG objects, independent repeat and controlled cleanup. Those known RNG checks do not establish complete gameplay RNG coverage. Same-context live facts must be compared to independently saved Unit/PlayerHeader fields and the actual ordered rules data. The recorded **89,198-byte** raw Save→Load failure remains unclassified and unmasked.

Reproduce preparation without original execution:

```sh
python3 tools/linux/unit_operation_manager_metadata_audit.py \
  --output target/linux/unit-operation-manager-metadata-preparation.json
```

The audit gates 72 complete original method bodies, both whole ELF hashes, concrete const-map binding and constructor vptr origin, target DWARF scalar widths and storage layouts. It compiles the helper with strict warnings and the C analyzer, and runs UBSan tests of the actual host-symbol binding, ELF-header and extent guards, raw-byte preservation and unsupported null-entry boundary. The host regression accepts absolute lookup VA `0x395f480` with `dli_fbase=0x400000` and rejects the erroneous sum `0x3d5f480`. These tests use no fabricated game receiver or original engine execution and do not count as native metadata parity fixtures.
