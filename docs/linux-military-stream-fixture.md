# Passive Military Load/Save fixture

This is preparation tooling, not a genuine native observation or complete Player/gameplay acceptance. The [observer packet](linux-military-initialization-observer.md) owns the original method/schema gates. This caller owns `context_stream.c`, `stream_observation.h`, `military_observer_runner.py`, the fixture audit and the ordinary-load runner mode.

The new mode performs only the existing original Context Load and two Context Saves. It adds no native query, SQL, handler, FullManager, Lua, action or turn call. A caller-owned marker reports actual constructor-created MemoryIStream/MemoryOStream pointers, borrowed Context, payload, size, path and fresh occurrence. The 80-byte record is materialized before an exact return-only naked marker. The actual compiled marker may have a four-byte CET `endbr64`; hardware stops at the symbol or its checked return instruction are accepted without changing the PC. The synthetic GDB test verifies the actual descriptor and marker bytes; it executes no original game code.

The original stream source projects exactly back to committed `cd4b227` after removing instrumentation and restoring the single existing input-offset expression. No original getter is added. Load markers distinguish ready, original return, release and destruction. Save markers additionally distinguish native return from successful file close. A release retires attribution before the original destructor; a destroyed marker never permits dereferencing the recorded stale pointer.

One pending hardware execution breakpoint watches the marker. At most three other hardware lanes follow the observer's tested original entry/return/branch/query/count schedule. The stop method only queues registers/thread; the outer drain creates/deletes breakpoints after the stop callback unwinds. No FinishBreakpoint, software game breakpoint, inferior call or field write is used. GDB's own loader rendezvous instrumentation is disclosed separately. Initial and final original-method fingerprints must match actual mapped code. Actual registers, thread, RSP, return PC and dynamic frame IDs are retained.

Each Military identity is scoped to its selected original Read/Write frame and actual receiver, with a fresh generation even if an address repeats. The pre-Read owner is unverified and is not dereferenced. Original Initialize entry supplies the actual Player argument; the observer checks that installation before owner snapshots. No continuous owner lifetime between Read and a later Save is inferred. Initialize calls outside an attributed Read are outside this profile's coverage.

The caller passively requires the actual host worker pointer to be NULL and controller initialized byte to be zero before checkpoints. It does not substitute `!IsExecuting` for a completion barrier. Known policy-call counters are unavailable: this mode installs no GOT interposer and claims no runtime policy-zero proof. Its invocation scope is ordinary Load/Save only.

The actual whole `xp2benchmark.civ6save` supplied to the saved-configuration loader is identified by full path, byte extent and SHA, separately from the actual incoming raw Core MemoryIStream artifact. The historical configuration digest is a whole-file digest, not a section hash. No container-to-Core extraction relationship is inferred by this observer. The first profile observes incoming `a667` Read ranges and each of its own actual output Write ranges. A later fresh Read of `ff31` or `85d` requires a distinct profile; Write snapshots are not reused as subsequent Read initialization.

The rules input gate, DLC descriptor identities and configuration inputs are recorded. The active gameplay SQLite database is not serialized: its snapshot digest is unavailable and is never replaced by a rules-input hash. Actual original query pointers, defaults, ordered definitions and count results remain observations. No extra SQL/serialization operation is added.

After original Load, the caller records two known 32-byte RNG objects and requires their bytes/identity to remain stable before and after each Save. This is not a complete RNG inventory or a claim that Load preserves RNG. Each Save's native buffer hash must match its own successfully closed raw Core output file; every original Military Write receives its actual output ID/range. The two actual Saves, full native teardown and source/config/dependency gates require independent closure review. Unknown bytes remain unmasked; the historical 89,198-byte Save→Load discrepancy is not resolved here.

GDB runs in a fresh owned session. PID/starttime/executable/session identities are retained. The current leader is checked before any signal; if a leader is gone, only exact previously witnessed member identities can be signalled. Reused leaders or unknown members are never treated as owned, and unresolved executing processes block any retry. On timeout, debugger failure or caller exception, the caller kills and waits for its own traced session and records whether any executing process remains. Disposal never counts as successful native cleanup. A failed capture remains unsupported and is preserved; no automatic retry occurs.

The [fixture contract](../evidence/linux/military-stream-fixture-contract.json) records source projection, original accessor bytes, fifteen guard groups, stop-API negative injections and the synthetic hardware-marker ABI test. Original execution still requires a frozen prepared profile and independent admission.
