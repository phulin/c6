# Independent internal turn-completion kernel review

Corrected source checkpoint `337fa32` passes review for the internal dispatch prefix, setter/hook traversal and concrete overflow-clearing leaf. The [review evidence](../evidence/linux/turn-completion-kernel-review.json) pins all four author-owned files, the compiled review fixture's committed dependencies and exact Linux target identities. The [review driver](../tools/linux/turn_completion_kernel_review.py) checks independently inspected full methods, retained-receiver instructions and the original global completion-array address, then runs a discriminating City/owner/queue fixture. No original code was executed. Public `Engine::apply(EndTurn)` remains Unsupported before mutation; complete turn, gameplay state/actions/RNG and external decision-boundary parity remain unimplemented.

Initial checkpoint `d5b1f70` omitted explicit receiver captures. Independent complete-method inspection found that Execute obtains Game before the human query and retains that object for pause; SetTurnComplete captures one Player Manager after its global write and retains it across all 64 validity queries; each required Game.Update has a fresh Game lookup. The author corrected these contracts and added replacement/order tests. The pointer getters themselves are pure target loads, not newly discovered service callbacks. The tests use synthetic replacements to discriminate retention/order; they do not establish that the actual pure getters invoke callbacks. The historical checkpoint remains preserved; approval applies to the corrected source.

Unsigned encoded Player values above 63 reject before resolution, including negative i32 bit patterns. A valid encoding resolves the actual requested Player and captures Game. Human-and-paused invokes the full logging provider, then synchronous report `0xa7b85261`, and returns before completion checks. Nonhuman skips only the pause query. Duplicate completion logs and returns without reporting or Game.Update. Logging remains an exact service/format/allocation obligation; its branch-dependent repeated Player GetID reads cannot be replaced with an eager cached ID. The report provider owes EventType construction followed by current requested GetID and the actual Send/subscriber effects. No alive/active or CanEndTurn admission gate is invented.

SetTurnComplete writes the original global `Player::ms_abIsTurnComplete[requested.GetID()]` at `0x3c06210`, a 64-element bool array distinct from serialized Player fields. False assignment still returns true and performs no manager/hook loop. True captures one Manager after the write, visits numeric slots 0 through 63 in order, and for each valid slot rereads **the requested Player's** alive state and invokes **that same requested Player's** hook. It never substitutes the enumerated Player or simplifies the traversal to one call. Later validity and alive reads observe synchronous effects; the Manager receiver remains retained. Native out-of-domain object IDs would be unchecked; the Rust provider boundary rejects them explicitly rather than inventing a successful branch.

Even NONE and unknown raw reason hashes traverse EditTurnManager and its actual owner's Cities accessor on each qualifying hook. Forced and timer reasons additionally resolve the Cities object's actual owner and query that owner's human status. For a human, original recycled-container order is preserved: cursor dereference, City GetID, Cities Find, actual City build queue, then Front. The complete target Front method returns null exactly when its queue size is zero, supporting the typed empty-entry predicate for complete valid queue state. Only that branch calls the same returned City's EditBuildQueue and clears overflow. Increment precedes a fresh End lookup. IDs are not sorted and the container is not snapshotted.

ClearOverflow targets the queue's fixed-point overflow at `+0x1f4` and assigns integer zero; no other queue field is changed. The surrounding City edit is not a pure accessor: complete `FAutoVariable<BuildQueue,City>::edit` inspection shows a conditional insertion of the wrapper into its owner's dirty set before returning the value. Dirty-set ownership, tree insertion/allocation and archive effects remain a required provider. A wire codec or direct field assignment cannot fulfill that dependency. Errors after the completion write or queue effects can retain partial internal mutation; no generic rollback is promised.

After the prefix, exactly one whole Game.Update is mandatory. Its target wrapper calls Game Processor Update, pending diplomacy and cache profiling in order; those full transitive effects remain required. On return, the same requested Player's current active flag is reread. True requires one further whole Update with a fresh Game lookup; the second return performs no third active test. `RequiresGameUpdate` expresses internal Rust sequencing only. It is not a resumable native stack, an external player-policy yield or successful public EndTurn. No provider may return Ok after skipping unfinished upkeep or genuine external decisions, including NPC/offturn/diplomacy/automation choices.
