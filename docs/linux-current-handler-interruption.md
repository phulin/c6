# Current queued handler interruption

The accepted 63-handler metadata capture contains actual handler vptrs, **but no runtime `+0x20` method-slot contents**. Looking up those vptrs in the pinned ELF image predicts two families: 62 point to the true BaseHandler leaf and one to the false MakeTradeRoute leaf. That lookup does not establish actual runtime dispatch: dynamic interposition or vtable rewriting has not been excluded. The [successor audit](../evidence/linux/current-handler-interruption.json) explicitly labels every target, result and corpus grouping as an original-image prediction and sets runtime dispatch admission to false.

This v2 evidence corrects v1 from commit `3bd25f6`, report SHA-256 `d9b7ff5a2c20a92397f473e0b91f80dcd4073996f77d206f8ac9848346c8a367`. That historical report remains in Git history; its `target_rva`, `result` and family labels must be read as source predictions, not observed runtime bindings. Neither version executes original code or establishes native Manager predicate parity.

The original-image BaseHandler `0x2d95660` and MakeTradeRoute `0x2da0920` bodies are complete three-byte constant leaves. Neither reads the handler, changes memory, allocates, calls another function, or consumes RNG. In the captured registry, MakeTradeRoute has runtime ID **18**, hash `8374d954`, and vptr RVA `0x3b03960`; these identities must be observed again for a different registry/configuration. The independently checked saved corpus has 954 empty queues and 308 one-node queues per capture. Joining those saved hashes to captured registry vptrs and then to original-image relocations predicts **185** false-leaf and **123** true-leaf queues. These joins span different capture contexts and supply neither live slot pointers nor native interruption results. A requested native ID equal to the native current ID bypasses leaf dispatch in the original source.

`c6_core::unit_operation_interruption::ObservedRegistry` now supplies concrete lookup and handler leaf behavior using the existing `messages::HandlerId` and `OperationHash` types. The constructor checks the exact target module identity, evidence identity shape, slot identities, unique explicitly observed reverse-map answers and supported original function targets. Each handler target now carries explicit provenance: `LiveSlotObservation` or `OriginalImagePrediction`. The latter always returns `UnobservedLiveBinding`, even when the predicted RVA names a supported leaf. Unknown targets, unobserved hashes, invalid native numeric accesses and missing saved-hash resolutions return explicit errors. A null slot and an observed native hash miss remain distinct from missing evidence. It does not accept caller-supplied interruption booleans or add a trait-only provider. The existing generic Manager orchestration retains empty-front, same-ID and actually-null-current-handler branches.

Admission remains an external evidence obligation: callers must retain the genuine owners, establish the live Manager virtual slots and observed actual handler `+0x20` pointer, and bind observations to the same configuration and synchronous context. Supplying a digest string or manually labeling an RVA `LiveSlotObservation` does not authenticate native memory or prove that an old snapshot remains current. Source-only unit tests use synthetic slot observations to exercise the model; they do not admit the closed captures as runtime bindings. `saved_hash_runtime_id` only translates a wire identity; it does not turn a saved queue into a live queue. No full Manager provider is installed by this module.

## Identity and lookup ordering

Manager `CanCurrentOperationBeInterrupted` at `0x2da2a60` receives the requested operation bits captured by its caller. It reads the Unit queue, permits zero size or null front, then rereads front zero and compares that node's first 32 bits directly with the captured requested bits. Those native node bits are not the serialized operation hash. Equal bits permit interruption without resolving a handler. Different bits call the Manager's const GetHandler virtual `+0x88` with the current bits, permit an actually null result, and otherwise tail-dispatch that actual current handler's `+0x20`. No Unit or requested-operation argument reaches the interruption leaf.

Original const GetHandler `0x2da1650` constructs HashID from unchanged bits. HashID::IsIndex `0x270bbb0` uses an **unsigned `< 0x800`** test. Index-form keys access Manager `+0x18` vector storage without a native bounds check. An out-of-range numeric key therefore cannot be invented as a null-handler success case. Other bit patterns call const GetHandlerFromHash virtual `+0x98`. That implementation calls GetHandlerIDFromHash `+0xa0`, which searches Manager's `+0x38` reverse map and returns `-1` on a miss; a miss yields null, otherwise it delegates back to GetHandler. Definition collection indices, SQLite rowids, operation hashes and native front IDs remain distinct even where this fixture's observed IDs coincide with collection positions.

The original static Manager vptr RVA `0x3aff880` has the expected `+0x88`, `+0x98`, `+0xa0` and `+0xd8` bindings. The accepted metadata and earlier registry records do **not** contain a live Manager vptr or these delegated slot pointers. The new audit verifies all 63 metadata reverse mappings and concrete handler vptrs against the independently accepted earlier registry report, but does not merge their different observation contexts. Existing captures establish registry mapping and saved queue census; another capture must observe actual runtime handler method slots together with Manager slots and queue fronts in one retained synchronous context. An ELF relocation cannot fill a missing runtime method slot.

## Minimal future read-only capture protocol

This is a protocol specification, not a new runner or permission to execute original code. The existing sole native runner owner must prepare and admit any capture independently.

1. Reuse the established exact GameCore/host hash, rules/configuration/DLC identity, retained original initialized owners, main-thread synchronization, idle admission, full-roster traversal and terminal cleanup gates from the accepted Manager metadata fixture. Host ELF ET_EXEC symbol addresses are absolute VAs, with zero load bias. Retain complete unmasked Saves and known Game/Map RNG controls with the same two-pass, six-Save arrangement. Equal Saves do not prove complete transient-state nonmutation.
2. Record the genuine Manager pointer, owning module, live vptr, and actual pointers at `+0x88`, `+0x98`, `+0xa0`, `+0xd8`; normalize GameCore pointers only after range/module validation. Check each against the pinned static implementations before admitting the concrete Rust resolver. Reject other bindings rather than replacing them with base implementations.
3. Preserve actual ordered handler vector storage and nullable slots, each nonnull object's native ID/hash/vptr, and passively read the actual eight bytes at that live vptr `+0x20` in the same retained synchronous context as steps 2 and 4. Record the raw absolute target, mapped owning object/module and executable mapping; normalize only after validating the target belongs to the exact pinned GameCore image and verifying its live code bytes against the complete supported leaf. A missing slot read, interposed target, altered code or unsupported owner rejects admission; an ELF relocation prediction is never a substitute. Reuse the already proven reverse-map getter only within separately admitted read-only instrumentation, or retain the complete typed reverse map. Record observed misses explicitly. Do not populate the reverse map from definition indices or SQLite order. A later reader must distinguish unknown lookup coverage from an actual native `-1`.
4. For every actual Unit, keyed by owner and full ID, retain native queue size and header, front availability, native first-node operation bits and the associated complete serialized queue hash/ownership evidence from the same synchronous context. Preserve all unknown header/node bytes unmasked. Check size/front consistency and any actual hash/native-ID relation; do not modify a queue, manufacture a current handler, or treat the 308 saved fronts as new live observations. Record the actual resolved current handler pointer and virtual target by bounded observation, without invoking Manager predicates or handler methods in this metadata-only protocol.
5. Repeat the complete facts under retained owner identity and require byte-identical facts plus all Save/RNG controls and terminal cleanup. Freeze evidence/checker identities before a future comparison. Empty queues, same-ID bypass, both differing-ID target families, actual null slots, observed absent hashes, unobserved hashes and invalid numeric bounds must remain distinct in replay and failure reporting. Absence of a native boundary case is a coverage gap; no native null slot exists in the current 63-handler capture.

This closes the two original-image leaf implementations and supplies a bounded resolver conditional on genuinely admitted live observations. The existing capture cannot construct an admitted runtime registry from its vptrs alone. Live dispatch/queue admission, native predicate boundary comparisons, scripting callbacks and the remaining Manager dependencies stay open. Complete gameplay state, all RNG, actions, turns and every-player external decision boundaries remain unimplemented. The historical **89,198-byte** raw Save→Load failure remains unclassified and unmasked.
