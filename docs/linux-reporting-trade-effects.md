# Linux reporting Trade-yield effects

The active YieldMonitor callback recomputes Trade yields, but its actual caller excludes the temporary-route/game-signal branch. The accepted before-Core graph contains **182 active routes, all with nonempty forward paths** (6,193 path nodes). A supported path can therefore require successful existing-path lookup and avoid the pooled pathfinder. This is a conditional static contract plus production-codec inspection, not an implemented Trade rule, a new native run or complete gameplay action acceptance.

The [audit](../evidence/linux/reporting-trade-effects.json) pins Linux XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`, exact original method fingerprints, branch bytes and supplied target DWARF. It independently decodes and exactly re-encodes the graph at `[71027800,71497438)` in the accepted `ff31f4c5...` before stream using the production Rust codec. The [focused native evidence](linux-reporting-provider.md) establishes active-human count 1 and 182 live monitor cache records. Serialized graph coverage does not itself observe every live lookup, its indexes or callback order.

The concrete call chain is YieldMonitor route callback `0x2c66a30` → Route origin/destination yield getters `0x2c11920`/`0x2c119a0` → Rules economic calculations `0x2be3b70`/`0x2be4120` → scalar/vector Trade modifiers. The Route getters pass **false** for DWARF parameter `includeTempRoute`. Origin vector modifiers save that argument at stack `+0x10` and branch at `0x2c09a32`; destination modifiers save it at `+0x28` and branch at `0x2c0aee0`. Both false branches skip the entire EditRoute → EditTempRoute → CreateTempRoute → game-signal block. This excludes those mutations and subscribers for this caller by original arguments and control flow. The true branch remains in general Trade scope; its signal at Game::Signals `+0x1380` must not be approximated as presentation output.

The modifier calculation writes caller-owned yield buffers and uses seven invocation-local `InitializeOnUse<int>` objects for district/resource counts. Their Get method writes their own initialized byte `+0x34` and computed value `+0x30`; these objects are constructed on the current call stack. They are real lazy writes, but do not establish a persistent route memoization cache. The false branch does not update the stored Route origin/destination yield arrays. Arithmetic still depends on current city/player modifiers, resources, districts, religion, progress/culture, diplomacy, alliances, suzerains, congress and yield-definition order. These rules are required inputs/state, not captured constants or implemented formulas supplied by this audit.

The cold branch's mutations are concrete. AcquirePathFinder scans the actual Movement pool at `+8/+0x10`, repeatedly tries each finder's native critical section at `+0x180`, and retries when none is available. GeneratePath writes the selected Trade finder's player at `+0x3d0`; the generic finder updates start/destination/info at `+0x120..+0x130`, open/closed/best pointers, its working-node stack/grid and reset/abort flags, and invokes actual registered callbacks and Step. These persistent objects cannot be omitted as planning-only. The inspected FindNewPath body contains no graph cache insertion. Generic callback registrations and their transitive gameplay/RNG effects remain unresolved. No direct Random call occurs in the inspected Trade wrappers; that is not a proof that the complete cold callback closure consumes no RNG.

The native iteration and observer mutations also matter. Manager::IterateRoutes addresses its Graph at `+0xc8`; Graph iterates its **ID-map order**, calling the monitor only for Edge's live active flag at `+0x140`. It does not iterate serialized origin/destination order. The monitor lower-bounds its current sorted TradeYields cache by origin/destination, checks the result against end, and then uses it; the inspected body has no additional exact-key equality check. Preserve that behavior and existing cache contents. Each selected current yield compares recomputed fixed8 origin/destination values, writes changed **monitor cache** values and sends event `0x14deda5a` with the route endpoints when any comparison changed. Those downstream synchronous reporting effects remain part of the reporting environment. This task did not capture individual comparison outcomes or before/after cache values.

For the bounded forward-hit path, Rust needs the actual active-route iteration order, endpoints/resource identities, yield definitions, complete monitor cache, consistent graph indexes/ordered paths, and current rules/map/city/player inputs listed above. Unsupported missing paths or unknown callback environments must be rejected before mutation; assuming all graph inputs have this fixture's cache coverage would be incorrect. A future general miss implementation additionally needs complete finder pool/lock/working-node/delegate state and all affected RNG. Current full Core stream agreement is not a substitute for these live inputs.

Keep the native cost model explicit. The monitor traverses current active routes in native order and invokes scalar origin/destination calculations for each current yield. Scalar modifier wrappers use a stack fixed-buffer yield array with `onlyYield` filtering; local count caches last that invocation. Existing graph paths are reused without rebuilding them or touching the finder pool. This audit supplies no benchmark and does not authorize memoizing across changes to rules inputs.

The smallest distinct unsupported branch identified here is **forward-path miss plus reverse-path miss**, where execution enters the real pooled pathfinder callback/Step closure. The accepted graph has no serialized forward-path misses, so no new native observation or policy/flag bypass was needed to narrow that branch. Complete transitive purity of every modifier/feature getter, precise monitor comparison effects, callback ordering and resulting reporting are not universally proved by this static audit. Complete Rust gameplay state, actions and turns remain unimplemented; full-host admission and gameplay parity remain false. The separate raw Save→Load **89,198-byte failure** remains unclassified and unmasked.
