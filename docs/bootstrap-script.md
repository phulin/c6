# Native script bridge evidence

This is bounded target-version ABI research for original-code bootstrap. It does not establish usable gameplay scripting, initialized game state, action parity or turn equivalence.

`python3 tools/analysis/script_binding_evidence.py` verifies the full EXE and XP2 GameCore SHA-256 identities before extracting targeted instructions into private `../c6-ghidra/evidence/script/`. The public [static report](../evidence/bootstrap/script-binding.json) records addresses and verified vtable entries. No original script registration is executed by this extractor. Reference names from cru121's [Civ6-GameCore-reference](https://github.com/cru121/civ6-gamecore-reference/tree/5af389445118bed2bdebf7a8a42b219c8fba5175), CC BY 4.0, are leads checked against the supplied target instructions.

The original Context vtable slot `+0x68` executes XP2 RVA `0x590440`. It lazily constructs the native static ScriptSystemUtility at `0xb8f0e0` using constructor `0x5a1a40`, which installs vtable `0xa126c8`. Utility slot `+0x10` is `RegisterScriptLibraries(self, genuine_havok_state)`: wrapper `0x5a1da0` moves the state to the first argument and jumps to `0x5bdac0`. Utility slot `+0x18`, wrapper `0x5a1db0`, additionally passes its third argument to the UI registration implementation. These slots are not IUnknown add-reference/release slots. The utility's `+0x08` is the shared empty operation `0x8972d0`.

The genuine host registration callback at EXE RVA `0x1614a0` registers `MapModData` and `GameCoreState`, obtains a Context through `0xf8430`, calls Context `+0x68`, then utility `+0x10`. It subsequently registers another native callback and calls utility and Context `+0x08`. Its protected dispatcher is `0x161160`. The Context provider reads cached EXE global `0x22d60c0`; if empty, it calls the factory pointer at `0x22d64e8` and caches its result. The original module loader `0xf8510` obtains that factory through the module's exported symbol. Directly installing a fake Context provider, or invoking this callback with those globals absent, would not validate the host bootstrap pipeline. This evidence tool does neither.

The ScriptSystem state's native creation path at EXE `0x161a90` registers host libraries before this GameCore registration callback is used. In particular, `0x2a0b40` registers `DB`, `GameInfo` and `GlobalParameters`. The GameInfo callback at `0x2a3440` references `GameInfo_Data`, then unconditionally loads the Civ6App singleton at `0x12c2c88` and calls `0x64660` from `0x2a3504`. That getter reads the application's `+0x54d8` field and dispatches to `0xf02860`. Therefore successful construction of an original Havok manager and an original ScriptSystem object does not establish that native script-state creation can complete: original application/database ownership is an additional prerequisite. This static boundary independently explains the native VM owner's observed null-app fault. A synthetic application shell or suppressed callback would leave that prerequisite unvalidated.
