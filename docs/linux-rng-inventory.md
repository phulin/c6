# Linux RNG ownership inventory

The pinned Linux XP2 contains at least the four RNG families/owners below. This static checkpoint establishes the gameplay combat stream receiver and archive mutation path, and identifies additional state that the existing two-object native observer does not cover. It does **not** establish a complete RNG inventory, complete gameplay state, action execution or turn parity. The Rust library still implements bounded primitives, transport and rules/registry components; full gameplay remains open.

Reproduce without executing the game:

```sh
python3 tools/linux/rng_inventory_audit.py
```

The audit rejects any host or XP2 hash other than [the active Linux profile](targets.md), validates selected actual-target DWARF layouts, hashes method bytes, and scans original XP2 disassembly for direct RNG branches and the exact LCG multiplier immediate. Public [inventory evidence](../evidence/linux/rng-inventory.json) contains derived addresses, hashes and caller relationships. Raw target instructions/debug information are private under `../c6-ghidra/evidence/linux-rng-inventory/inventory-*`. The pinned [cru121 reference](reference.md) supplied Random/ScopedRandom discovery leads; Linux instructions and DWARF determine these contracts.

`Game::Instance::GetRandNum` at `0x1fe5240` adds `0xe8` to its genuine Game receiver and calls `FAutoVariable<Random,Game>::edit` at `0x1fe7230`. If the wrapper has an owner, edit inserts the wrapper into the owner's changed-variable tree at owner+56; it returns wrapper+16. Thus an exact gameplay draw changes seed/call count **and archive tracking**. The target edit call instantiates a unique-key tree with `std::less<FAutoVariableBase*>`: membership is keyed by the wrapper pointer, so repeated edits deduplicate and the tree orders by that pointer comparator. This dirty-set membership is separate from serialized RNG bytes; it must not be encoded as an extra Random record field. Calling only the primitive on a copied Random does not reproduce that complete affected state. The normal getters at `0x28e8af0` and const `0x2d7b4d0` expose the same stream; `EditSyncRandom` is `0x2662460`.

`Game::Initialize` at `0x2661150` obtains the edited sync stream, locks it before component initialization and unlocks it on the normal completion path. This is a wrapping numeric counter, not a mutex: target `Random::Get` neither reads the lock count nor suppresses draws when locked. `Context::Instance::InitializeSyncRandomSeed` at `0x290caf0` reaches `Random::Initialize` on the Game stream; `InitializeGameInstance` at `0x29f5750` checks its seed and uses configuration-seed `Reset` only when it is zero. `Game::SetRandomSeed` at `0x2cb5400` edits the wrapper and calls `Reseed`, which increments reset count while preserving calls and locks. Initializer Reset and explicit Reseed must not be silently replaced with Initialize, which clears counters/locks.

The [Random primitive evidence](linux-random.md) covers 3,072 native/Rust cases. Live Random fields are seed/calls/resets/locks at offsets 8/12/16/20 and raw synchronous byte at 24, plus vptr/padding in the 32-byte object. Normal Write emits version, seed, calls, resets, raw synchronous and legacy flag in 18 bytes. Read preserves the live lock count. The codec therefore does not transport all live state or wrapper bookkeeping. The existing initialized action observer copies and reports both actual Random objects and checks its observations leave them unchanged; it does not capture PCG state or every possible stream. No new native fixture was run for this inventory.

Target `ScopedRandom` ctor/reset/draw/get-seed are `0x2d4d030/040/050/070`. Draw advances the four-byte seed with wrapping `seed*0x41c64e6d+0x3039` and returns the same high-half scaled unsigned-short result as Random, without counters or logging. A complete scan for that exact multiplier immediate found only Random::Get and ScopedRandom::Get; that does not exclude other algorithms, algebraically different inline implementations or RNGs in dependencies.

The PCG implementation is imported from the genuine pinned host: default ctor `0x3c087b4`, seeded ctor `0x3c087c0`, Seed `0x3c087ea`, destructor `0x3c08814`, Rand `0x3c08816`, fRand `0x3c08850`. Seed sets increment=3 and state=`u64(u32(seed))*0x5851f42d4c957f2d+0x08f5dc87e5c07d8a` with wrapping arithmetic. Rand advances state by `old*0x5851f42d4c957f2d+inc` and rotates the u32 truncation of `((old>>18)^old)>>27` right by `old>>59`. Default construction copies a separate 16-byte host constant; a port must verify that constant independently. Cache Lua's bound reduction uses unsigned division rather than Random's high-half scaling: zero bound divides by zero **after** drawing. Primitive native oracles can call actual ScopedRandom after gated module loading and actual host PCG after host CRT initialization without a synthetic Game; their absent Read/Write methods do not authorize inventing a save format.

The direct-call census includes Lua, map, fractal and other consumers but is not transitive proof of ownership. No thread-local or temporary derived stream, fixed-hash pseudorandom helper, AI planning-only RNG exclusion, or exhaustive host/dependency classification has been proven here. In particular, absence of direct ScopedRandom draw calls cannot prove the type unused. Follow-up work should trace script registration and indirect delegate/function-pointer consumption, record per-owner construction/destruction and seed derivation, then extend actual-state observers before accepting stream completeness. Every gameplay draw must retain ordering and all affected archive state; external player decisions remain external. Unknown save bytes remain unclassified and unmasked, including the raw 89,198-byte Save→Load failure.
