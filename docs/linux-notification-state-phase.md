# Linux typed notification lifecycle state phase

`c6_core::notification_lifecycle` implements generic selection, base activation and logical cleanup on the production `PlayerNotifications` codec. It preserves native record order and next-ID state, carries omitted live inputs explicitly, and represents object/pool ownership with logical handles. It does not implement complete Manager::Update, complete gameplay state, accepted actions or turns. `Engine::apply` gameplay support remains unchanged and unsupported.

The [exact original lifecycle contract](linux-notification-lifecycle.md) and [checked static evidence](../evidence/linux/notification-lifecycle.json) target the supplied Linux XP2 module and matching host. The current wire codec correctly names native +0x20 as Message and +0xa0 as Summary after `2c30b37`; this phase preserves both strings and every other untouched field. It never selects a notification using fixture IDs or type hashes.

`find_auto_activate` scans list order. IsAutoActivate uses already-activated state, single-player definition icon behavior and native +0x19d. Eligibility uses a signed severity threshold (0 for single player, 3 for network) or the first matching `c362976f` parameter's bool. A later eligible record with signed lock count strictly greater than zero immediately preempts an earlier retained candidate, even if dismissed or already activated. Otherwise the first eligible unactivated unlocked record survives the scan. No dismissed filter is introduced. The supported bool subset preserves upper union bytes, uses the native low bool byte, and rejects unsupported conversion forms rather than guessing.

`DefinitionIcon::Unobserved` represents a getter skipped by the original short circuit. It is accepted when already activated or the network branch makes the definition irrelevant; a required unknown definition rejects before mutation. MissingDefinition and an observed ShowInSinglePlayer flag are separate inputs. Required manager/player gates include initialized vector, game uninitializing, human configuration, active turn, network/PlayByCloud, actual manager game presence and local owner. Those fields are not fabricated from the codec.

`activate_base_in_place` models original BaseActivate(bool): unconditionally set HasBeenActivated, then synchronously send event `025f6cfd` with identity key `eab69e5a` and the actual argument under bool key `78a2f946`. The automatic pass supplies false and rescans after each synchronous delivery. Actual activation/release/destruction virtual bindings are explicit supported-profile inputs. Nonbase activation and unsupported ownership/destruction reject before mutation. `UnboundDelivery` rejects the activation pass before changes; a caller can bind an exact synchronous simulation through `ActivationDelivery`. Merely collecting events uses the explicitly named `UndeliveredProjection` and does not fulfill reporting/subscriber effects.

Cleanup visits dismissed records in order, executes logical Release, then erases each owner-list node. A pool binding appends the object to that pool and clears its binding. An unpooled object requires the audited base-resource destruction profile and canonical nonowned scalar32 parameters (types 0–4). Owned/nested payload destruction can invoke VariantManager callbacks and rejects before mutation. Pooled release preserves those payloads untouched. Pool vectors retain existing ordered logical object handles and newly released typed objects; unknown fields of existing pool objects are never interpreted. Duplicate notification IDs are allowed, while object-handle aliasing and missing/duplicate pools reject. Allocation, pool reuse/Initialize, subtype-specific extra resources and complete allocator/localization-reference state are outside this phase. Native Create's LIFO pool reuse is documented but not implemented.

Production entry points mutate this component locally after preflight; they do not copy the world. Separate adapters clone only the notification component and delivery model for isolated differential checks. A bound hook must preserve its declared supported ownership/profile and isolate modeled state. External game/configuration gates and the owner-container identity must stay fixed during delivery; native IsAutoActivate reads network configuration per record, so changing that configuration is outside this boundary. Modeled record locks, definition flags, ordering and activation state may change before the next scan. A hook-contract violation or exhaustion of the explicit diagnostic activation budget can leave an in-place prefix and is an error, never native completion. Initial unsupported profiles, unknown required inputs, unbound delivery and an initially insufficient zero budget reject without mutation. The isolated adapter returns no candidate on any error.

The composite function runs **ProcessAutoActivate followed by Cleanup**, not the complete original Update. SendAutoNotify, DismissExpired, notification/owner blocking-state computation and all intervening subtype/provider effects remain separate requirements. Original reporting can invoke synchronous cache delegates and host pre-publish callbacks before queueing. The bounded passive/focused reporting observations do not supply the complete notification manager/pool/input inventory. The live-observer task is collecting those inputs separately; unknowns stay unknown.

Reproduce the read-only check:

```sh
python3 tools/linux/notification_state_phase_audit.py --output target/linux/notification-state-phase.json
cargo test -p c6-core notification_lifecycle
```

The [current checked result](../evidence/linux/notification-state-phase.json) freezes and hashes a private candidate copy before execution, gates both original modules and the static method/vtable contracts, then compares all **2,629 resulting notification-owner bytes** against the actual native after record. The default scenario explicitly assumes zero locks, absent definitions, unpooled base instances and allowed manager gates. That scenario produces the observed 12→9 records and one activation, but **actual native phase input parity is false**. The owner bytes alone do not establish actual locks, pool ownership, virtual bindings or callbacks. A supplied live manifest is hashed; it needs independent passive-observer provenance before any actual-input parity claim. Reporting remains undelivered in this adapter.

Eight test groups exercise signed/locked/dismissed/already-activated ordering, definition/network branches, first duplicate override keys, exact manager/cloud gates, pool/destruction, unsupported owned payloads and duplicate-ID behavior, unconditional BaseActivate arguments, required unknown inputs, rejection atomicity and a synchronous subscriber changing subsequent selection. These are original-contract-derived Rust tests without a native boundary matrix.

The release benchmark separately measures isolated component-copy execution and local mutation over states prepared outside the latter timing. It includes preflight, actual supported phase work and effect allocation/drop. The local timing excludes initial component cloning and final state drop. Both exclude codecs, native code/I/O, actual reporting callbacks, other Update stages, diplomacy, full actions and turns. No whole-world copy or native performance comparison is measured. Complete gameplay RNG/state/action/turn equivalence remains open; the separate raw Save→Load **89,198-byte difference** stays unclassified and unmasked.

The adapter manifest is positional and checks each record's actual identity:

```text
mode undelivered_projection
gates INITIALIZED UNINITIALIZING HUMAN TURN_ACTIVE NETWORK CLOUD GAME_PRESENT LOCAL_PLAYER v1
record OBJECT LOCK_COUNT POOL_OR_MINUS DEFINITION ACTIVATE RELEASE DESTRUCTOR OWNER COMPONENT_TYPE ID
pool POOL_ID ORDERED_EXISTING_OBJECT_HANDLES...
```

Booleans use 0/1. Definition uses `?` for unobserved, `-` for a missing definition, or 0/1 for the observed icon flag. Binding tokens are `base` or `unsupported`. Logical handles never substitute notification IDs or native addresses. All live records must correspond exactly to wire-list order. Actual native captures must preserve missing/short-circuited observations rather than defaulting them.
