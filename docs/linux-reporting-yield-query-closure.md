# Linux monitor plot-yield query closure

For the accepted conditional SkipTurn input profile, the three remaining focused plot-yield effect gaps now have concrete contracts: loaded improvement properties use original const map lookups, improvement adjacency/technology/civic bonuses read existing source data, and the two direct appeal sites cannot enter unowned appeal recomputation under the matching definition inputs. This is a static refinement of the [earlier yield audit](linux-reporting-yield-effects.md), using the [typed Map domain](linux-reporting-effects-observation.md) and existing native rules/definition exports. It neither implements numerical plot yields in Rust nor establishes complete gameplay state/actions/turns.

The [executable audit](../tools/linux/reporting_yield_query_closure_audit.py) and [result](../evidence/linux/reporting-yield-query-closure.json) gate original XP2/host SHA-256, 79 focused construction/query/read bodies, critical caller branches, native virtual bindings, the exact typed Map and rules database. The accepted action, rules exports and native Yield registry export have equal original active-content selections, source inventory, saved configuration and relevant asset identities. Their diagnostic configuration IDs remain distinct. This audit performs no native execution and captures no additional live definition fields. Proprietary instruction evidence stays local in `../c6-ghidra/evidence/linux-reporting-yield-query-closure-local`, outside private upload approval.

Original `Plot.Read` obtains its mutable property map through native plot virtual `+0x60`. `EditDynamicProperties` constructs the concrete host `Data::TypedVariantMap`; its constructor stores vtable `0x53b3680 + 16`. The original typed stream reader reaches `ArrayVariant.Unserialize`, whose typed-map flag branch directly constructs that same class for the nested improvement map. This establishes construction provenance rather than guessing a virtual target from serialized counts. The native map's const `FindVariant` and `GetVariant` use existing tree lookup and a static default; they do not insert, allocate or change the source tree. The const keyed conversion reads type/pointer fields.

All six serialized property-bearing plots contain key `d9a34c75` with an empty native improvement map. The actual `GetYield` property query first asks that map for `877b95f0`. Missing keys take the original branch past the deeper per-yield map conversion/read, adding no property yield. Other plots return the original static empty map. Construction, insertion and ownership setup during load are separate from these const queries. This contract covers the deserialized native property graph; arbitrary externally rebound property subclasses remain unsupported. Construction provenance is not a new dynamic attestation of every current live vptr or definition field.

The original improvement caller requires a nonmissing, unpillaged improvement and a matching declared base-yield row before calling `GetYieldFrom`. That wrapper uses the plot's political owner and returns zero for owner `-1`; it does not substitute the improvement builder's owner. For an owned plot, the matching-yield calculation includes base changes, definition-ordered adjacency changes and technology/civic bonuses. Thirty adjacency references in the present improvement definitions survive the caller's yield guard. None intersects the exported excluded-adjacency IDs, so the separate civilization/leader trait-exclusion path is unnecessary for this bounded profile.

Caller argument evidence excludes the mutation-sensitive optional paths:

- The actual contribution list is null, selecting a null tile-output vector and skipping contribution-list append and temporary GameEffects object creation.
- Hypothetical map changes are null. Their planning-vector scans are skipped because of that argument, not because of their namespace.
- The requested yield is a specific nonnegative registry index. The `yield == -1` normalization path is skipped. The existing native registry export contains six ordered yields; this audit does not recapture the monitor's NUM_YIELD_TYPES global.

In this supported adjacency/bonus path, explicit writes target stack temporaries or the excluded optional outputs. Native visibility lookup selects existing player/group/layer storage and reads a signed 16-bit revealed-resource value; it performs no lazy layer creation. Technology/civic checks read both original global availability and player masks. District attributes bind to original CityAttributes methods, which resolve existing district IDs through the original player container and read completion/pillage/type fields. Adjacent-plot lookup uses original geometry and native Map access. No source mutation, RNG draw or reporting/signal dispatch is introduced by these focused query paths. Exact values and operation order remain required; this is not permission to replace their numerical results with zero.

The supplied Map has 1,709 unowned plots. Its only three unowned improved plots are barbarian camps, whose exported `YieldFromAppeal` is null. The original builder maps SQL NULL to hash zero, and `NameToYieldType` resolves that to `-1`, which cannot match a requested nonnegative yield. The only appeal-yield improvement definition is the beach resort; all ten matching plots are owned, with six unpillaged candidates before other guards. Their appeal access reads the existing signed 16-bit cached value. The other direct appeal site requires an `Adjacent_AppealYieldChange` reference; the exact exported table has zero rows, and the original collection builder inserts only actual query rows. Thus neither direct site requires unowned appeal recomputation under this definition input gate. Other rules profiles can reach the general appeal/ring/governor calculation and require its separate contract.

A typed implementation needs the original definition order/references, improvement/pillage/ownership and property data, adjacent plot fields/geometry, district identities/status, revealed-resource layers, and both player/global technology/civic availability. It must preserve native integer wrapping, fixed-point conversions and matching/iteration order. Differing property classes, relevant rules inputs, or optional argument domains must be rejected before mutation until supported. Monitor-owned IndexList comparison/update and reporting remain separate caller effects; already proven presentation-only consumers do not require reproducing their presentation output. This evidence does not classify every reporting consumer or establish purity of unrelated GetYield rule groups.
