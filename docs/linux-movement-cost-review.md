# Independent Linux movement-cost review

The nine-phase scalar evaluator in [movement.rs](../crates/c6-core/src/movement.rs) matches the inspected supplied Linux XP2 bodies within its explicit resolved-query-fact domain. No arithmetic discrepancy was found. This is source/static review acceptance, not native differential movement acceptance. The reviewed source and audit identities are in [review metadata](../evidence/linux/movement-cost-review.json); the implementation boundary and future oracle ABI are documented in [the movement contract](linux-movement-cost.md).

The review independently inspected the original Values constructor/layout, phase dispatcher, nine rule bodies, final/exit getters, ZOC prelude, route conversion and formation ignore aggregation. Reproduction of the exact-module audit passes 37 method fingerprints, nine ordered phase targets, constructor tail delegation, the native float scale and Plot virtual bindings. The isolated Rust arithmetic suite passes six tests. No original game code was executed, and no live world/rules queries, movement legality, unit mutation or turn were admitted.

## Concrete conclusions

Both shore bodies use source completion for the second district test: Embarking loads source `Values+8` at `0x2bedafa`, and Disembarking does the same at `0x2bedcc0`. If that source is complete and a destination district exists, the destination definition's FreeEmbark result replaces the accumulated source flag (`0x2bedb28` / `0x2bedcee`). It is not logical OR, and destination completion is not queried there. The evaluator preserves this behavior. It also preserves the distinct water/domain checks: embarking requires qualifying destination water and raw source nonwater; disembarking requires qualifying source water and raw destination nonwater. Each applicable phase adds remaining-minus-base to the separate exit accumulator only when signed Q8 base is less than remaining. The shore tests do not imply any extra movement legality rule.

Route selection preserves the exact ordered comparison: destination is selected only if its float is ordered and greater than source; ties and unordered comparisons select source. The selected value goes through the original float constructor, which delegates to assignment. Conversion is floorf, whole CVTTSS2SI then wrapping left shift eight, binary32 fractional subtraction/multiplication by 256, fractional CVTTSS2SI, low-byte extraction, and bitwise OR. It is not generally replaceable by a single mathematical floor of value times 256 or Rust's saturating cast. In particular negative minimum subnormal `0x80000001` produces raw `-256` in the supported rounding environment; the added regression preserves this rounding boundary. Invalid conversion uses x86 integer-indefinite `i32::MIN`, whose shifted whole/low fractional assembly is modeled explicitly.

Integer conversion, addition and subtraction wrap in 32 bits. Signed minimum/maximum clamps are applied as `max(min(regular, soft_maximum), hard_minimum)`, then any nonpositive result becomes raw 256. The initial soft maximum is raw 2147483392. No remaining-moves cap is invented. City, terrain, feature, improvement, route, river, portal, embark and disembark run in that order. The ZOC prelude precedes those phases, with bit 11 bypassing the slowed test and selecting exit moves; an actual slowed case chooses positive remaining moves or otherwise maximum moves. The resolved IsSlowedByZOC result remains an external dependency.

Formation ignore aggregation skips missing member IDs. An empty resolved set returns true; any nonignoring member clears the aggregate, but a later ignoring member with escort mobility returns true immediately. These rules match the inspected terrain, feature, shore and river aggregation bodies. Each independent predicate must come from its corresponding original-equivalent resolver; no individual unit result substitutes for an entire formation.

## Numerical and invocation scope

The reviewed float result contract is for Linux x86-64 binary32 under round-to-nearest with masked floating exceptions and DAZ/FTZ disabled. It does not model MXCSR status flags, errno, NaN payload propagation, traps or arbitrary floating environments. Those assumptions must be observed/gated in a future native scalar corpus; source tests alone do not establish them. No cross-platform numerical acceptance follows.

The native Values object is 64 bytes, including four trailing padding bytes. Its formation and plot references are borrowed. The Rust fact API represents nonnull plots and resolved native query results; native null-input branches are not a substitute for missing resolver support. Definition lookup absence and no route/district retain their explicit distinctions. World, definitions, modifiers, spatial adjacency, river predicates, domain validity, portal lookup and formation capability must be supplied exactly before this scalar result can support gameplay.

A future native adapter must use the original ABI, notably hidden-output FixedPoint returns: GetFinalCost takes output storage in RDI and const Values in RSI. ApplyMovementRules takes Values in RDI and gets the actual Rules receiver internally. Individual rule methods take receiver RDI and Values RSI. The original constructor's Q8 arguments are pointers, including stack-passed remaining/exit arguments; they must not be called as integer-return or by-value C functions. Preserve caller-owned output lifetimes and Values padding separately. This review does not authorize a native run or accept an unimplemented runner contract.

The added review requests were closed: the audit now pins float/int constructor delegation as well as conversion bodies, and the numerical environment plus negative-subnormal boundary are explicit. A native boundary corpus and comparison of all affected state/gameplay RNG remain outstanding. Full movement, live action and turn acceptance remain false; unknown save bytes and the separate 89,198-byte Save-to-Load failure remain unmasked and unclassified.
