# Independent Linux Map codec review

The review found **no unresolved defects** in the bounded current Map v4 / Plot v6 wire implementation. It checked the Rust readers, writers, public lookup helpers and budget propagation against the independently recovered [native contract](linux-map-state.md) and structural Python decoder. Complete live gameplay-state reconstruction, movement, actions and turns remain unimplemented; this result does not establish gameplay or RNG parity.

The implementation checkpoint is `768ec2f`. The reviewed frozen candidate is SHA-256 `871ba70feb80dbe8715abb58f6326a4d2908de645ee973842a5cadb7d2bf58bc`. Exact reviewed source identities, comparisons and rejection results are in [map-codec-review.json](../evidence/linux/map-codec-review.json). The author's separate reproducible [codec audit](../tools/linux/map_codec_audit.py) and [evidence](../evidence/linux/map-codec.json) retain the original module/configuration gates and fixture provenance. No original game code was executed for this review, and no implementation or private-project files were changed by the reviewer.

Of the reported ranges, 315 have original owner-trace validation in the underlying audit; the remaining range checks compare independently derived structure. Component-internal MemoryOStream ranges are not claimed as original trace observations.

The original before/reload Core streams contain the same Map bytes. They provide two lifecycle observations and one distinct native Map input. The generalized carrier is independently hand-authored from source-derived wire schemas: it exercises all 17 Plot flags, signed integer boundaries, masks, optional CityAttributes, nonempty Route portals, all six Terrain vectors, a Territory record and every current localized argument tag, including raw floating-point bits and a signed Linux 64-bit long. It is not an original-code fixture or a gameplay-valid world. Its complete value comparison therefore adds structural codec coverage, not native differential acceptance for those branches. A further source-only carrier adds a nonempty Ice record and also matches all values and ranges. The native input independently covers 166 Volcano Eruptions, six natural-wonder Eruptions and 55 River Flood records; its Ice vector is empty.

Static field review confirmed the native order and widths for Map headers, resources, visibility, Areas/Landmasses/Regions/Chokepoints/Continents, FeatureLayouts, Plots, occupancy and all six named components. The codec retains the saved owned-plot aggregate zero alongside 5,287 present CityAttributes, rather than recomputing it. It keeps generated object IDs distinct from recycled slot indices, preserves allocator metadata and native vector order, and does not impose an invented high-generation check. Political ownership remains the CityAttributes player plus owning-city identity used by the original CityID constructor; no owner is guessed from city-ID bits or improvement ownership.

Plot review checked each flag's native serialized position, the three-byte flag width, unsigned mask preservation, the outer property count and nested typed-variant contract, and the optional 17-byte CityAttributes tail. Spare bits, count mismatches and unsupported branches reject explicitly. General component review confirmed the one shared Route portal version, entrance/exit/source plot identities, geographical Territory IDs in Terrain records, all CoastalLowland fields, Territory boundary order, and recursive localized-name widths and bytes. Current-format and single-name restrictions are codec policy; they are not misrepresented as native reader validation or Load→Save normalization.

The shared reader/writer budgets remain active through component children, nested vectors, boxed component values, typed variants and recursive localized names. Independent checks exercised byte, item, logical allocation and depth limits on both decode and encode. For this native Map, ordinary decode requires a minimum logical allocation charge of 5,253,460 bytes; range collection increases it to 5,495,796 bytes. These are model-storage charges, not measured process heap usage. Encoded output and temporary component buffers use separate `max_bytes` bounds; vector spare capacity, allocator overhead and other process memory are not a heap ceiling. The author clarified this policy in the codec documentation and evidence.

The lookup helpers address canonical in-bounds coordinates and dense row-major indices. They preserve pointer identity and reject negative coordinates, each dimension boundary and invalid indices. They deliberately do not emulate original wrapping, hex movement or pathfinding. The original negative-multiple wrapping behavior remains documented in the native contract; no Euclidean-modulo substitution is claimed.

Native acceptance still needs nonempty Route/Terrain/Territory/localization and Ice fixtures, wrapped maps, and affected live-state comparison. The codec does not reconstruct omitted live/derived fields, resolve definition hashes through the active native registry, enforce every live-world consistency invariant, or execute native initialization/rebuild obligations. The complete raw Save→Load difference remains **89,198 bytes**, with no unknown bytes masked or reclassified by this review.
