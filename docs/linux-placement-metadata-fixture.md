# Original friendly-formation count fixture

The [first count-only capture controls](../evidence/linux/placement-metadata-native-capture-1.json) passed: 17,584 count rows, 1,262 binding rows, six identical full Core saves, unchanged observed RNG objects and clean teardown. Complete membership coverage and count parity await the independent offline checker. It adds no complete gameplay/action or
turn support. The accepted domain and movement captures remain immutable.

`--placement-metadata` is mutually exclusive with actions, Core commands, domain
metadata and movement-cost profiles. It requires the genuine loaded Core fixture,
original early main-thread preparation, cleanup, a fresh private trace directory,
a reviewed frozen Rust manifest and six distinct private artifact paths:

- `--placement-metadata-output`: genuine input facts, excluding count answers.
- `--placement-metadata-expected-output`: original count-only answers.
- `--placement-metadata-before`, `--placement-metadata-control-save`,
  `--placement-metadata-after`, `--placement-metadata-repeat`: four full Core saves.

Core alive is the actual native Core field, not an inferred saved-header value. A source-gated saved-header cross-check is separate.

Two outer full saves remain separate. `--prepare-only` builds and gates identity
without executing original code. The profile records its helper/audit sources,
preload, native target contracts, rules/configuration, Rust candidate and source
archive. `c6-linux-placement-count-candidate-v1` gates candidate bytes, the complete
source archive and declared Git source hashes before any original execution.
The candidate receives only strict typed input JSON; native expected counts are
not a candidate input. Both expected configuration/profile CLI arguments bind to
the independently verified full runtime configuration digest.

The loader retains its genuine Core module reference throughout the synchronous
profile. Its separate lifecycle entry calls original Initialize/InitializeCache,
opens an independent placement admission scope, verifies quiescence, runs the
exporter, verifies quiescence/identity again, clears admission before original
Uninitialize, then checks teardown and trace end. It never requests an operation,
pumps network messages or wakes a worker. Unknown/live state terminates the
isolated process before further observations, Save or native teardown.

`placement_metadata_fixture.c` preserves the accepted domain fixture's twelve
original immutable address checks and mutable idle/facade-lock call sequence under
an independent namespace/global scope. No controller/context state or facade is
cached. A work predicate immediately exits before facade release or post-reads.
Source projections check that adding the placement dispatch preserves all prior
loader and lifecycle profiles. New source/build/configuration identities are
required; historical profile acceptance does not admit this exporter.

The exporter captures complete native Unit/Formation traversal, original stored
slot presence and 65 player mapping/configuration facts, Unit definitions, full
WarTypes and plot-unit-limit inputs. The intended query matrix preserves current
and all six neighbor slots, including absent/invalid anchors and orphan Formations;
it must not silently sample or drop unsupported rows. Actual source-valid coverage
is established from the closed artifacts, not an assumed number of entities or
neighbors. The literal native Boolean argument is false; it is not given an
invented cargo interpretation. Native count answers remain in the separate
expected artifact. Original handler/CanStart answers are unavailable for this
profile, so Rust handler results cannot count as passing native comparisons.

Four internal full saves, both known complete 32-byte RNG objects, policy trace
and actual cleanup are controls. They do not establish complete state/RNG inventory
or getter purity. Raw Save→Load differences and unknown bytes remain unmasked.
Logical lookup slots do not establish an allocator/free-list implementation.
