## Authority and rejection checks

Corrupted rules-report bytes refuse both definition builders; corrupted owner-trace bytes refuse installation without creating relation authority. Repeat owner installation rejects without resetting values. The initialized relation object cannot be reinitialized. A Unit timer write increments the revision but preserves the installed relation owner and movement query result; old observed-snapshot admission after that write rejects. Changed-turn words remain intact, and the captured war sidecar is dropped after comparison.

The data builders check the exact destination binding and admitted resource/report identities. Their definition tables are private owned values exposed through immutable borrows. Installed relationship access is likewise immutable: this API currently exposes no gameplay relation setter or mutable relationship reference. Consequently, unrelated writes do not make the owner stale, and callers cannot silently mutate its rules or reload old relation values. Future diplomacy updates must operate on that owned authority; their semantics remain unimplemented. The low-level component install API still requires its caller to establish resource and owner attribution; the reviewed data adapter supplies those checks.
