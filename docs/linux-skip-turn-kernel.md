# Bounded Linux SkipTurn operation state phase

`c6_core::skip_turn::replace_operation` computes the original supported operation-manager state transition on complete typed Unit and Formation records and returns ordered archive/reporting effect requests. The actual native fixture's complete resulting Unit record (all 73 fields, 4,774 bytes) and Formation record (56 bytes) match exactly. This is a coherent operation state phase, **not an accepted gameplay action**. Full gameplay state, action execution and turns remain unimplemented; `Engine::apply` still rejects gameplay actions.

The phase covers USE_REQUEST replacement with the native public empty-map metadata: append=false, from_user=false, directive=-1, flags=0. It supports an empty queue or one MoveTo node, no automation, matching singleton Formation, and a legal nonbusy activation. It requires actual numeric SkipTurn registry identity, game turn/local player, IsBusy/CanMove/activation CanStart results and each affected wrapper's live archive attachment. These omitted live values cannot be reconstructed from wire bytes. Full CanStart, including placement/rules, script calls and disabled/interruption checks, remains outside this boundary. Unsupported supported-profile inputs reject before creating candidate state/effects; the borrowed inputs remain unchanged.

MoveTo has its own Deactivate override at `0x2da4b40`, calling Placement::CompleteMovement before BaseHandler::Deactivate. The phase explicitly requires the typed `m_bNeedsMovementCompletion` to be false when cancelling MoveTo. Original CompleteMovement (`0x2c42ab0`) then returns immediately. True rejects before mutation: that branch changes archive index 50 and sends an identity/coordinate report whose effects are not modeled here. The actual native fixture has false before and after. Old saved activity, destination, parameters, actor IDs, coordinates and notification IDs are never selection constants.

The implementation follows Clear → old MoveTo deactivation/deletion → insertion → activation/start → SkipTurn deactivation/deletion. Clear first sets OPERATION to the literal AWAKE value; it does **not** restore the old node's saved activity. Nonempty deactivation always tracks timer assignment to zero, even when its value is already zero. DeleteNode tracks the queue before deactivating/removing its front. Old deletion, Clear's tail and new deletion each clear Formation path/cache; every clear tracks indices 14 and 15 even after values are already empty/invalid. Initially empty Clear performs neither timer assignment nor path clearing. Formation evaluating-operation is unaffected by these direct phases and remains omitted live state outside the wire model.

Returned Unit dirty requests are in call order, with duplicates: `[11,32,72,32,72,11,11,72,32]` for the native fixture. Their unique membership, unioned with existing native dirtiness, matches the observed after set. This does not implement the native archive's pointer-keyed tree or claim its iteration order. Formation requests are `[14,15]` three times; native Formation dirty state was not observed. Exact registered field mappings follow [the archive contract](linux-unit-archive.md).

Reporting delivery remains a material boundary. Original Event::Send synchronously invokes registered cache dispatcher callbacks and the actual engine utility/translation provider. Actual callback registrations and enable flags are uncaptured. The coherent phase returns the nine ordered identity reports as **undelivered obligations**, under the explicit condition that delivery does not synchronously alter its core inputs. It cannot be promoted to live action support under an unknown reporting environment. The separately callable Start and SetActivityType leaves support synchronous hooks, with state reread after Start's reporting call; their bounded contract requires stable identity and the verified original manager implementation. Their Send return is int and is ignored by these original callers. Collecting reports alone does not fulfill subscribers.

The historical fixture observed nine selected identity calls through wrappers with an int/void ABI defect. Comparing those selected arguments/order is a diagnostic comparison, not corrected-observer event parity or proof of provider effects. The corrected observer needs separately identified native evidence. Diplomacy, all player decisions, notification/player upkeep, complete live affected state and complete gameplay RNG also remain required. The three notification removals/one activation and full notification footprint are not part of this phase; see [the complete serialized footprint](linux-skip-turn-state-success.md). Unknown bytes remain unclassified/unmasked, including the separate 89,198-byte raw Save→Load failure.

The adapter uses production Unit/Formation/message codecs, reads current turn/local player from original observations and uses the actual command's handler/identity/metadata. Positive control-flow inputs are inferred from the observed original branches reaching Start, with those limits recorded explicitly. No new native run, Ghidra write or raw evidence upload occurs.

Sixteen synthetic branch checks derive from original contracts but have **no corresponding native boundary fixtures**. They exercise unsupported metadata, identity, movement completion, queue count, automation and membership; empty Clear, zero movement, detached archive bindings, saved-activity independence and a synchronous subscriber changing activity. These are Rust checks, not native boundary parity. Release timing includes the actual typed clone/queue transition/effect allocation/drop; it excludes codecs, initialization, full legality, provider delivery, diplomacy, notification/player aftermath, turns and original-code performance. Candidate executable/source identities are regenerated for each audit build.
