# Linux AI.Governors current saved wire

The bounded `player_ai_governors` codec implements the complete current saved record for Linux XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. This is **AI.Governors v3**, distinct from gameplay `Player.Governors` v6. Complete Player/world state, gameplay RNG, actions and turns remain unsupported. No planning-only exclusion is established, and the recorded **89,198-byte raw Save→Load difference remains unmasked**.

The writer at `0x2115ba0` emits version 3, signed Player identity, one raw `done_off_turn` storage byte, a Governor definition-hash array, and a GovernorPromotion definition-hash array. Counts are unsigned little-endian u32. Each array row preserves its u32 definition hash, then its complete nested value; row order, duplicates and sentinels survive unchanged.

GovernorAnalysis writer `0x2115780` emits version 4, signed Player identity, Governor hash, a counted CityID vector and a separately counted signed raw Q8 vector. CityID writer `0x2c9ad10` emits **i16 owner, i16 component type, u32 ID**, without a version. These are identities rather than pointers or packed live memory. The two vectors need not have equal lengths for wire transport. GovernorPromotionAnalysis writer `0x21159c0` emits version 2, signed Player identity, promotion hash, counted Governor **hashes** and signed raw Q8 value. Hashes are not collection indices. Q8 values retain their exact i32 bit patterns without floating conversion.

The wrapped bool writer dispatches through the concrete FAutoVariable vtable save slot at relocation `0x3a1bbf0`, bound to `0x211acf0`; that body addresses wrapper `+0x10` storage and calls the bool stream operator. `WriteObject(bool)` at `0x1fe7900` sends exactly one source byte through the stream virtual write function. The API consequently uses `RawBool = u8` and does not silently normalize noncanonical storage. This is preservation of serializer storage, not a claim that arbitrary noncanonical C++ bool execution is defined. The small carrier tests exercise byte 255.

The reader at `0x2115c40` resolves non-null Player identities through Player.Manager, calls InitArchive and InitializeLists, version-gates `done_off_turn` from v3, reads Governor analyses, resets Promotion analyses and reads them from v2. Native Read therefore depends on actual player/definition mappings, initialized lists, archive services and callbacks. Nested readers resolve identities and definition hashes; their legacy branches are unsupported by this current-version codec. Encoding does not perform native lookup, remapping, reader initialization, policy choices or RNG execution.

`decode`, `decode_prefix`, `decode_prefix_with_items`, `encode` and `encode_with_items` share `unit::Limits`. Byte accounting covers the actual consumed record; item accounting aggregates every counted row at every nesting level. Decode checks minimum wire extents and fallible allocation; encode first checks the complete budget and fallibly reserves the exact output. Truncation, strict trailing bytes, unsupported root/nested versions and exhausted aggregate caps are explicit errors.

The read-only [audit](../tools/linux/player_ai_governors_audit.py) gates target methods, DWARF, vtable binding, original Core blobs and comparison-only owner traces. Actual Governors hooks and nested analysis hooks validate the schema; no hook-derived lengths enter the Rust parser. It independently projects and repacks all 86 original records, then compares all typed fields with an exported, unchanged committed-source Rust candidate. The candidate checks exact and one-short aggregate byte/item caps, prefix tails, strict trailing refusal and bounded structural/interior cuts on actual records. Source tests exhaust all truncations of a small carrier and reject hostile counts and versions. This is existing original Save-output validation, not a new original Read or gameplay oracle.
