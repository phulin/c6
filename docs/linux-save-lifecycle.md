# Original Linux save-load lifecycle

The original Linux host has an encompassing staged loader: `LoadGameViewState::LaunchNextStage(unsigned)` at `0x2fd2180`. Calling Context::Load directly executes a lower serialization boundary and omits this orchestration. The contracts below are verified against pinned original Linux ELF bytes, not copied from historical platform layouts. They do not establish that a complete game has loaded.

Run the reproducible, read-only audit:

```sh
python3 tools/linux/save_lifecycle_audit.py --output target/linux/save-lifecycle-contracts.json
```

The tool checks the exact original host and XP2 SHA-256 gates, 22 native direct calls, the 12-entry original stage jump table, original immediate arguments, and relocated target Context virtual slots. [save-lifecycle-contracts.json](../evidence/linux/save-lifecycle-contracts.json) records this static checkpoint. Raw disassembly is private under `../c6-ghidra/evidence/linux-save-lifecycle`.

The native loader stores its current stage at its own object offset `0x440`. The argument to LaunchNextStage is not the stage selector. These are original observed fields, not permission to fabricate a view-state object or write its stage manually. Original constructor, Begin, synchronous/asynchronous progression, Tick and End own the object and its surrounding UI, art, event, tuner and application dependencies.

| Original stage | Observed operation |
|---|---|
| 0 | Initialize error results and advance to 1. |
| 1 | Request type 2 selects stage 4; other requests select stage 2. |
| 4 | `Serializer::Manager::LoadCurrentRequest`, then stage 5 when result is OK or PENDING. |
| 5 | Wait for request completion; on success `ApplyModdingState(nullptr)` uses the retained original stream, then stage 2. |
| 2 | Pre-content automation, configuration ownership checks, ConfigureContent and UpdateContent; successful path selects stage 3. |
| 3 | Apply original gameplay options; select stage 6 without a retained stream or stage 9 with one. |
| 9 | Original Context StartupGame, serializer Unserialize, controller cache and postinitialization work; successful path advances to 10. |
| 10 | Apply pending user settings, choose active user from the original local-player cache, reload tuner states, then advance toward 11. |
| 11 | Remaining game-view/UI startup and completion flow. Full execution is still required to validate its prerequisites and completion. |

Stages 6–8 belong to the alternate new-game path. The supplied target has different stage numbering from the upstream reference's documented loader, so upstream stage IDs cannot be reused.

Stage 9 calls the Context virtual at offset `0x40` before unserialization. The target's actual ELF relocation identifies it as original `Exports::Context::StartupGame` at `0x2c7d2f0`. It sets the controller's initializing flag and disables event-stream cache updates before loading. After an OK result it calls SetContext and InitializeCache, original automation PostGameInitialization, and Context virtual `0x160`, proven by target relocation to `PostInitialize` at `0x2c7d0c0`, with argument true. It later updates cache components, restores visual state, reenables cache updates and publishes the native GameCore initialized event before stage 10. Those hooks are not interchangeable with merely returning from Load.

Stage 10 contains the only direct original host call to User::Instance::ApplyPending found by scanning executable instructions. Its argument is **true**, verified at caller `0x2fd2e7f`. Unless WorldBuilder editor mode is active, the original sequence then calls Cache::GetLocalPlayer and passes that result to User::SetActive. It does not select player zero because a save contains player-zero user settings. Cache::GetLocalPlayer returns `-1` when the original game cache is absent; otherwise it delegates to that cache's original virtual provider. Pending settings must therefore remain pending until the original postload lifecycle reaches this boundary with a valid cache.

UpdateContent takes the original libc++ `std::function<void(Database::IDatabaseConnection1*,bool)>` by value through its C++ ABI; its Linux call-site argument points to the native function object. The loader constructs a genuine callback capturing its owning LoadGameViewState. Its invocation ultimately calls original `App::Censorship::ApplyContentCensoring(Database*,bool,bool)`, with the second bool read from that native owner. UpdateContent checks the function object's presence before calling it; an absent callback is supported by that function's bytes. This does not prove that omitting the loader's supplied censorship callback preserves the benchmark configuration. An invented libc++ representation or a replacement callback is not a verified fixture.

`LoadCurrentRequest` opens the source using the serializer's real request filename/location. Its callback retains the original stream and SaveType, signals stream retention to OpenFromSource, and preserves ownership until ClearLastStream invokes the original deleting destructor. ApplyModdingState reads LoadHeader then calls stream SetOffset(0); the native host MemoryIStream vtable resolves that seek slot to its actual original method. `Unserialize(default,nullptr)` subsequently uses the retained original stream and type. It expects the **complete save container**, since UnserializeGameState starts with LoadHeader and then AttachToSession, LoadGameCoreState through a genuine ZLibIStream, LoadAudioState, LoadUIState and LoadRecorderState. The extracted GameCore payload used by the lower Context::Load probe is not a substitute for this input. RequestLoad's optional IStream and SaveLocation contracts must be established before substituting an explicitly supplied native stream for normal source opening.

Matching target DWARF defines serializer Result as a four-byte signed enum: OK=0, PENDING=1, FAILED_TO_READ=5, UNEXPECTED_END_OF_FILE=9 and ERROR_RESTORING_STATE=10. The optional native `c6_linux_save_lifecycle_check` checks only the missing-retained-stream boundary: `Unserialize(0,nullptr)` returns FAILED_TO_READ, leaves the request result and retained pointer unchanged, and reports the original local-player query. It never applies pending settings or changes player selection. [save-lifecycle-native-boundary.json](../evidence/linux/save-lifecycle-native-boundary.json) records native result 5, unchanged request state, absent retained stream, original local player -1 and complete fixture teardown with exit zero. Its successful execution is a negative serializer fixture, not a complete load.

A faithful integration lets the genuine AppModdingFramework own its bootstrap and replacement contexts, then uses the original loader's lifecycle. Manual startup of an independent Context cannot be combined with framework bootstrap without establishing ownership. Lower original XP2 Core Load/Save now has independent native execution evidence; that boundary does not establish the host's saved-request profile, finalization, valid local-player cache, legal actions or turns. The [saved-configuration comparison](linux-saved-configuration.md) retains its observed normalization differences separately.

## Original request and retained complete stream

The [request contract audit](../evidence/linux/save-lifecycle-request-contracts.json) checks twenty-five original host calls, fourteen byte contracts and the native benchmark-directory dispatch:

```sh
python3 tools/linux/save_lifecycle_request_audit.py \
  --output target/linux/save-lifecycle-request-contracts.json
```

`RequestLoad(const wchar_t*, const SaveLocation::Instance&, IStream*)` returns a bool and forwards request kind 2. The native SaveLocation constructor owns its string member; the observed object size is 40 bytes. Native Linux Lua enum registration identifies SINGLE_PLAYER save type 1. Device value 4 selects the supplied-stream path; LOCAL_STORAGE is 1. These are distinct original source behaviors, not interchangeable ways to name the same request.

The LOCAL_STORAGE reader strips the request filename to its basename, obtains the original save directory, adds the native extension, and opens the concatenated path with original FileISynchStream. Passing an absolute filename does not select an arbitrary input path. Native Directory 2 chooses the App asset root plus `Base/Assets/Benchmark/Saves`; the exported four-argument SaveLocation constructor accepts SaveType, Device, Directory and Options. Directory 0 with an empty custom directory falls back to the App user directory and its save category. A local-source fixture must satisfy the actual native path and casing rather than treating the source-4 stream route as equivalent.

For Device 4, Request requires the supplied IStream and calls original `FillLastStream`. That method creates its own 40-byte GameCore::MemoryIStream, initializes a destination MemoryBuffer with the serializer's allocator and the input's complete size, seeks input to zero, reads all bytes into the destination, and seeks the retained stream to zero. The pinned complete benchmark is 7,348,717 bytes, SHA-256 `a328d643201cb11ba226eee46c782f85b0df36b2a7a4e1a32372da8abe9cddb8`. Neither the 103,901-byte configuration prefix nor the decompressed core payload is this complete-container input. Original `ClearLastStream` invokes the retained object's virtual deleting destructor; the caller must not also delete that retained object.

Request normally calls original CheckRequest immediately, except when App's actual current state equals its game-view state. The diagnostic `request_load.[ch]` requires both genuine getters to return NULL and no existing request/stream, so the constructor fixture takes the deferred branch without invoking shutdown or event dispatch. It checks genuine request kind 2, progress false, complete retained-byte equality and independent backing, releases the supplied stream, and leaves the original retained stream owned by the serializer. Its clear API calls original Reset and ClearLastStream before owner teardown. This fixture does not call Begin or claim a saved-game censorship profile.

The [native request control](../evidence/linux/save-lifecycle-request-native.json) now passes: original RequestLoad accepts the complete benchmark, retains a distinct complete byte-equal copy at offset zero, and keeps it valid after the supplied stream and bytes are released. Native kind is 2, in-progress is false, and GetRequestInProgress returns zero. Original Reset and ClearLastStream return kind zero and absent stream, followed by complete original framework/service cleanup with process exit zero. This is a genuine deferred-request and ownership result, not an executed Begin or full host save load.

Device 4 skips LeaveGame there and later skips AttachToSession; a real session prerequisite must still be established before Core Load. The original Begin method sets its saved-game censorship bool from `GetRequestInProgress()==2`. Its genuine exported `IsLoadingFromSave` getter observes this same bool. Begin must run after original request dispatch has marked the request active and before LoadCurrentRequest's callback resets request kind and progress. Calling Begin after LoadCurrentRequest would select a different profile. `ValidateLoadedStream` is an original unconditional true return and provides no container-validation evidence.

## Native single-player session prerequisite

The original encompassing `Civ6App::SetupNetwork` at `0x2f91d60` constructs the original Network::Manager when absent, initializes it, subscribes its real event handlers, and applies the actual App command-line configuration. Native manager initialization creates FireWireMgr and FAutoArchiveFactory; FireWire's constructor obtains the original message factory and FGameSyncManager, creating each only when absent; the fixture may preserve a genuine message factory already established by original CRT initialization. These are genuine providers, not logging or service stubs. Initialization unconditionally creates the FireWire/archive objects, so an independently owned archive fixture must not already exist. Original manager destruction unsubscribes events and frees the game-sync manager, archive factory and FireWire manager. The network owner must outlive Context usage of those providers.

For this target, the manager's friend capability queries return original constant true values, and its SteamFriends constructor initializes the native base/vptr without requesting a Steam provider. SetupFromCommandLine skips its argument loop for argc below two. These observations establish specific startup boundaries; they do not authorize arbitrary command-line, Steam or multiplayer behavior.

`Serializer::Manager::AttachToSession` at `0x324cac0` obtains the actual host context. It bypasses session hosting for WorldBuilder mode or original request source type 4. Otherwise it calls original `Network::Manager::HostGame(ServerType(0), false)`. **AttachToSession ignores HostGame's return and returns OK itself.** A successful attach return therefore needs independent native session and peer observations.

ServerType zero selects transport zero through the original table at `0x461ec30`. HostGame skips InitLobby for this type, invokes the original InitSession, constructs real Network::NetSessionCallbacks, and obtains a native FNetSession from FireWire. Transport zero bypasses the age-validation lookup. Its FNetAccessENet path does not create the transport-one ENet thread. This specific native path requires no fabricated lobby or Steam/EOS session object. FNetSession::Host creates the local peer through the original FNetPlayerManager and callbacks.

For the non-network, non-cloud configuration branch, NetSessionCallbacks::GetNewPlayerID scans the actual player configurations from ID 0 through 21. It tests slot status 3, proven by matching Linux DWARF as SS_TAKEN, and invokes the native eligibility callback before accepting an ID. This is not evidence that a local player must be zero. The original host EngineUtility virtual slot `0xd0` resolves to GetNetworkLocalPlayerID, which delegates to the actual Network::Manager session's player manager. The target Game::Instance::InitializeLocalPlayer reads this callback on its non-hotseat branch and validates the resulting native player ID. Missing session returns -1 at the host getter. Crucially, original XP2 Game serialization (`Serialization::operator>>(IStream&, Game::Instance&)` at `0x2d7aaa0`) calls InitializeLocalPlayer at `0x2d7afbf`, inside Core Load. The genuine session peer must therefore exist before Core Load; later PostInitialize and host-cache rebuilding cannot substitute for this precondition.

`LoadGameCoreState` takes an original IStream reference positioned at the compressed game-state section of the **complete** save. It constructs genuine ZLibIStream with argument true, calls actual target Context virtual `0x170` (relocation to Exports::Context::Load at `0x2c7d240`), then destroys the original decompressor and releases its context wrapper. It returns the original Load result. The pinned configuration parser's 103,901 boundary is a fixture-specific lead for that position; the normal encompassing loader reaches it by reading LoadHeader. Replacing the real input with an extracted or incomplete stream requires separate boundary validation.

The guarded `c6_linux_save_lifecycle_attach_session` adapter calls original AttachToSession without constructing request state or choosing IDs. It requires genuine initialized Network/FireWire/archive providers, a host-owned active Context, the native SINGLEPLAYER mode, no existing session, non-WorldBuilder mode and a request source that does not trigger the bypass. It then asks the separately owned original-network observer to validate the real session and peer. Unsupported preconditions return before the attachment call.

## Original shutdown order

The same session audit checks fourteen exact shutdown call sites. Original GameViewState::ShutdownGame calls Network::LeaveGame at `0x2fbbf23`, then performs its remaining game-view shutdown work, controller Uninitialize at `0x2fbc0bf`, and GameCore::ShutdownGame at `0x2fbc0c4`, followed by clearing event queues. Controller Uninitialize synchronizes and, when its original initialized flag is set, releases its dispatch lock as needed, uninitializes the App cache, releases its context and unsubscribes messages. GameCore::ShutdownGame independently calls the active Context's virtual `0x48`, proven by target relocation as Exports::Context::ShutdownGame. This shuts down game state without unpublishing the module context.

Later Civ6App::GUIShutdown calls AppModdingFramework::DestroyInstance at `0x2f98190` **before** GameCoreController::Shutdown at `0x2f98195`, then destroys the Lua script system. Framework destruction clears the last completed serializer request, clears the original Game configuration root, shuts down configuration, and calls UnloadGameCore. That unload releases the active controller's context before unloading the module. Finally Civ6App::FinalShutdown calls original Network::Shutdown and Network::Manager::FreeInstance; the latter releases the archive and transport providers. Thus real session, controller, game-state and module lifetimes are distinct. The headless fixture now explicitly invokes original UnloadGameCore while the host configuration manager is alive, then preserves normal framework/controller/service destruction. [Configuration lifetime evidence](linux-saved-configuration.md) proves the previous first-free error and validates both saved-only and no-save cleanup controls; retaining save input or skipping teardown is not the fix.
