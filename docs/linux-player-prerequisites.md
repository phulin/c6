# Linux prerequisite owner inputs

`player_prerequisites` connects structurally located original acquired bool arrays and complete live global nodes to the existing owned `world::Player` / `World` prerequisite provider. This is source-backed typed projection, not a complete Player.Techs, Player.Culture or Core importer, initialized native differential acceptance, or gameplay state/action/turn equivalence.

The [audit](../tools/linux/player_prerequisites_audit.py) verifies 19 complete method fingerprints, seven call sites and five critical instructions against XP2 SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. Its [report](../evidence/linux/player-prerequisites.json) includes the remaining capture requirements. Raw original disassembly remains private under `../c6-ghidra/evidence/linux-player-prerequisites`. No original game execution was added.

The acquired technology vector is the raw `Types::Vector<bool>` at Player.Techs `+0x140` (its FAutoVariable begins at `+0x130`). `HasTech` at `0x2b8ac60` reads this vector, and the first bool hash-array in the owner writer `0x2b89f90` / reader `0x2b8a090` supplies it. The next bool array is boost state and cannot substitute for acquired state. The acquired civic vector is Player.Culture `+0x360` (FAutoVariable at `+0x350`), read by `HasCivic` at `0x2a73e70` and the first civic bool hash-array in writer `0x2a6e330` / reader `0x2a6e880`.

Both owner readers call their concrete Reset before applying arrays. Techs Reset `0x2b8a280` clears the acquired vector and resizes it using an explicit false byte; Culture Reset `0x2a6f5e0` does the same. The size comes from `Game.Techs.GetNumTechs` (`0x2a2d150`) or `Game.Culture.GetNumCivics` (`0x29783c0`), which obtains the actual definition collection count. Thus `acquired_after_owner_read` uses proven false initialization for these two owner paths. Generic `IndexedBools::apply` preserves supplied prior values and requires complete destination storage; it never invents an owner reset for an unrelated array. No partial construction or uninitialized native memory is modeled.

`IndexedBools` decodes a little-endian u32 pair count followed by u32 definition hash and one-byte bool pairs. Native bool ReadObject (`0x1fe81a0`) requests one byte without canonicalization; this Rust typed codec explicitly supports canonical 0/1 bytes and rejects other encodings. `ReadIndexHashArray<bool>` (`0x218fd60` / `0x2a7ead0`) consumes unknown hashes, preserves unspecified destination slots, and applies later duplicates last. HashToIndex (`0x2016480` / `0x2017150`) calls actual native Find and returns the selected definition's collection index. `DefinitionLookup` retains that existing native-order Find contract, including the direct-index domain and collision selection. SQL row IDs, sorted rows or caller-selected counts do not supply it. Prefix decoding is for an already structurally located field, never a signature search through opaque saves.

For globals, `GlobalNodes::from_complete_live` requires every original ordered node after original Read/Validate. It accepts each node's actual signed32 GetType and IsActive, not research eligibility or completed-player flags. Game.Techs and Game.Culture keep raw node vectors at `+0xc0`. IsActive reads the bool at node `+4` (`0x2a2e460` / `0x297a950`). GetTechNode (`0x2a2d180`) and GetCivicNode (`0x2978330`) first accept a node at the requested position only when its type matches, then fall back to the first matching type in original order. Duplicate types can therefore select the positional entry even when an earlier match exists. Projection preserves this behavior. A known complete empty vector yields false availability; uncaptured nodes cannot produce a `GlobalNodes` value. Raw serialized nodes cannot be supplied here because original Read remaps and Validate removes invalid types. There is no claimed global wire codec.

`AcquiredState::install` moves the captured/remapped acquired vector into the chosen existing Player field. `GlobalNodes::install` constructs the complete availability vector before changing World. The native Manager player-validity mapping remains a separate required input, so importing a player does not make a native-invalid player valid. Inputs must share the pinned module, rules database, enabled DLC/mods and configuration identity. This module deliberately does not manufacture that identity or derive it from hashes of a synthetic fixture.

A real capture must still supply either structurally located acquired arrays through the preceding unframed Player components or complete live acquired vectors, complete post-Validate global nodes, and actual ordered technology/civic registries under the same identity. Existing complete Core records do not yet have all intervening Player schemas decoded; there is no safe field-offset search in the stream. No fresh original owner records or native oracle are claimed by these tests. These production projections make that exact capture surface usable without substituting a hint or guessed all-false mask.

Five synthetic tests cover ordered remapping/unknown hashes/duplicate overwrites, proven owner reset versus prior overlay, technology/civic installation into the World provider, all truncated wire prefixes and strict/prefix exhaustion, canonical bool refusal, resource/malformed-registry errors, global fast-path precedence and fallback/known absence.
