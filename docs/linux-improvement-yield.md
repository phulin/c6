# Linux XP2 improvement yield arithmetic

`c6_core::improvement_yield` implements the numerical composition in original Linux `Improvement::Yields::GetPlayerYieldFrom(improvement)` at `0x2a3ee50`, and its political-owner wrapper `GetYieldFrom` at `0x2a3ed90`, for a null contribution-list argument. This is a bounded component over supplied typed definitions and world queries. It does not implement complete plot yields, gameplay state, action execution, or turns. Initialized native differential acceptance remains outstanding; no native code was executed for this change.

The target remains `libGameCore_XP2.so` SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. The importer/caller must gate this binary, actual rules, enabled content, and configuration identity. This arithmetic interface does not assert those identities itself.

The source bodies are preserved outside the public repository in `../c6-ghidra/evidence/linux-reporting-yield-effects-local/additional-081.asm` (wrapper), `extra-008.asm` (composition), and `additional-085.asm` (fixed-point `AsInt`). The existing [query closure](linux-reporting-yield-query-closure.md) and its executable audit establish the caller's null contribution and hypothetical-map-change domains. The existing [effects audit](../tools/linux/reporting_yield_effects_audit.py) gates the original composition body and its exact module identity. This change does not claim a new native oracle.

For a specific requested yield, the native base loop takes the first matching row and exits; duplicate base rows are not summed. It then visits every adjacency reference in definition order, including duplicates, passing null hypothetical-map changes and null tile output. Each adjacency result is an integer converted to signed 32-bit FixedPointT<8> storage. Technology and civic helpers then add all their eligible rows in their original order. Every conversion shifts left eight bits with wrapping, and every fixed-point addition wraps at 32 bits. The final `AsInt` at `0x1fccdb0` uses a signed right shift by eight; negative fractions round toward negative infinity. No wider intermediate or host floating point participates.

At `0x2a3f097` the null contribution pointer skips `GetPlayerBonusYieldFromModifiers` entirely. This is an original caller branch, not a zero approximation of modifier behavior. Nonnull contributions, their append effects, and that modifier helper remain outside this component's interface. For requested yield `-1`, all base rows instead pass through `NormalizeYields(value, yield, null player)`; a typed provider must implement that separate policy, or the operation returns an explicit normalization error. The specific-yield monitor caller never requires it.

The wrapper returns zero for improvement `-1`, a null plot, or political owner `-1`; it uses `CityAttributes.GetPlayer`, not builder ownership. The direct player helper has no global invalid-player early return: its base and adjacency work still occurs, while the existing technology/civic helpers apply their own player-validity checks.

`OrderedImprovementYieldDefinitions::new` validates the numerical and existing bonus property arrays against one native `DefinitionLookup`. Small keys remain direct indices, hashes use the original duplicate resolution supplied by the registry. References use actual bounded native definition indices; they must never be constructed from SQL row IDs. Unknown reference slices are explicit errors, distinct from known empty collections. The base and adjacency slices represent resolved nonnull references: malformed/null rows that native dereferences are outside this import contract. `ImprovementAdjacency` is an unresolved typed dependency, not a cache of recorded fixture answers: implementations must compute the original adjacency overload from captured definition/world state or return missing-input errors.

Focused tests exercise duplicate base and adjacency references, first/all iteration semantics, both prerequisite bonuses, native hash versus index lookup, missing inputs, wrapper guards and political ownership, invalid-player callee handling, overflow, negative fractional conversion, and explicit normalization delegation. Run `cargo test -p c6-core improvement_yield`. These tests validate the translation against instruction-derived expectations; they do not replace initialized native differential fixtures. Adjacency computation, normalization policy, complete affected-state comparison and full host admission remain separate gaps. The independent 89,198-byte Save→Load failure remains unclassified and unmasked.
