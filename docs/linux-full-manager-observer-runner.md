# Hardware adapter for one genuine full Manager invocation

The new [adapter](../tools/linux/full_manager_observer_runner.py) connects the reviewed [passive Lua observer](linux-script-manager-live.md) to the [separate full Manager caller](linux-full-manager-fixture.md). It implements actual GDB installation, outer-drain scheduling, mapped-code/source/profile gates, native frame attribution and lock provenance. Explicit `raw_unresolved` mode supports the first authorized passive observation without predicting internal HKS frames; `source_closed_registry` mode separately enables the reviewed HKS decoder. It does not launch a process, create a native profile or execute originals during preparation. Full Manager parity, callback effects and complete gameplay state/actions/RNG/turns remain unaccepted.

The [source audit](../evidence/linux/full-manager-observer-runner-source.json) rechecks original host/Core bodies, compiles all offsets of the actual 88-byte C observation descriptor, and exercises descriptor/frame/plan refusals and the real installer/drain using fake GDB hardware lanes. No synthetic test loads original game code. The caller's independent review remains separate from this adapter's review and the future concrete loader/guard/profile admission.

## Sole-runner contract

The sole runner calls `install(runtime_plan_path, fresh_private_directory)` inside its separately launched GDB driver, then runs `c6-full-manager-drain`. The driver owns exact process/session identity, timeout, terminal native cleanup interpretation and failure disposal. Reuse the existing Military supervisor's exact-PID/start-time/session disposal discipline; never leave a failed or timed-out inferior executing. This adapter leaves a failed inferior stopped for that owner and makes no native teardown, detach or kill call. `exit.json` explicitly records `observer_failed` and does not claim original cleanup.

The driver configures pending breakpoints and all-stop mode before installation. It must disclose its `starti` and GDB loader-rendezvous instrumentation separately. This adapter's marker and original target breakpoints are exclusively `BP_HARDWARE_BREAKPOINT`; it performs no inferior function call, Lua lookup, lock operation, GC step, PC skip, FinishBreakpoint, software game patch or native policy call. Stop callbacks queue only registers/thread identity. All memory/frame analysis and breakpoint deletion/creation run after the stop callback unwinds, in the outer drain. The drain is one-shot: every second invocation is refused before any continue, including after a failure, and never rewrites terminal artifacts.

The pending own marker is installed before `FACADE_ACQUIRED` phase 1. At the first real marker the adapter gates exact mapped Civ6/Core/preload/dependency file identities, profile and source closure, compiled marker/caller code and mandatory original bodies. The source caller reaches this marker after its genuine facade acquisition, before actor/registry/Operation/predicate calls. The separately reviewed runner must also gate the original acquisition/profile before launch; a phase-1 check does not retroactively admit earlier calls.

## Immutable plan and complete native frame evidence

The profile key is `lower_core_full_manager_observer` with `static_plan` and `static_plan_sha256`. The runtime plan adds `runtime_gate`, containing the prepared report path/hash, exact configuration hash, all frozen source files and `static_plan_path`. The adapter rechecks the actual static file hash and its JSON against the configuration; it never derives expected results from native answers. The report must be schema `c6-linux-native-profile-prepared-v1`, with `native_execution_performed=false` and an explicitly null returncode. Its complete normalized `configuration.sources` plus runner hash must equal `runtime_gate.source_files`. Actual preload bytes, configuration preload hash, mapped module declaration and prepared execution path must agree.

The static schema is `c6-linux-full-manager-observer-plan-v1`, with profile kind `genuine_lower_core_full_Manager` and an explicit `observation_mode` of `raw_unresolved` or `source_closed_registry`. It requires canonical `host`, `core` and `preload` paths, a `modules` hash map including executable frame dependencies, complete `live_bodies`, compiled marker RVA, and these reviewed contracts:

- `caller_suffix_frames`: the exact normalized compiled caller return through the actual owned `mod_probe_main`, following the original Manager frame. Raw mode matches this complete own prefix and preserves additional startup/root frames as unresolved; it does not require predicted libc unwinding. Source-closed registry mode retains its complete reviewed chain. Each entry has `module` and integer `relative_pc`.
- `window_parent_prefixes`: in `source_closed_registry` mode, accepted exact original parent chains through Manager continuation for every natural Lua checkpoint. In `raw_unresolved` mode this map may be empty; actual unknown internal frames remain evidence, without a zero-GC inference or registry decoding.
- `marker_parent_frames`: exact owned marker/caller/main-entry frame prefixes (complete reviewed chains in source-closed registry mode) for phases 1 through 9, with alternatives only when individually source-closed.
- `compiled_symbols`: exact actual preload ELF symbol names/types/addresses/extents for the marker, fixture entry, `invoke`, `run_bound`, `notify`, profile probe, `mod_probe_main` and `observed_mod_main_tid`. Every complete function body must be file-backed executable bytes with a matching live-body fingerprint. The actual eight-byte writable object must equal the declared witness; a marker-only plan is refused.
- `main_entry_witness`: the reviewed preload module and RVA of its own recorded OS main TID field. The future loader will record `observed_mod_main_tid` at original main entry under `C6_FULL_MANAGER_FIXTURE`. The adapter copies that field and matches actual inferior PID/LWP without calling its getter or converting a native lock token.
- `stack_contract_review`: path/hash of a source review packet with schema `c6-linux-full-manager-stack-contract-v1`, the same frame/marker/body/compiled-symbol/witness contracts and complete reviewed source map. Its `no_VM_or_GC_parent_frames_source_closed` assertion is required only for `source_closed_registry`, backed by exact source/call-chain contracts and matching actual unwinds. Raw mode makes no such assertion.

The future compiled preload's exact marker/return/main-witness and safe caller ownership identities remain required. No actual native plan has been admitted here. Complete original protected-call prefix prediction is a decoder-attribution design condition, not an automatic-review or authorization restriction; it is unnecessary for raw mode's bounded copying. Missing internal HKS classifications remain explicitly unresolved and do not suppress otherwise legitimate original execution.

Mapped module files must match source hashes, device/inode and stable file metadata. Executable body and frame reads use separate current mapping gates: exact retained path/device/inode, readable executable permissions without write, pinned ELF executable PT_LOAD extent and exact backing-file offset. Generic heap snapshot reads remain separate. File versions/hashes and current mapping identities are rechecked at body-gate endpoints, including phase 9; matching readable bytes or a matching path alone is insufficient. All observed executable frames belong to those pinned mappings. Unwinds are bounded to 128 frames. Marker, selected Manager entry/return and compiled caller/main ownership checks retain their exact contracts through the actual compiled `mod_probe_main`; a truncated or unknown frame inside that required own prefix still refuses. Additional startup/root frames are retained rather than predicted in raw mode. Raw mode preserves partial or unknown internal HKS parent frames, while known-module mapping provenance failures remain fatal. At raw dispatch the pinned Manager/wrapper prologues also prove `wrapper_rsp = selected_Manager_entry_rsp - 152`; subsequent CCall return/context/RSP checks retain attribution even when optional internal unwinding is incomplete. The adapter intrinsically checks the original script backend, HKS decoder layout methods, lifecycle/critical-section implementations **and Platform Enter/Leave trampolines**, complete negative-index function helper, concrete host slots and named strings. Additional compiled preload/marker/caller bodies are mandatory plan inputs. These checks repeat at phase 9.

The marker must be the actual compiled return-only function, with its source-gated optional CET ENDBR64 prefix. All 88 raw descriptor bytes, including unknown padding, remain recorded privately. Unit/Manager addresses are provenance, not general post-callback liveness proof; the adapter never dereferences the returned actor or Manager merely because the marker retains an address.

## Natural call attribution and hardware lanes

Phase 4 arms the complete original Manager entry. Its actual six argument registers must equal the live descriptor's Manager, Unit, Operation, NULL Plot, exact visibility flag and NULL result map. The actual stack return must equal the reviewed compiled caller return. It then arms Manager return and the source-closed script dispatch. Early busy/turn/disabled rejection can return without Lua: the adapter preserves that actual boolean and reports zero natural Lua calls, with no callback-absence claim.

When dispatch is reached, exact Manager continuation `XP2+0x2da22a0` and full caller suffix establish the original path. CCall entry additionally requires concrete direct parents `0x36b40e1` and `XP2+0x2ce79ff`, while the reviewed producer independently checks actual stack and context identities. The adapter records the pre-acquisition Lua lock. `source_closed_registry` mode requires no retained parent ownership and a nonnull initialized mutex pointer, then recursion one, a nonzero ASL ThreadHANDLE owner pointer and unchanged mutex identity after original Enter. Raw mode instead retains nonbaseline lock fields and original normal Enter/Leave return observations as unresolved transitions, without inventing zero parent ownership or successful baseline acquisition. These facts combine actual normal acquisition flow, complete source-closed parent frames and raw lock fields. No GC control byte or owner/count sample substitutes for that provenance.

In `source_closed_registry` mode, the producer captures before lookup, actual naturally resolved function/groups when reached, protected result and completion before release, and original release/return facts. In `raw_unresolved` mode, a separate narrow native context trace never constructs SourceObserver: it records registers/actual frames, 64 raw known Lua-lock bytes, the actual 26-byte CCall context and an optional bounded 128-byte header from the retained actual CCall RDI pointer. That header is named `actual_CCall_state_header_raw`, with no initialized/main-VM/GC-safe claim. It performs no collector, table, string, closure, upvalue, interner or registry traversal and supplies no active-Lua/GC-zero values. Generic CCall hits with unresolved selected-frame attribution are retained as unattributed; nesting is not inferred and they do not become the selected result. All threads must be stopped for every copied extent. Reads are bounded to the u64 address space, mapped readable extents and the producer's existing image budget. Main VM/global/collector bytes, raw named absence and actual uncached metamethod-returned functions retain their separate meanings. Lua owner pointers remain distinct from core u32 thread IDs and OS TIDs.

There is one persistent marker lane and at most two original target lanes. During the protected interval only the producer's next sites are armed; Manager return is temporarily unarmed when needed for the resolved/protected-return fork. It is restored after original wrapper return. A skipped/unwound Lua checkpoint therefore fails at the next marker or terminal check, never becoming an assumed callback outcome. After actual Manager return, phase 5 must agree with that observed AL result. Phase 9 requires completed Manager and original facade lifetime.

After a fresh writable private root exists, installation and runtime refusals write private failure/exit rows before any new target continuation; invalid/unwritable/non-fresh output-root failures must be retained by the sole driver transcript. Overall fixture completion is checked before the producer emits a successful terminal record; producer failures preserve immutable partial images and terminal pending-call state. Successful terminal output records actual natural-call count, whether registry images were captured, and explicit absence of callback-effects/native-parity acceptance. A missing window is unavailable evidence. Save production and binary-identical rewriting remain decoding diagnostics, not action gates; complete affected gameplay/VM state, all RNG, order and logical identity still require comparison. The historical 89,198-byte raw Save→Load difference remains unclassified and unmasked.
