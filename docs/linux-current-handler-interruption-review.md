# Independent current-handler interruption review

Corrected checkpoint `1dae236` passes review for the two original-code constant leaves, evidence-aware snapshot resolver and explicit rejection of source-image predictions. **Runtime handler dispatch is not admitted.** The [review evidence](../evidence/linux/current-handler-interruption-review.json) separates captured registry facts from predicted original-image targets. The [review driver](../evidence/linux/current-handler-interruption-review.py) builds the actual committed production-export archive without injected exports, verifies unchanged sources, checks target methods and existing captures, and tests all 63 predictions as inadmissible live bindings. No original code was executed and no captures were changed.

An important evidence error was corrected during review. Initial `3bd25f6` described handler target families as concrete observed bindings. The metadata captures contain actual handler pointers, IDs, hashes and **vptrs**, but no reads of the runtime vtable `+0x20` contents. The audit computed those targets using original ELF relocations. That predicts the original image; it does not exclude runtime symbol interposition, table rewriting or changed code bytes. The producer's successor explicitly supersedes the earlier report and relabels those targets and census results as source predictions. The source API now distinguishes `OriginalImagePrediction` from `LiveSlotObservation` and always rejects the former, even for a known original RVA. This correction does not invalidate previously accepted raw registry identity facts.

Independent complete-method inspection agrees with native lookup ordering. HashID::IsIndex tests the raw 32 bits unsigned against `0x800`. Smaller values select a numeric vector slot before any hash lookup. Numeric access has no native bounds check, so a missing extent cannot become a null-handler success. Other values use the actual reverse map. A native `-1` miss returns null; a resolved ID delegates back to GetHandler. The library conservatively admits only bounded index-form reverse answers and rejects unobserved/invalid inputs. Unknown targets never become base handlers. Handler IDs, operation hashes and definition positions remain separate even where this fixture records equal numeric IDs/collection positions.

Original BaseHandler at `0x2d95660` is a complete three-byte true leaf; MakeTradeRoute at `0x2da0920` is a complete three-byte false leaf. These exact original bodies perform no object reads, writes, calls, allocation or RNG. The existing Manager orchestration retains empty/null-front, captured requested/current same-ID bypass, and actually-null-current-handler semantics. The new module neither repeats those decisions nor installs a full ManagerQueries provider. A saved queue hash translation is not a live queue observation. In particular, same-ID bypass can permit interruption without consulting a false leaf.

The closed metadata has 63 nonnull handler slots, no observed null slot and no actual operation hash below `0x800`. IDs/hashes/vptrs agree with the independently accepted earlier registry report. Original-image `+0x20` relocation lookup predicts 62 true-family targets and one MakeTradeRoute false-family target. **These are not observed runtime slot values or native interruption results.** The two earlier saved queue corpora each attribute 185 fronts to the predicted trade family, 123 to the predicted base family and 954 to empty queues. Their contexts are not merged into a same-context live Manager/front profile. None of these rows supplies the missing target observation required to construct an admitted current registry.

The API requires exact module identity, valid digest syntax, complete ordered observed slots, matching slot IDs, supported live-target provenance and unique explicitly observed reverse-map answers. An observed null slot, an observed native hash miss, an omitted hash answer and an invalid numeric extent remain distinct. Snapshot lifetime is borrowed and registry mutations require rebuilding observations. Public provenance tags and digest strings cannot authenticate native memory; callers still owe genuine retained owners, the live slot pointer, owning module and validated live leaf code bytes from the same admitted context. Tests using synthetic `LiveSlotObservation` values do not establish those facts.

The two corrected source test groups passed from an unchanged archived Cargo build. The producer audit and two Python rejection tests passed independently. Eight additional boundary groups distinguish unsigned `0x7ff`/`0x800`, high-bit negative hash bits, observed miss versus unobserved hash, mapped/actual null versus invalid numeric extent, saved-hash translation versus small-index handler selection, non-index reverse answers, malformed identities and slot-ID mismatch. A separate check feeds each of the 63 original-image predictions to the corrected API and requires `UnobservedLiveBinding`; none is promoted to live evidence. The driver checks eight complete target methods and four original-image Manager bindings. Those static Manager bindings also remain unobserved in live memory.

The first genuine production export is `ee021ff`; review builds corrected successor `1dae236`, which contains that committed export. Cargo runs offline with its committed lockfile, and every archived source file is checked unchanged after building. The separate Manager script-lock correction `7d3c026` retains interruption ordering and is reviewed by its assigned owner; this review does not admit its script effects or any complete Manager provider.

Before native-binding acceptance, a separately admitted passive capture must retain actual Manager/handler ownership, live delegated Manager slots, actual handler `+0x20` pointer/module/live-code bytes, and native queue size/front bits alongside saved identity evidence under one configuration and synchronous context. The producer has a protocol for that missing packet; specifying it does not authorize execution. No native predicate fixture or full affected-state/RNG comparison exists for this module. Complete gameplay state, actions, RNG, turns and external decisions remain unsupported; the **89,198-byte raw Save→Load failure** remains unclassified and unmasked. Attribution remains in [reference.md](reference.md).
