# Original Linux action and turn execution boundary

The user requires external policies for **all player decisions**. Native AI planning internals are outside the simulator scope; gameplay state, gameplay RNG and passive rules progression remain exact requirements. A class being in an AI namespace does not exclude its gameplay effects, such as diplomacy, deals or NPC state. The native oracle must stop/yield at actual decision boundaries and record externally supplied decisions rather than silently run original AI policy.

The Rust library still covers isolated primitives. No Rust/native gameplay action, complete legal-action enumeration, full affected-state comparison or end turn has passed differential validation. Original controller/cache readiness and live actor discovery pass in a genuine loaded fixture. The current native request converts and broadcasts successfully but has not reached the core message queue; the applied-action boundary remains unresolved.

## Receiver, ABI and ownership

These are ELF virtual addresses before module rebasing. Use the genuine framework-owned active `IContext1`, after original session attachment, Core Load, PostInitialize, cache initialization and active-user selection described in [save lifecycle](linux-save-lifecycle.md). Original rules/DLC/mod order, save container, game configuration and all dependencies must be identified. Context allocation, successful Initialize or a nonnull global do not establish these preconditions.

Linux x86-64 SysV supplies the receiver in RDI, subsequent integer/pointer arguments in RSI, RDX, RCX, R8 and R9. References below are pointers to actual native objects. Four-byte enum values use their low 32 bits; bool uses its actual native ABI. DWARF establishes return types; do not read a result from a void request.

| Original boundary | Address | Signature after receiver / return |
|---|---|---|
| Context RequestAction | `0x2c7d490`, virtual `+0x1f8` | `(ActionTypes, PlayerTypes) -> void` |
| Context RequestAction with parameters | `0x2c7d4f0`, `+0x200` | `(ActionTypes, PlayerTypes, TypedVariantVectorMap const&) -> void` |
| Context RequestUnitOperation | `0x2c7e2c0`, `+0x208` | `(ComponentID const&, TypeHash, TypedVariantMap const&) -> void` |
| Context ProcessMessages | `0x2c7d330`, `+0x238` | `() -> void` |
| Context HasPendingMessages | `0x2c7d340`, `+0x240` | `() -> bool` |
| Context Save | `0x2c7d230`, `+0x168` | `(Serialization::OStream&) -> Serializer::Result` |
| Game Update | `0x2c862e0`, `+0x30` | `() -> void` |
| Game NeedsUpdate | `0x2c86a60`, `+0x50` | `() const -> bool` |

The two-argument RequestAction constructs and destroys a genuine empty TypedVariantVectorMap itself. It avoids a fabricated container representation for a parameterless end-turn request. Unit requests require a real native TypedVariantMap and an identity obtained from the loaded original unit; do not manufacture units or infer their IDs. The original unit request constructs a Request and UnitOperation on its stack, broadcasts, then destroys both. The external caller must not retain pointers to those temporaries. The original registered operations manager owns numeric handler resolution; action hashes are not wire handler IDs.

Context GetGame/GetUnitOperations return native interface wrappers with their own reference lifetime. Preserve the original wrapper ownership convention: the host releases acquired wrappers through `ICvUnknown::operator delete`, which dispatches their native Destroy, rather than freeing their bytes or destroying the underlying game. Keep the framework Context, host services, network/session, registries and stream provider alive through use and release. This contract does not authorize deleting the framework's Context.

## End-turn request and real effects

Matching Linux DWARF identifies `ACTION_ENDTURN = 751412917 = 0x2cc9a6b5`. Its parameterized branch at `0x2c7db90` looks up parameter hash `0x34bfb075`; when absent it uses `TurnRequest::RequestSubTypes::NONE = -1225125244 = 0xb6fa1284`. At `0x2c7dca4` it constructs the genuine PlayerTurnComplete, then broadcasts at `0x2c7dcac`. WorldBuilder has an early rejection. This request returns void, so return alone is not legal-action acceptance or completion.

PlayerTurnComplete::Execute at `0x2d27b50` resolves the real player, checks human/paused and already-complete state, and on its advancing branch calls `Player::Processor::SetTurnComplete(player, true, subtype)` at `0x2d27e82`. It immediately calls `Game::Instance::Update` at `0x2d27e8f`; if the player remains active it tail-calls Update again at `0x2d27ebc`. Calling SetTurnComplete, BeginTurn or EndTurn directly omits the enclosing checks and messages. GameTurnComplete is a distinct barrier message; its existence is not interchangeable with PlayerTurnComplete.

`Game::Instance::Update` at `0x2661ba0` calls Game::Processor::Update, Diplomacy::Manager::ProcessPending and cache profiling. The processor invokes Player::Processor::Update at `0x2a0ccf5`, whose inactive-player branch invokes original `AI::Control::Manager::DoTurn` at `0x2b5c7b5`. Its active-player branch calls Player::TurnManager::DoTurn; this returns immediately for a genuine human and otherwise enters the AI control manager. The processor also waits for original GlobalAi jobs at `0x2a0d290`. Therefore a single end-turn message drain can run native AI. A future external-player loop needs genuine player-control/automation configuration and an observed decision boundary for every player, plus mandatory passive world rules. Native policy choices must yield to the external policy. This evidence supplies no no-AI mode. Do not patch these calls, substitute AI stubs, or report native AI decisions as Rust/external-player behavior.

Crucially, Context::Update(bool) at `0x2c7e490` only calls Autoplay::Manager::Update when its argument is false and returns zero. Repeatedly calling that export does not reproduce the Game Update boundary.

## Queue, host pump and completion

The genuine host GameCoreThread::Run at `0x31d11d0` enters its original critical section, obtains the original game/context wrappers, checks update suspension, invokes Context virtual `+0x238` at `0x31d1213`, marks the pass complete and leaves the critical section. GameCoreController::ExecuteGameCoreUpdate at `0x31d4950` resumes that worker in threaded mode. Its inline mode instead obtains the controller lock and invokes Game virtual `+0x30` at `0x31d4a0e`, then releases the lock. These two modes must not be silently treated as the same drain operation.

The host's RequestGameCoreUpdate(bool) at `0x31d4a90` checks initialized controller, actual network-session host and pending-request state. It constructs native parameters with key `0xc4af951d`, obtains the genuine local player, and requests ACTION_GAME_UPDATE `0xb186b9fb` through Context `+0x200`. A headless fixture must establish this host handshake and original Network delivery rather than adding fabricated message entries.

Original Messages::Manager::ProcessMessages at `0x2d248a0` repeatedly reads the queue front, constructs a real MemoryIStream over that entry, calls ReceiveMessage, pops the front and emits reporting event hash `0x9ea4c222`, until the queue is empty. It can process messages added during this pass. HasPendingMessages also consults the record queue during playback; exclude playback or preserve that original lifecycle. Queue-empty only establishes this queue's drain, not turn advance, AI completion, pending diplomacy completion or external-player readiness. Synchronize the actual host worker before observing state; do not race the worker with Save.

A future fixture should record original current turn/phase, all player activation/completion/control states, NeedsUpdate, NeedsTurnAdvance, IsAiProcessing, IsTurnProcessing, pending messages and pending diplomacy before and after the host-owned pass. Any pump/timeout policy must preserve a failing case and report unfinished work, not force completion flags. The exact full host frame/event/network completion policy remains to be executed and validated.

End-turn UI blocking and force/subtype semantics need their own genuine fixture.

Capture the entire original core stream before and after an action, its hash, status and stream error state, plus separately identified complete save/configuration inputs and full gameplay RNG objects. Preserve output bytes privately. Raw core bytes are a broad state observation, not proof every affected live state is serialized: message queues, caches, reporting/event subscribers, asynchronous jobs, host/session state and pending diplomacy need their own observations. Core Save is also not the complete Civ VI save container.

A genuine lower-Core-loaded native session is now available; complete host Begin/finalization and reproducible Save/Load branch restore remain unresolved. The bounded experimental adapter below has not yet produced a mutating native case. The first concrete acceptance case should use a real fixture unit and native CanStart/Request for SkipTurn, or a legal original end-turn scenario; capture complete core output and all transient boundaries, reload the same original fixture, repeat, and compare both effects and RNG before implementing Rust parity. ## Genuine human decision boundary: bounded static evidence

Player::Instance::IsHuman (`0x2b31530`) resolves the player's real configuration; Configuration::Player::Instance::IsHuman (`0x28ec230`) returns whether original slot status is 3 (SS_TAKEN). Original SetAsHuman (`0x28ebd80`) delegates to SetSlotStatus(3); this is configuration API evidence, not authorization to rewrite loaded slots. Player::TurnManager::DoTurn (`0x2ba16c0`) checks this predicate and returns for humans before AI DoTurn; nonhumans enter the original AI manager. That is a real active-policy separation worth testing with a natively configured human/hotseat fixture. It does not suppress off-turn processing: inactive Player::Processor::Update calls AI manager DoTurn, whose inactive branch dispatches the original OffTurnProcessingStatus signal at `0x201ed3c` and waits for original jobs. Even an all-human major-player fixture does not prove absence of native AI policy for minors/barbarians, automation, off-turn subscribers or diplomacy.

The current evidence therefore supports an eventual external action loop at verified human readiness, with original control, phase and legal predicates observed and host passes synchronized. It does not supply a universal yield-before-AI API. Native all-human/hotseat setup, player switching/session eligibility, automation control, off-turn signal effects and branch-restorable Save state remain runtime prerequisites. Their exact semantics must be validated rather than inferred from these short predicates.
