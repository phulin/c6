# Original Linux turn progression and external decisions

This static contract establishes the original completion request, top-level phase/call ordering and a bounded next implementation. It does not implement or validate a complete turn. Complete gameplay state/action/turn support remains absent. The supplied XP2 target is SHA-256 `a0b6611f45ed28fa7bf6e18d608cafddbdd5b1c20cfd880cb50937af731c1faa`. [The reproducible audit](../tools/linux/turn_progression_audit.py) checks full method fingerprints, direct calls through their original ELF-defined GOT targets, branch bytes, virtual bindings and matching DWARF; [the report](../evidence/linux/turn-progression.json) records the checked identities. No original code was executed.

This work first reused [Linux actions](linux-actions.md), [the activation/research policy boundary](linux-policy-boundary.md) and [the gameplay-only oracle scope](linux-gameplay-oracle-scope.md). Discovery also consulted cru121's *Civ6-GameCore-reference*, pinned revision `5af389445118bed2bdebf7a8a42b219c8fba5175`, CC BY 4.0, especially its completion-message build-difference warning and turn-method index. See [attribution and limitations](reference.md). All addresses below are supplied Linux ELF RVAs, independently checked; upstream Windows RVAs and build labels are not evidence of equality.

## Request normalization and dispatch

Original `Exports::Context::RequestAction` (`0x2c7d4f0`) rejects WorldBuilder first. Player `-1` resolves through original Context local-player; an explicit player is retained. The `ACTION_ENDTURN=0x2cc9a6b5` branch looks up parameter key `0x34bfb075`. Absence supplies **NONE `0xb6fa1284`**. Presence calls original `GetNumberOrHash` (`0x2d57dc0`): a nonempty string goes through MakeHash, an empty string produces zero, and a non-string uses original unsigned conversion. Thus absent and present-empty are different. No subtype whitelist is applied here. Exact conversion of arbitrary typed variants must use its own contract; the next proposed slice accepts the genuine absent-parameter/default-NONE case.

It constructs original `PlayerTurnComplete(player, subtype)` and broadcasts it. Matching DWARF gives native size 32, player i32 at `+24`, reason/subtype at `+28`; the constructor sets message key `0xd7c02786`. Its body writer serializes player then subtype through four-byte signed enum-to-stream operations. `GetUnreadiesTurn` is false: this completion does not run the request-side TurnUnready composite. Public request returns void and proves neither acceptance nor an ended turn. Preserve original queued deserialization, execution, queue pop and post-message reporting. The trusted authoritative gameplay provider must still validate source/actor entitlement; this Execute body does not establish network sender authorization. Full desktop/UI admission is not a prerequisite for that separately identified gameplay boundary.

`PlayerTurnComplete::Execute` (`0x2d27b50`) has these ordered branches:

| Condition, in native order | Original effects in this body |
|---|---|
| Unsigned encoded player >63, including negative IDs | Return before player resolution or gameplay calls |
| Resolved player is human **and** game is paused | Logging, then synchronous reporting `0xa7b85261(player)`; no completion setter or Game.Update |
| Otherwise player already globally turn-complete | Logging only; no ignored-report event, setter or Game.Update |
| Otherwise | `SetTurnComplete(player,true,subtype)`; Game.Update; if that same player is still active, a second Game.Update via tail call |

There is no active-player, alive-player or notification-blocker rejection before the accepted branch in this body. Do not add a guessed CanEndTurn gate and label it original dispatch semantics. Invalid in-range player availability, higher-level admission and gameplay-provider preconditions remain separate. Logging-only branches have service effects; the paused-human rejection also has reporting subscribers, so rejection cannot generically be called state-pure.

`SetTurnComplete` (`0x2b5b840`, actual return type **bool**) first writes the global per-player completion array. False returns true without completion hooks. True iterates integer slots 0 through 63; for every valid slot, if the **same requested player** is alive, it calls that player's `TurnManager::DoSetTurnComplete(subtype)`. It does not replace the receiver with the enumerated player. Preserve that repeated-call behavior and order, including possible callback multiplicity, rather than simplifying the loop.

The turn-manager hook (`0x2ba17b0`) reaches the same player's Cities hook (`0x2a5b640`). Only **UserForced `0x720b6468`** or **TurnTimerExpired `0x4601eac9`**, for a human, calls RemoveUnassignedProductionOverflow. That iterates actual recycled city-container order, resolves each city's build queue, and calls ClearOverflow only when Front is null. ClearOverflow assigns fixed-point zero at build-queue `+0x1f4`. Default NONE skips this city mutation. Forced/timer completion therefore needs production state; it is not merely a reason label.

`GameTurnComplete::Execute` (`0x2d232b0`) is distinct. If actual NeedsTurnAdvance is true, it returns. Otherwise it range-checks player, sets that player's **game**-turn-complete flag, calls Game.Update and repeats once if the player remains active. Player EndTurn broadcasts this message after per-player end upkeep. Its protocol/arrival meaning is not established by conflating it with PlayerTurnComplete or invoking it as an unconditional next-turn setter.

## Ordered game and player passes

`Game::Instance::Update` (`0x2661ba0`) invokes Game::Processor::Update, then Diplomacy::Manager::ProcessPending, then Cache::Dispatcher::DoProfile via tail call. Processor Update (`0x2a0cb70`) is an internal loop, not one player tick:

1. Autoplay.Update; clear global NeedsUpdate. If `NewGame || (TurnComplete && AdvanceTurn)`, Game.BeginTurn runs. A new-turn branch with a live human in the selected process vector can leave the processor before its ordinary player passes; the enclosing Instance.Update tail still applies.
2. Build the actual players-to-process vector and call Player.Processor.Update in its original order.
3. Build the actual players-to-deactivate vector in `ms_aiTurnOrder` order and call DoTurnDeactivate for each.
4. If no player remains active, call ActivateNextPlayer, which may advance phase and activate a player. If activation leaves no active player/phase continuation and live major players exist, inspect unprocessed automation and run Game.EndTurn on the native branch. Do not substitute an unconditional turn-number increment.
5. Wait for original GlobalAi jobs. In the single-player continuation, inspect active players' pending statements, actions, open sessions and deals, plus relevant human pending statements. These checks can keep the call within its internal repeat. The original finite retry bound is a progress guard, not proof of decision readiness. Finally run Autoplay.Update again.

GetPlayersToProcess (`0x2a0c0c0`) is stateful. It first scans original alive-vector order for the first active nonhuman and, when found, returns that single ID. Otherwise it calls SetAIProcessed and relevant engine turn-request notification, then traverses the alive vector: include active humans and, subject to `game.m_autoPlayerGame`, at most one inactive player with actual HasOutOfTurnProcessing. It also calls SetInitialAIProcessed per visited alive player. A sort by player ID, or treating this as a pure query, changes semantics.

GetPlayersToDeactivate (`0x2a0c2b0`) scans the 64-entry native turn order. A valid active player with player-complete or game-complete is eligible and clears `game.m_autoPlayerGame`. Otherwise humans remain active; nonhumans require actual AI IsDoneTurn, pending-diplomacy validation/gates and original GetUnitCounts work. Multiplayer changes the pending-diplomacy gate. Keep these side effects and original ordering; “AI done” is not an external policy's implicit consent to end a turn.

For an active player, Player.Update (`0x2b5c720`) calls DoTurnActivate, DoTurn and UpdateEndTurnBlockingState in that order. DoTurnActivate consumes first/activation-event flags before invoking the turn manager and reports activation afterward. DoTurn increments phase/turn update counters with native wrapping u32 arithmetic, and AI-update count for a nonhuman. On the first phase update the blocker is temporarily set to `-1` before the blocking-state update. An inactive player's Update directly invokes original AI Control DoTurn. DoTurnDeactivate (`0x2b5ad20`) first sets inactive, then calls DoAutomation; automation may reactivate the player. It branches on the actual result: reactivation suppresses a future activation event and reports its own subtype; otherwise original TurnManager.DoTurnDeactivate runs, followed by deactivation reporting. It is not just a bool flip.

## New turn, phases and required upkeep

Game.BeginTurn (`0x2a0c460`) reports the impending turn, calls Player.BeginTurn, resets Phase.current to `-1`, and only then increments the archived current-turn value when AdvanceTurn was true. It next calls the actual game virtual `+0x30`, reports/sends begin-turn signals, computes simultaneous-turn behavior/activates the next player, and clears TurnComplete, AdvanceTurn and NewGame. Player.BeginTurn resets all 64 slots' completion/activation/automation/update arrays, active count and automation-player bookkeeping; valid alive players receive TurnManager.DoBeginTurn in numeric slot order. That hook enters AI Control BeginTurn, which has mixed callbacks/jobs and cannot be dropped wholesale.

Actual XP2 game virtual `+0x30` binds to `XP2::Game::Instance::DoBeginTurn` (`0x2d77fa0`). Its ordered calls are **Map**, climate, trade, great people, religion, quests, random events, fallout, diplomatic relations, eras, emergency, congress, economic, heroes. Several use concrete manager virtual `+0x28`; their loaded implementations and nested rules/decisions remain required. Actual XP2 Map virtual `+0x160` binds to Map.DoTurn (`0x2a480e0`), which invokes each registered map component's `+0x28` in container-index order, rechecking component count. This is an explicit world/upkeep dependency, not an excluded AI-planning category.

Phase definitions are filtered by actual configuration TurnPhaseType and sorted through original EASTL code. Preserve the resulting native definition order, disabled-segment set, current index, last-valid segment and time-limit state; this checkpoint does not certify all sort-tie behavior or export the fixture's phase definitions. ActivateNextTurnPhase (`0x2a54880`) can first run automation for a tactical phase. If players become active, it reports no phase change and returns. Otherwise it records the previous segment, ends the old phase, advances over disabled segments, and on a valid next definition updates current phase/time limit and calls Game.BeginPhase. Exhaustion returns false. BeginPhase resets player phase state, dispatches original signals and activates eligible simultaneous players in native turn order. ActivateNextPlayer (`0x2a0bf90`) has a network nonhuman-priority branch before phase selection; the general branch selects the first eligible sequential player in native turn order. Actual phase permission checks remain in each request/automation path.

On a first player activation, TurnManager.DoTurnActivate (`0x2ba0b60`) performs begin-activation signal and score calculation, then, for nonbarbarians: research, tax, deals, culture, religion, great-person points, influence, quests, diplomacy, player-cities activation, heroes, congress, espionage, climate resource reset, resources, units, governors, trade and statistics. Eras follows; then placement virtual `+0x78`, improvement captures, city turn activation in original container order and deferred cultural-identity transfers, nonbarbarian resource maintenance, plot/unit-manager and unit-operation callbacks, promotion notification/processed-turn reset, formation movement restoration and activation signals. Non-first activation skips that upkeep region but still dispatches activation continuation, updates influence map and calls AI Control DoTurnActivate. Conditional calls and virtuals require their own mechanics contracts; the names do not prove decision-free behavior.

Game.EndTurn (`0x2a0c750`) sets AdvanceTurn/TurnComplete true, calls Player.EndTurn then resets Phase.current to `-1`, followed by end-turn reporting/signals and Autoplay.EndTurn. Player.EndTurn visits valid alive numeric slots and calls each TurnManager.DoEndTurn; that invokes units, cities, culture in order. It then reports timing and broadcasts GameTurnComplete for original local player. Map/world beginning upkeep and per-player ending upkeep must not be interchanged.

## External boundary and one implementable next transition

The user requires **every player decision** to be external. The next genuine boundary is the earliest unresolved choice encountered along these continuations, including NPC/minor/barbarian decisions, diplomacy, automated units and off-turn subscribers. Human configuration only suppresses the narrow TurnManager.DoTurn AI path; it does not suppress activation/off-turn processing or already-queued operations. The proven technology selector in [the policy contract](linux-policy-boundary.md) chooses and mutates research during activation, including a fallback draw from gameplay RNG. Yield before that selection and preserve required bookkeeping/continuation under the external-policy profile. Do not consume native policy RNG draws speculatively or mask their consequences. Earlier nested choices may exist in upkeep/signals; a universal “next human turn” yield is not proven.

A concrete next kernel is **PlayerTurnComplete dispatch prefix for default NONE**, represented as a typed transition with an explicit internal `RequiresGameUpdate` continuation. Inputs are encoded/resolved player, original human/paused/global completion state and actual valid/alive player availability. It follows the rejection table above; the accepted slice changes that player's global turn-complete bool and records the exact required update continuation. Default NONE has no forced/timer production-overflow mutation. Keep the native repeated hook control flow represented even if this reason's leaf has no effects. The hook count alone is not a completed action. A public Engine.end_turn/apply must remain Unsupported before mutation until the continuation can reach the next supported external boundary with complete affected state/RNG. This internal kernel must never create a resumable native token by aborting an original running stack.

Next acceptance dependency: obtain genuine default-NONE message bytes/source identity, observe the full dispatcher prefix and all global arrays/reporting changes in a separate identified component fixture, then compare this typed transition under paused, duplicate-complete, invalid/out-of-range and eligible conditions. Forced/timer support additionally needs exact build-queue/overflow ownership and callbacks. A complete accepted turn needs actual phase/rules inputs, all mandatory player/city/unit/map upkeep, ordered messages/events/jobs/diplomacy and complete logical state/RNG, with all native choice commits replaced by evidenced external decisions. Do not build an advancing scheduler with no-op subsystem bodies. The historical 89,198-byte raw Save→Load failure remains unresolved and unmasked.
